# 结果记录模板知识库实施计划

## 1. 总体策略

结果记录模板知识库专项采用“先兼容、再增强”的方式推进：

1. 先把现有静态 JSON 模板导入 SQLite，保持现有接口和前端录入行为不变。
2. 再开放用户模板新增、编辑、删除 API。
3. 最后补充模板管理 UI、搜索、导入导出和完整回归。

专项命名为 `KB`，每个阶段完成后需要：

- 更新相关项目文档。
- 运行阶段相关测试。
- 检查工作区，避免提交缓存、运行产物或无关文件。
- 提交代码并推送到远程仓库 `https://github.com/ZN4819/FuLuA`。
- 涉及数据库、API、前端核心流程的重要阶段使用独立分支。

## 2. KB-1：数据库化系统模板知识库

### 2.1 目标

将 `templates/appendix_a/record_templates.json` 从“运行时唯一来源”升级为“系统模板种子”，由 SQLite 表 `record_templates` 作为运行时模板知识库。

### 2.2 任务

- 新增 `record_templates` 数据表。
- 新增必要索引。
- 在模板服务中同步系统模板种子。
- `GET /api/record-templates` 改为从 SQLite 读取。
- 保持响应字段兼容现有前端。
- 保持固定测评单元分组逻辑不变。
- 补充数据库种子导入测试。
- 更新 README、开发方案和实施计划。

### 2.3 验收标准

- 后端启动后可创建模板表。
- 首次读取模板时自动导入 117 条系统模板。
- 多次读取不会重复插入。
- `GET /api/record-templates?section_code=A-5` 仍能正确筛选。
- 现有结果记录模板测试通过。
- 前端不需要改动即可继续套用模板。

### 2.4 当前执行范围

本阶段先完成系统模板数据库化，不开放用户新增、编辑和删除接口。

### 2.5 完成记录（2026-06-18）

- 已新增 SQLite `record_templates` 数据表。
- 已新增按章节/测评单元、来源和启用状态筛选的索引。
- 已保留 `record_templates.json` 作为系统模板种子。
- 已新增系统模板 upsert 同步逻辑，使用 `template_key` 防止重复导入。
- 已将 `GET /api/record-templates` 的数据来源切换为 SQLite。
- 已扩展模板响应模型，预留 `source_type`、`tags`、`is_enabled`、`created_at` 和 `updated_at` 字段。
- 已扩展前端 `RecordTemplate` 类型，但不改变当前录入界面。
- 已补充系统模板导入和幂等测试。

## 3. KB-2：用户模板 CRUD API

### 3.1 目标

开放用户模板维护能力，让用户能够通过接口新增、编辑和删除模板。

### 3.2 任务

- 新增 Pydantic schema：
  - `RecordTemplateCreate`
  - `RecordTemplateUpdate`
  - `RecordTemplateDelete`
- 新增 API：
  - `POST /api/record-templates`
  - `PUT /api/record-templates/{template_key}`
  - `DELETE /api/record-templates/{template_key}`
  - `POST /api/record-templates/{template_key}/copy`
- 限制系统模板不能直接编辑或删除。
- 用户删除模板采用软删除。
- 新增服务层校验：
  - 章节必须为 A-1 至 A-8。
  - 表格类型必须为 technical 或 management。
  - 结果记录正文不能为空。
  - 标题为空时可由测评单元和测评对象自动生成。
- 补充 API 测试。

### 3.3 验收标准

- 可新增用户模板。
- 可编辑用户模板标题、测评单元、测评对象、正文和标签。
- 可软删除用户模板。
- 删除后的用户模板不再出现在读取接口中。
- 直接编辑或删除系统模板返回明确错误。
- 复制系统模板后生成新的用户模板。

### 3.4 完成记录（2026-06-18）

- 已新增 `RecordTemplateCreate`、`RecordTemplateUpdate` 和 `RecordTemplateDelete` schema。
- 已新增 `POST /api/record-templates` 用户模板创建接口。
- 已新增 `PUT /api/record-templates/{template_key}` 用户模板编辑接口。
- 已新增 `DELETE /api/record-templates/{template_key}` 用户模板软删除接口。
- 已新增 `POST /api/record-templates/{template_key}/copy` 模板复制接口。
- 已实现服务层校验：章节必须为 A-1 至 A-8，表格类型必须为 technical 或 management，正文不能为空，标题为空时自动由测评单元和测评对象生成。
- 已限制系统模板不能直接编辑或删除。
- 已扩展前端 API client，预留创建、更新、删除和复制模板函数。
- 已补充用户模板新增、编辑、软删除、系统模板保护、系统模板复制和非法输入测试。

## 4. KB-3：录入区模板筛选与分组优化

### 4.1 目标

让测评表录入区能更清楚地区分系统模板和用户模板，并支持更精确的套用。

### 4.2 任务

- 扩展前端 `RecordTemplate` 类型，接收 `source_type`、`tags`、`updated_at` 等字段。
- 模板下拉按来源分组：
  - 系统模板
  - 我的模板
- 下拉展示内容包含测评对象和标题。
- 当前测评单元下无模板时显示清晰空态。
- 套用模板后继续保留当前可手动编辑逻辑。
- 固定测评单元继续优先来自系统模板。

### 4.3 验收标准

- 当前测评单元下可看到系统模板和用户模板分组。
- 用户模板新增后刷新或重新进入章节仍能显示。
- 套用用户模板后结果记录文本正确填入。
- 图片引用占位 `[插入图片引用]` 的替换逻辑不受影响。

### 4.4 完成记录（2026-06-18）

- 已将测评表录入区的模板下拉改为按来源分组展示。
- 系统模板显示在“系统模板”分组，用户模板显示在“我的模板”分组。
- 模板选项文案调整为“测评对象 - 模板标题”，同一测评单元下更容易区分。
- 当前测评单元没有可用模板时，显示“本单元暂无模板”的禁用空态，图片引用下拉仍保持可用。
- 工具条模板统计改为分别展示系统模板数量和我的模板数量。
- 固定测评单元提取逻辑改为优先使用系统模板，并继续保留已有测评行中的单元，避免用户模板误扩展基准单元清单。
- 已通过前端构建和浏览器检查，确认项目页模板分组渲染正常且无页面级横向溢出。

## 5. KB-4：模板管理 UI

### 5.1 目标

为用户提供可视化模板管理入口，支持新增、编辑、删除和复制模板。

### 5.2 任务

- 新增模板管理入口，建议放在项目工作台顶部或测评表工具条。
- 新增模板管理面板：
  - 章节筛选。
  - 测评单元筛选。
  - 关键词搜索。
  - 模板列表。
  - 新增模板表单。
  - 编辑用户模板表单。
  - 删除用户模板确认。
  - 复制系统模板为用户模板。
- 支持“将当前测评行保存为模板”。
- 对系统模板展示只读状态。
- 对用户模板展示编辑、删除按钮。
- 补充空态、加载态和错误提示。

### 5.3 验收标准

- 用户能从界面新增一条模板。
- 用户能修改自己新增的模板。
- 用户能删除自己新增的模板。
- 用户能复制系统模板后再修改。
- 保存当前结果记录为模板后，能立即在当前测评单元下拉中使用。
- 系统模板不会被误删。

### 5.4 完成记录（2026-06-18）

- 已在项目工作台顶部操作区新增“模板管理”入口。
- 已新增结果记录模板管理面板，支持章节筛选、测评单元筛选和关键词搜索。
- 已提供用户模板新增表单，可录入章节、测评单元、测评对象、标题、标签和结果记录正文。
- 已支持编辑和删除用户模板，系统模板保持只读，仅提供复制为用户模板的入口。
- 已支持复制系统模板或用户模板为新的用户模板，并在复制后进入可编辑状态。
- 已在当前编辑章节中列出可保存的测评行，支持将结果记录正文保存为用户模板。
- 已在测评表行级控件中新增“存为模板”快捷按钮，保存后会刷新模板下拉数据。
- 已补充空态、成功提示和错误提示，管理面板在窄屏下切换为单列布局。

## 6. KB-5：搜索、导入导出与备份

### 6.1 目标

增强模板知识库的长期维护能力，便于不同项目复用。

### 6.2 任务

- 增加关键词搜索，优先基于普通 `LIKE` 查询，数据量增大后再启用 FTS5。
- 支持模板导出为 JSON。
- 支持用户模板从 JSON 导入。
- 导入时校验字段、章节和重复模板。
- 支持导入预览：新增多少、更新多少、跳过多少。
- 增加备份说明。

### 6.3 验收标准

- 可按关键词搜索标题、测评单元、测评对象和正文。
- 可导出所有用户模板。
- 可从导出的 JSON 恢复用户模板。
- 导入非法模板时返回明确错误。
- 导入不会覆盖系统模板。

## 8. 阶段风险

- KB-1 风险：数据库种子同步导致重复数据。
  - 控制：使用唯一 `template_key` 和 upsert。

- KB-2 风险：系统模板被用户误改。
  - 控制：服务层禁止直接编辑、删除 `source_type=system`。

- KB-3 风险：模板下拉过长。
  - 控制：按当前测评单元过滤，并分组展示。

- KB-4 风险：管理入口干扰主录入流程。
  - 控制：使用独立面板，不把管理表单塞进测评表单元格。

- KB-5 风险：导入模板质量不一致。
  - 控制：导入前做字段、章节、正文和重复检查。
