# UI 布局优化实施计划

## 1. 背景

当前工具已经完成项目创建、已有项目打开与删除、A-1 至 A-8 结构化录入、结果记录模板、证据图片管理、校验、预览和 DOCX 导出等核心能力。下一步需要把界面从“功能可用”提升到“长期录入可用”，让用户在处理大表格、长文本和大量证据图片时更容易定位、判断和操作。

本计划只覆盖前端 UI 布局与交互体验优化。除非实施中发现必要问题，本阶段不调整数据库结构、DOCX 生成规则、模板 profile 和后端业务接口。

## 2. 优化目标

- 建立更专业、克制、稳定的工作台界面，而不是宣传页或演示页。
- 提升项目首页的打开、创建、删除和状态识别效率。
- 提升项目编辑页的信息层级，让章节导航、当前章节、保存状态、校验和导出关系更清楚；当前版本已取消项目级“生成预览”入口。
- 降低长表格录入负担，重点优化结果记录、模板套用、图片引用插入和评分录入的操作密度。
- 改善证据图片上传、题注、排序和质量提示区域，让它更像当前章节的证据管理面板。
- 保持现有功能、接口和数据结构不变，避免为了视觉改造引入业务回归。

## 3. 当前界面主要问题

1. 项目首页层级不够明确：创建新项目、已有项目列表和删除操作混在一起，用户刷新后找回项目的路径不够醒目。
2. 项目工作台顶部操作拥挤：校验、导出、保存状态和当前项目标题没有形成清晰分组。
3. 章节导航视觉重量偏重：A-1 至 A-8 的状态展示有限，未保存状态和当前章节信息不够集中。
4. 测评表输入区像原始表格直铺：长文本、下拉、分数和模板套用都在同一视觉层级里，扫描和录入成本偏高。
5. 结果记录与证据图片区距离过远：用户在正文中插入图片引用时，需要在上下区域之间频繁切换。
6. 图片上传表单字段语义不够明确：图片文件、题注和上传状态的关系不够直观。
7. 校验与预览反馈容易打断录入：结果区域需要更清晰地分成“当前状态”和“问题明细”。
8. 当前色彩和卡片样式偏单一：主色使用较重，界面容易显得笨重，按钮和输入框层级不够细。
9. 窄屏和横向滚动体验不足：长表格必须横向滚动，但滚动区域、固定宽度和操作按钮需要更稳定。

## 4. 设计原则

- 工作台优先：首屏直接服务创建、打开和编辑，不做营销式首页。
- 信息密度适中：保留表格录入效率，同时通过分组、留白和弱边框降低压迫感。
- 操作层级清晰：主要操作、次要操作、危险操作和状态提示必须有不同视觉权重。
- 状态始终可见：当前项目、当前章节、保存状态、校验状态和预览状态应在合适位置持续可见。
- 输入不中断：长表格录入过程中尽量减少跳转、弹窗和滚动来回移动。
- 文档语境一致：界面应服务“附录A测评结果记录”编写流程，避免通用后台模板感过强。
- 变更可回退：优先调整组件结构和样式，不改变业务数据合同。

## 5. 视觉系统计划

### 5.1 色彩

- 页面背景使用浅灰白，突出主工作区。
- 当前已按 Vercel 式轻量工作台刷新视觉基线：主操作使用近黑色，次操作使用白底细边界，卡片、面板和输入框使用轻阴影模拟细边框。
- 文本使用深灰黑，辅助说明使用中性灰。
- 未保存使用浅琥珀色，成功使用低饱和绿色，错误使用红色，警告使用橙色。
- 危险操作如删除项目、删除图片使用红色弱按钮或描边按钮，避免与主操作混淆。

### 5.2 字体与排版

- 优先使用 Geist 字体，并保留中文系统字体栈兜底，确保网络字体不可用时中文界面仍清晰。
- 页面标题、章节标题、表格标题、输入标签和状态文本建立固定字号层级。
- 表格内文本不使用过大的标题字号，避免单元格撑开。
- 不使用随视口宽度变化的字体大小。
- 避免负字距，所有字距保持正常。

### 5.3 间距与圆角

- 页面主体使用稳定的左右留白和最大宽度。
- 工具栏、表格、表单和图片卡片使用统一间距 token。
- 卡片或面板圆角不超过 8px。
- 避免卡片套卡片，页面分区使用全宽面板、轻边框或分隔线表达。

### 5.4 控件

- 主按钮用于保存、生成、导出等明确动作。
- 次按钮用于校验、预览、打开等常规动作。
- 文本按钮或弱按钮用于取消、清除、删除等低频动作。
- 下拉用于模板套用、图片引用、评分和符合情况。
- 输入框、文本域、选择框保持统一边框、聚焦和禁用状态。

## 6. 信息架构调整

### 6.1 首页

首页改成“项目入口”：

- 顶部显示产品名和一句短描述，说明这是本地附录A编写工具。
- 左侧或上方提供新建项目输入和创建按钮。
- 主要区域显示已有项目列表，包含项目名、创建时间、更新时间和操作。
- 项目操作分为打开、删除，删除需要明确确认。
- 空状态应提示可以新建项目，不展示技术细节。

### 6.2 项目工作台

项目工作台改成稳定三层结构：

- 顶部工作栏：项目名称、保存状态、全部保存、校验、导出可编辑版、导出最终版。
- 左侧章节栏：A-1 至 A-8、章节标题、未保存状态、可选的校验摘要。
- 主工作区：当前章节摘要、测评表、证据图片和校验结果。

### 6.3 当前章节摘要

当前章节顶部显示：

- 章节编号，如 A-1。
- 章节名称，如物理和环境安全。
- 表题，如表A-1物理和环境安全测评结果记录。
- 本章节保存状态和图片数量。

该区域应轻量化，不能占用过多首屏空间。

### 6.4 测评表区域

测评表区域保留真实表格感，但优化录入体验：

- 表头固定视觉层级，列名更紧凑。
- 测评单元按模板库固定分组展示，测评对象列宽稳定。
- 结果记录列给足宽度，文本域高度稳定，可随内容适度扩展。
- 模板套用和图片引用下拉放在结果记录文本域下方，同一单元内分组。
- D/A/K 和符合情况使用紧凑选择控件。
- A-1、A-3 技术表的新增测评对象表单放在保存按钮下方，表格上方保留已添加对象与章节级删除入口，并作用于本章所有固定测评单元；A-2、A-4 支持所属子系统新增、删除和筛选，新增测评对象归属到当前子系统，导入后无所属子系统的对象可单个或批量归入当前子系统，已归属对象可移出当前子系统并回到未归属列表；在“全部子系统”视图下，如果对象只有一个所属子系统，也可直接移出该所属子系统；删除子系统时同步删除该子系统关联的测评行但不删除证据图片；A-4 应用和数据安全新增测评对象需要先选择用户、访问控制信息、重要数据或关键业务行为分类，并按分类同步到对应测评单元，重要信息资源安全标记完整性保留单元内新增；表格行内“删除对象”仅删除当前测评单元下该测评对象所在行，若其他单元不再包含该对象则对象列表自动移除，不删除证据图片；A-5 至 A-8 管理表的新增入口保留在对应固定测评单元内。
- A-1 至 A-4 技术表增加测评单元筛选和测评对象筛选，并与 A-2、A-4 的子系统筛选叠加；筛选只影响当前可见表格、对象列表和证据图片区，不改变保存数据。
- 横向滚动条所在区域要清晰，不影响整页滚动判断。

### 6.5 证据图片区域

证据图片区域改成当前章节证据管理面板：

- 上传区包含选择文件、题注和上传按钮。
- 字段标签明确，避免只显示占位符。
- 上传后图片以网格或紧凑列表显示。
- 每张图片显示图号、缩略图、文件名、尺寸、DPI、题注和质量提示。
- 排序操作使用上移、下移和拖拽，保持当前功能。
- 删除图片作为危险操作，视觉上弱于主操作。

### 6.6 校验与预览区域

校验反馈改成结果面板：

- 校验摘要显示错误、警告、提示数量。
- 问题明细按严重程度分组，默认优先展示错误。
- 项目级“生成预览”入口已取消，失败态说明集中在校验和导出流程内展示。

## 9. 风险与控制

- 风险：表格样式调整影响长文本录入。
  控制：优先使用 CSS 和局部结构调整，保留原有数据更新函数。

- 风险：按钮和状态重排导致用户找不到导出入口。
  控制：顶部工作栏固定展示导出入口，按钮命名保持现有语义。

- 风险：图片面板重排影响上传和排序。
  控制：不改变接口和图片数据结构，先保持现有事件处理逻辑。

- 风险：响应式处理影响宽表格可用性。
  控制：宽表格继续使用明确横向滚动，不强行压缩全部列。

- 风险：视觉优化范围扩大。
  控制：本专项不新增业务功能，不改 DOCX 生成规则，不改数据库。
