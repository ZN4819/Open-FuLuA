# R8 客户端更名打包与交付实施方案

> 状态：未实施。本文档为开发实施基线，不代表功能已交付。

## 1. 阶段定位

R8 将客户端面向用户的名称由“附录A编写工具”升级为“密评报告工具”，完成完整报告能力的 Windows 打包、升级兼容、资源准入和交付验收。

本阶段复杂度为中高。显示名修改本身简单，但安装身份、本地数据目录、自动更新、备份恢复和模板资源若同时变化，会导致用户数据丢失、双应用安装或真实报告泄漏。因此本阶段采取“只改显示名，保留技术身份和数据根”的兼容策略。

依赖：

- R1～R7 的 full_report 数据、DOCX/XLSX 导出、迁移和模板能力已完成。
- 脱敏运行时完整报告 DOCX 已经过结构和视觉验收。
- 全量前端和后端检查通过后才能进入打包。

统一契约：支持 `project_type=appendix_a|full_report`、`workflow_status=draft|ready_for_review|confirmed`、模板 `2023/2025-12-08`、`export=draft|final`、`import=migration|roundtrip`。R8 必须验收 R6 的一次性迁移和 R7 的受控 roundtrip 均已可用，不得把已交付能力回退为“不支持”。Word 不含 Ra/Rk；批注规则只 warning。用户交付输出仅 DOCX 和 XLSX，不包含 PDF。

## 2. 经仓库验证的当前基线

- `desktop/electron-builder.yml` 当前：
  - `appId: cn.fulua.appendix-a-tool`；
  - `productName: 附录A编写工具`；
  - `executableName: FuLuA`；
  - NSIS 快捷方式和卸载显示名均为“附录A编写工具”；
  - 安装包名为 `fulua-desktop-setup-{version}`。
- `desktop/src/main.ts` 当前固定使用 `%LOCALAPPDATA%\附录A编写工具` 作为 data root，并在启动页、窗口标题和欢迎通知显示旧名称。
- `backend/app/config.py` 的 `app_name` 仍为“附录A编写工具”。
- `desktop/src/diagnostics.ts`、`desktop/package.json` 和多份用户文档仍含旧名称。
- Electron 只将 `frontend/dist` 和 PyInstaller 后端目录作为 `extraResources`；没有通配复制仓库根目录。
- PyInstaller 当前仅允许 `template_profile.json`、`record_templates.json`、`scoring_template_v1.xlsx` 和前端资源；尚无完整报告运行时 DOCX。
- 当前导出 API 提供 DOCX、XLSX；render job 还包含 PDF 路径和 URL，完整交付需收紧为不向用户输出 PDF。
- 现有桌面端已经具备侧车进程、随机会话令牌、健康检查、启动闸门、备份恢复、更新和诊断能力，应该保持而不是重写。

## 3. 不可变兼容决策

以下值必须保持：

```text
appId = cn.fulua.appendix-a-tool
data root = %LOCALAPPDATA%\附录A编写工具
```

原因：

- 保持 appId 可避免 Windows 和更新器把新版本识别为另一款应用。
- 保持 data root 可让原有数据库、图片、导出历史、备份和升级日志原地可用。
- 不执行目录搬迁，不创建 `%LOCALAPPDATA%\密评报告工具`，也不复制双份数据。

`executableName=FuLuA` 和安装包文件名默认保持，以降低自动更新和运维脚本风险；它们不是面向用户的产品显示名。如确需改名，必须另开兼容性决策，不在 R8 顺带修改。

## 4. 目标与非目标

### 4.1 目标

- 所有用户可见名称统一为“密评报告工具”。
- 旧安装直接升级后继续读取原 data root 和 schema，不要求手工迁移。
- 安装包只携带明确允许的脱敏运行时 DOCX 模板，不携带基础原稿、客户真实报告或本地导出件。
- 客户端支持创建/打开两种项目、迁移完整报告和导出 DOCX/XLSX。
- 用户输出和下载入口仅 DOCX、XLSX；不提供 PDF。
- 建立可机器执行的打包资源 allowlist、敏感文件扫描和安装态验收。

### 4.2 非目标

- 不改变 appId、数据目录、GitHub 发布仓库或更新频道。
- 不删除旧项目、旧导出或备份。
- 不把真实报告作为示例、模板、测试夹具或文档附件。
- 不增加 PDF 导出、批量压缩包或云同步。
- 不在 R8 重构业务数据模型。

## 5. 显示名和运行时契约

### 5.1 名称矩阵

需要改为“密评报告工具”：

- Electron `productName`；
- NSIS `shortcutName`、`uninstallDisplayName`；
- 主窗口标题、启动页、欢迎通知、故障页 `<title>`；
- 后端 health `app_name`；
- 前端页头、空状态、导出提示和用户帮助；
- `desktop/package.json` 描述；
- 用户安装、故障排查、升级恢复、发布检查文档。

需要保持：

- `appId=cn.fulua.appendix-a-tool`；
- `%LOCALAPPDATA%\附录A编写工具`；
- 数据库和 storage 相对布局；
- `FuLuA` 进程/可执行文件名和既有 installer artifact 名，除非兼容性测试证明可安全改变。

UI 可在“关于”页面说明：“为兼容旧版本，数据仍保存在‘附录A编写工具’目录。”不要尝试隐藏或重命名目录。

### 5.2 输出契约

- `export=draft|final` 适用于 DOCX。
- XLSX 继续由权威评分生成，不区分 Word 的 draft/final 内容控件行为。
- 项目导出区只提供“导出报告 DOCX”和“导出打分表 XLSX”。
- 不提供 PDF 按钮、PDF URL、PDF 文件保留或安装包内 PDF 模板。
- 如 Word/LibreOffice 预览内部需要临时 PDF，只能写入临时预览目录、不得作为用户输出，并在任务结束/超时后清理。
- Ra、Rk 继续进入 XLSX 和内部评分，不进入 DOCX。

## 6. 脱敏运行时 DOCX 准入

唯一允许随包发布的完整报告 DOCX 建议路径：

```text
templates/report/report_template_2023_rev_2025-12-08.sanitized.docx
```

准入要求：

- 不含真实单位、系统、联系人、电话、邮箱、地址、报告编号、金额、人员或客户图片；
- 不含作者批注、修订、外部关系、OLE、宏、嵌入包或远程模板；
- 不含 `XXX`、`20XX`、“贴图”、`{扫描件}` 等会泄露到 final 的示例占位符；必须使用工具可识别的语义槽位或保持空白；
- 保留 55 表、17 分节、标题样式、必要书签和版式；
- 记录 edition、revision、SHA-256 和结构摘要；
- 通过 DOCX 重解析和 Word/LibreOffice 打开无修复提示验收。

PyInstaller 使用逐项 allowlist 添加该文件。构建脚本在产物生成前扫描：

- 仓库和打包 staging 内所有 `.docx`；
- 归档内容、文件名和关系；
- 只有 allowlist 中路径及摘要完全匹配者可进入后端资源。

任何额外 DOCX、客户报告特征、根目录报告、`storage/`、`backend/data/app.db`、导出件、备份、导入任务或临时渲染文件存在于 bundle 时，构建必须失败。

## 7. 架构及 API/UI 契约

### 7.1 后端

- `settings.app_name` 改为“密评报告工具”，不改变 runtime path 解析。
- health 继续返回实际 data root、schema 和版本，供桌面启动闸门校验。
- 发布清单新增运行时 DOCX 的路径、SHA-256、edition 和 revision。
- 导出接口返回 DOCX/XLSX；render job 对外 schema 移除 PDF URL，或在兼容期固定返回 null 并在下一 schema 版本移除。
- 模板加载只通过 `resolve_resource_path` 和模板注册表，不能回退搜索仓库根目录的任意 DOCX。

### 7.2 桌面端

- `dataRoot` 代码保持旧目录字面值，并增加回归测试锁定。
- 启动闸门验证 schema、模板资源摘要、前端资源和后端版本。
- 安装升级测试验证旧数据库原地升级、旧备份可读和项目类型正确。
- 诊断信息显示新产品名，但不得输出完整客户路径、会话令牌或正文。

### 7.3 前端

- 首页以项目类型区分“附录 A 项目”和“完整报告项目”。
- workflow_status 使用统一状态文案：草稿、待复核、已确认。
- 导入入口标记 migration；roundtrip 未实现时不显示可执行按钮。
- 导出区只展示 DOCX/XLSX，并明确 draft/final 对 Word 的影响。
- 批注规则 warning 不阻止 final；真正的数据/文件结构 error 才阻止。

## 8. 可提交工作包

### R8-WP1：名称矩阵与兼容锁定

- 输入：当前 electron-builder、main.ts、config.py 和用户文档。
- 具体改动：集中定义显示名；更新所有用户可见文案；增加 appId 和 data root 不变的契约测试。
- 失败行为：检测到 appId 或 data root 改动时测试失败；不以自动迁移“修复”。
- 测试：字符串扫描、窗口标题、health、NSIS 配置、旧目录解析。
- 验收：用户界面只显示新名，技术身份和数据位置保持。
- 建议提交：`R8-WP1: 客户端显示名升级为密评报告工具`。

### R8-WP2：脱敏模板准入与版本核验

- 输入：R0 已验收的脱敏运行时 DOCX、manifest、资产哈希和模板身份。
- 具体改动：不重新制作或修改模板，只核验 R0 资产包的摘要、结构、标签、批注、占位符和资源路径，将已批准资产登记为客户端唯一准入模板。
- 失败行为：摘要、结构、版本或脱敏扫描任一不通过则后端启动/构建失败，不回退真实文件。
- 测试：55 表、17 分节、标题、书签、外部关系、批注、敏感词和模板版本。
- 验收：客户端准入 DOCX 与 R0 已批准资产逐字节一致，只存在一个准入版本，打开无修复提示。
- 建议提交：`R8-WP2: 纳入脱敏完整报告运行时模板`。

### R8-WP3：打包 allowlist 与泄漏扫描

- 输入：PyInstaller spec、Electron extraResources、模板 manifest。
- 具体改动：显式打包脱敏模板；增加 bundle 清单、DOCX allowlist、真实报告特征和 storage/data 排除测试。
- 失败行为：发现任意未准入 DOCX 或敏感产物立即终止构建并报告相对路径，不复制产物。
- 测试：故意放入伪客户报告、storage 导出、app.db、备份和第二个 DOCX 的负向测试。
- 验收：安装目录文件清单只含应用、前端、后端、JSON/XLSX 模板和唯一脱敏 DOCX。
- 建议提交：`R8-WP3: 强化客户端打包资源准入`。

### R8-WP4：移除 PDF 用户交付面

- 输入：现有 render job 的 PDF 字段和前端预览/导出入口。
- 具体改动：移除 PDF 下载和持久输出；内部预览若使用 PDF，改为临时文件并清理；更新 API schema 和文档。
- 失败行为：预览转换失败只影响预览，不生成残留 PDF；DOCX/XLSX 导出仍独立工作。
- 测试：API 无 PDF 链接、UI 无 PDF 按钮、storage/exports 无 PDF、临时任务清理。
- 验收：用户可获得的输出扩展名只有 `.docx`、`.xlsx`。
- 建议提交：`R8-WP4: 收敛交付输出为DOCX和XLSX`。

### R8-WP5：旧版原地升级与恢复测试

- 输入：旧安装数据布局、schema 3 备份、升级器和恢复流程。
- 具体改动：建立旧版数据夹具；安装旧版数据后升级新包；验证 schema、A 项目、full_report、图片、模板定制和备份恢复。
- 失败行为：升级前自动备份；启动闸门发现高版本库、迁移失败或资源缺失时阻止进入主界面并提供恢复入口。
- 测试：覆盖安装、卸载保留数据、重新安装、升级失败恢复、自动更新、无管理员安装。
- 验收：升级后仍使用旧 data root，不创建新名目录，不丢数据。
- 建议提交：`R8-WP5: 验证旧版客户端原地升级兼容`。

### R8-WP6：安装态端到端验收

- 输入：签名前候选安装包、脱敏验收数据。
- 具体改动：执行安装、创建两类项目、迁移、编辑、确认、DOCX/XLSX 导出、重启、备份恢复、卸载重装和更新检查；生成发布清单。
- 失败行为：任一资源泄漏、导出修复提示、数据目录漂移或更新身份变化阻止发布。
- 测试：自动契约检查加 Windows 人工验收；最终产物哈希记录。
- 验收：候选包满足全部发布闸门且只含脱敏数据。
- 建议提交：`R8-WP6: 完成密评报告工具客户端交付验收`。

## 9. 迁移与回滚

- 安装升级前沿用现有自动备份；不移动 data root。
- schema 迁移失败时显示恢复窗口，允许从升级前备份恢复，禁止继续写库。
- 显示名回滚不影响 appId、数据和更新身份；旧版本仍可找到原目录。
- 新版 full_report 数据无法由旧版理解时，旧版应拒绝写入而不是删除未知表。
- 运行时模板按 manifest 版本选择；回滚应用时使用随旧包提供的模板，不覆盖项目数据。
- 卸载默认不删除 `%LOCALAPPDATA%\附录A编写工具`；彻底删除必须由用户单独确认。

## 10. 风险与安全

- 最大风险是把真实报告、数据库或导入/导出件打入安装包；必须由机器 allowlist 而非人工目检兜底。
- 保留旧 data root 可能让用户疑惑，应在“关于”和支持文档解释，不能以重命名目录解决。
- 显示名变化可能影响快捷方式；NSIS 升级测试要确认旧快捷方式被更新且不重复。
- 自动更新依赖 appId、发布仓库、频道和 artifact 兼容，均需锁定。
- 诊断包、日志、崩溃信息不得包含 token、正文或敏感绝对路径。
- 模板摘要校验防止本地被替换为真实报告或恶意 OOXML。
- 最终版 DOCX 必须清理批注；规则 warning 不等同于审计通过。

## 11. 阶段验收闸门

- 所有用户可见名称为“密评报告工具”。
- appId 精确保持 `cn.fulua.appendix-a-tool`。
- data root 精确保持 `%LOCALAPPDATA%\附录A编写工具`，安装和升级均不创建新名数据目录。
- 安装包只含 manifest 准入的脱敏运行时 DOCX；真实文件和所有运行时数据被排除。
- DOCX 模板 SHA-256、55 表、17 分节、无批注/修订/外链检查通过。
- 用户输出仅 DOCX 和 XLSX，storage/exports 不产生 PDF。
- appendix_a 与 full_report、三种 workflow_status、draft/final、migration 和 roundtrip 流程均通过安装态验收。
- DOCX 无 Ra/Rk；XLSX 保留权威评分。
- 全量测试、依赖审计、构建清单、升级恢复、卸载重装和自动更新验证通过。

## 12. 分支、提交与 PR

- 建议分支：`codex/r8-client-rename-release`。
- WP1～WP6 独立提交；脱敏 DOCX 提交必须单独提交并附结构摘要，不附源报告。
- PR 标题：`R8: 完成密评报告工具更名、打包与交付`。
- PR 描述必须明确：appId 不变、data root 不变、只准入脱敏 DOCX、真实报告未提交、无 PDF 输出、安装态升级和恢复结果。
- 合并前由独立审查者复核打包文件清单和 `git diff --name-only`，再创建正式发布候选。
