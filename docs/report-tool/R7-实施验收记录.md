# R7：受控 Word 回收实施验收记录

## 1. 验收结论

R7 已完成严格同源的受控 Word 回收实现。完整报告项目可显式生成“可回收草稿”，在 Microsoft Word 中只修改服务端白名单内的既有事实字段和附录 A 既有业务行，再通过“上传—结构预检—三方差异—冲突决议—原子提交”流程回写当前项目。

该能力不是任意 Word 导入。只有本机签发、与项目及不可变导出快照匹配、`export_mode=draft` 且 `roundtrip_capable=true` 的 DOCX 才能进入回收流程；普通草稿、正式版、外部报告、来源清单缺失或签名不符的文档均被拒绝。图片、Ra/Rk、对象分、单元分、修正后分值、模板常量、派生统计和结论始终不从 Word 回收。

本阶段未使用 LibreOffice。完整报告的结构、字段刷新和回存兼容性只以 Microsoft Word 原生结果为准。

## 3. 关键实现

### 3.1 可回收草稿与签名清单

- 只有“生成可回收草稿”入口发送 `roundtrip_capable=true`；普通草稿和正式版契约保持不变。
- 服务端从冻结字段矩阵生成可写字段、既有行、规范化器、基线值摘要和结构契约，再以本机密钥签名。
- Windows 使用当前用户 DPAPI 保护本机 HMAC 密钥；密钥材料不写日志、不进入 manifest、不打包到安装目录。
- 清单签名同时覆盖项目、导出任务、快照、模板、字段字典、评分引擎、可写契约和基线摘要。
- Microsoft Word 字段刷新前临时解除受控内容控件锁，刷新后核对内容控件标签和顺序并恢复原锁；临时未锁版本不会作为导出结果发布。

### 3.2 不可信 DOCX 预检与结构边界

- 上传文件进入数据库同级私有隔离目录，限制文件大小、ZIP 条目、解压总量、压缩比和路径。
- 拒绝宏、ActiveX、OLE/嵌入包、外部关系、远程模板、危险字段、XXE 和全部未接受修订类型。
- custom XML 必须恰好组成一个工具签发的固定关系图；额外、重复、缺失或非 Word 标准重编号均拒绝。
- 对受控 block/row/slot 标签执行唯一性、层级、行集合、顺序、槽位集合和几何校验，不根据表格位置猜测字段。
- 图片字节变化只形成“不回收”警告；图片造成关系或业务结构损坏时升级为阻断错误。

### 3.3 三方差异、冲突和原子回写

- 使用签发快照 B、上传时数据库 D、Word 提取值 W 生成确定性三方 diff。
- `D=B,W≠B` 自动应用 Word；`W=B,D≠B` 保留数据库；双方不同且互不相等时要求逐项选择。
- 同一权威字段存在多个 Word 投影时，规范化值必须一致；不一致直接阻断，不按位置择一。
- 冲突决议绑定 diff hash 和项目 revision；项目变化后任务标记为 `stale`，旧决议不能提交。
- 提交时再次逐项读取数据库值，防止遗漏 revision 的旧写入路径造成静默覆盖。
- 事实字段写入、附录 A 权威评分重算、结果修正、R3 派生重算、正文失效传播和审计记录均位于同一事务；任一步失败都不产生部分写入。
- 重复提交相同成功任务返回既有审计结果，不重复改变项目 revision。

### 3.4 前端工作台

- 项目导出区新增“生成可回收草稿”，并在回收区明确说明已有行、图片、修订和只读字段限制。
- 独立 R7 客户端覆盖上传、任务、问题、diff、决议和 commit 六类接口，不与 R6 迁移状态机混用。
- 差异按章节和对象分组显示 B/D/W；冲突必须全部选择并保存后才允许提交。
- `invalid`、`failed`、`stale` 没有强制绕过入口；图片和只读变化单独显示为“不回收”。
- 未保存冲突决议接入现有离开页面保护；提交成功后刷新项目并提示评分和派生内容已由后端重算。

## 4. 根因级兼容修正

1. Microsoft Word 在内容控件锁定时不能更新目录。现只对私有临时副本解除锁，Word 回存后验证标签和顺序，再恢复与签发前完全相同的锁；原始受控结构不会暴露为未锁导出物。
2. Microsoft Word 会把自定义 XML 标准化为 `customXml/itemN.xml` 并重建关系 ID。现只接受工具固定关系图或该唯一 Word 标准化图，不放宽为任意 custom XML。
3. Word 会重排等价空白、换行和目录缓存，并可能清理未引用脚注。现只对等价表示进行规范化，目录按稳定域指令参与只读摘要，脚注/尾注只计算正文实际引用项；真实只读内容变化仍会阻断。
4. R7 私有密钥和签发源文件最初未进入备份范围。现备份、恢复和失败回滚同时覆盖数据库同级 `private/`；私有文件始终字节复制，避免硬链接导致旧备份被现场写入污染。
5. schema 10 新表最初会被空目标数据迁移误判为用户数据。现将 R7 系统表纳入允许清单，并在 schema 10 迁移预检中执行结构审计。
6. 旧草稿的签名只证明签发时允许写入，不能永久覆盖当前策略。上传时会再次按当前 R2 字段矩阵核对每个槽位；权限已收窄的旧草稿整份拒绝并要求重新导出。
7. 首次并发导出可能同时创建本机签名密钥。现使用唯一临时文件、落盘同步和原子“仅首次创建”发布；竞争失败方只读取最终落盘密钥，不会产生两把有效密钥。
8. Word 域结果缓存、批注和只读正文必须区别处理。只读摘要保留域前后固定文本并绑定规范化域指令，忽略可重算的结果缓存；批注正文不进入业务摘要但仍执行主动内容安全扫描，并在变化时给出“不回收”警告。
9. 过期任务最初可能只在当前请求内返回 409，数据库状态或前端仍停留在可提交。现将 `stale` 先持久化再响应；错误 expected revision 与真实项目变化分开处理，前端收到过期码后重新读取任务并清空旧决议。
10. 无效上传最初缺少磁盘总量、保留数量和异常退出恢复。现增加 64 MB 单文件、1 GB 私有区总量、原子 `.uploading` 清理、最多 8 份失败源文件保留及确定性淘汰；启动时把遗留 `uploaded/validating` 任务标记为中断并纳入同一保留策略。桌面侧车同时把会话令牌校验扩展到全部变更型 API。
11. 项目删除最初采用软删除并保留完整 manifest/audit，会继续保存客户内容。现改为单事务写入仅含摘要的不可变墓碑，再物理删除项目、签发清单、审计明细、回收任务和导出快照；墓碑不含正文、字段值、人员、文件名或路径。
12. 数据库删除与文件删除不能成为不可重试的两个半步骤。现为每次删除写入不含业务明文的持久清理队列，公开 storage 与私有 DOCX 独立尝试，失败时返回 `X-FuLua-Cleanup-Pending` 并在下次启动重试；私有清理与上传共用同一互斥锁，避免删除检查后上传才写出无主文件。

## 6. 阶段闸门与 R8 交接

R7 已满足进入 R8 的功能闸门：

- 可回收草稿可被精确定位到本机签发记录、项目和不可变导出快照。
- Word 只能修改白名单事实和既有业务行；越界字段、结构、修订和主动内容均由后端阻断。
- 三方 diff、冲突决议、并发失效、原子提交、权威重算和审计已形成闭环。
- 真实 Microsoft Word 的字段刷新、保存标准化和未修改回收已通过；修改值、冲突、篡改和回滚路径由自动化测试覆盖。
- schema 10、私有密钥、上传归档和备份恢复契约已纳入桌面运行时。
- 项目删除、失败上传清理、会话令牌和过期任务恢复已通过审查修复及回归测试。

R8 可以在此基础上执行产品更名、资源白名单、安装包和隔离安装态交付验收。R8 不得改变 R7 的签名、白名单、已有行、图片不回收和后端权威评分边界。

本阶段已证明最新 R7 代码能够生成后端目录、Electron 解压版和 NSIS 安装包，但未执行会创建并删除仓库外系统临时目录的安装态验收；该项按阶段边界留给 R8，在获得相应文件操作授权后执行。
