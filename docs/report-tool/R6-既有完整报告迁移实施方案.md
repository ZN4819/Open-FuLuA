# R6 既有完整报告迁移实施方案

> 状态：已完成技术实现、自动化回归、Microsoft Word 原生刷新、真实报告只读迁移和 Windows 安装态验收；[PR #34](https://github.com/ZN4819/Open-FuLuA/pull/34) 已创建，交付详情见《R6 实施验收记录》。

## 1. 阶段定位

R6 面向已经手工编写的当前三级完整报告，提供一次性、可审阅、不可破坏源文件的迁移流程，把封面、主体章节、资产、测评结果、风险、附录 A 和附录 B 尽可能迁入 `full_report` 项目。

本阶段复杂度为最高。DOCX 并不是稳定数据库：同一模板经过复制编辑后会出现表格扩行、合并单元格漂移、书签变化、缓存字段错误和文本歧义。因此迁移必须以“识别—预览—确认—创建新项目”为边界，不能直接覆盖已有项目，也不能承诺任意 DOCX 往返无损编辑。

依赖：

- R2 已交付并冻结《报告字段及参数关联矩阵》，其中包含稳定关联 ID、权威字段 ID、实体路径、可编辑性、约束表达式、缺失/冲突行为和目标槽位。
- R3 已交付并冻结《派生计算与文案生成规则矩阵》及黄金测试向量，能够从迁入的事实数据重新计算统计、风险、得分、结论和派生正文状态。
- 完整报告数据模型、章节模型和项目统一契约已经落地。
- R5 的附录 B 九类数据和图片模型可用。
- 2023 版、2025-12-08 修订模板的结构指纹已经版本化。
- 当前 A-1～A-8 导入器仍作为附录解析能力复用，但不得直接承担完整报告迁移。

统一契约：`project_type=appendix_a|full_report`；`workflow_status=draft|ready_for_review|confirmed`；`import=migration|roundtrip`。R6 只实现 `migration`；`roundtrip` 仅登记为未来能力，调用时明确返回 501/不支持。Ra、Rk 不从 Word 导入也不写回 Word；模板批注规则只产生 warning。

## 2. 经仓库验证的当前基线

- 现有 `POST /api/imports/docx` 最大接收 200 MB DOCX，保存到 `storage/imports/{job_id}`，解析后生成预览任务。
- 当前导入器只识别 A-1～A-8 表、图片和交叉引用；确认接口只会创建新的 A 项目。
- 当前 `docx_import_jobs` 保存原文件相对路径、解析 JSON、问题 JSON、状态和创建后的项目 ID。
- 当前导入任务状态为 uploaded/parsing/preview_ready/importing/succeeded/failed，已具备异步式预览数据模型。
- 当前导入失败采用结构化 issue；存在 error 时不能创建项目。
- 当前项目只有 A-1～A-8；不存在完整报告章节、字段来源、迁移置信度或待确认项。
- 数据库已有复制 A 章节的底层能力：复制行、评分、图片和交叉引用时能够重新映射 ID，但目前 API 主要按章节导入使用。
- 基础模板 112 页、55 张表、17 分节；客户复核版 132 页、55 张表、16 分节。表数稳定，行数、内容控件、书签和分节会漂移。
- 完整报告包含客户敏感信息，真实样本只能作为本地人工验收输入，不得进入 Git、测试夹具或打包资源。

## 3. 目标与非目标

### 3.1 目标

- 只支持当前三级报告模板族：`template_edition=2023`、`template_revision=2025-12-08`。
- 对 DOCX 做包结构、章节、表格、字段、图片、批注和书签扫描，输出模板匹配度和迁移预览。
- 所有结构化候选必须先映射到 R2 关联 ID 和权威字段 ID；高置信字段可默认采用，歧义内容保留原文并标记“待确认”，不得按 Word 位置临时造字段、猜测或丢弃。
- Word 中的统计、得分、风险数量、结论和其他 R3 派生结果只作为来源对照，不作为项目权威值；迁入事实数据后由当前规则重新计算，并保留源值、重算值和差异原因。
- 确认后创建全新的 `full_report`、`workflow_status=draft` 项目，源 DOCX 永不修改。
- 支持把既有 `appendix_a` 项目的 A-1～A-8 复制到 full_report，作为 DOCX 附录解析的可选替代来源。
- 迁移完成后生成差异摘要和审阅队列。

### 3.2 非目标

- 不支持任意版本、任意机构或任意排版的完整报告。
- 不承诺像素级复原原 DOCX，也不保留未知宏、OLE、嵌入文档或浮动对象。
- 不实现 `roundtrip` 回写原文件。
- 不覆盖现有项目，不把迁移结果直接标为 ready_for_review 或 confirmed。
- 不从 Word 推断 Ra/Rk，也不把 Word 中显示的对象分、单元分、层面分、综合得分或结论作为权威输入；Ra/Rk 按内部新建/复制契约初始化，且来源明确记为 `defaulted` 或 `copied`，不得伪装为 `imported`。
- 不把模板批注变成硬错误。

## 4. 架构及数据契约

### 4.1 两阶段迁移架构

```text
上传只读副本
  -> ZIP/OOXML 安全扫描
  -> 模板指纹识别
  -> 章节与 55 表解析
  -> 原始片段 + 结构化候选 + 置信度
  -> 预览和待确认项
  -> 用户确认/选择 A 来源
  -> 单事务创建 full_report
  -> 文件复制及 ID 重映射
  -> 迁移后校验和差异摘要
```

解析器不得直接调用项目写接口。所有写入集中在 confirm 服务的事务中；图片文件采用临时目录复制，事务成功后原子移动，失败时清理。

### 4.2 数据模型

扩展或新建 `report_import_jobs`，不要继续把完整报告字段塞进附录专用 JSON：

```text
report_import_jobs
  id, mode, status, job_revision, original_name, source_docx_path, source_sha256,
  detected_edition, detected_revision, fingerprint,
  parsed_json_path, summary_json,
  created_project_id, created_at, started_at, finished_at, error_message

report_import_issues
  id, job_id, revision, code, severity, association_id, authority_field_id,
  field_path, source_locator, original_text, source_value_hash,
  candidate_value_json, confidence, status, needs_confirmation,
  blocks_confirmation, blocks_final_export, created_at, updated_at

report_import_resolutions
  id, job_id, issue_id, issue_revision, association_id, authority_field_id, field_path,
  action, resolved_value_json, resolved_by_user, created_at, updated_at

report_field_sources
  project_id, report_import_job_id, association_id, authority_field_id, field_path,
  source_kind, source_locator, source_value_hash, original_text,
  confidence, mapping_status, needs_confirmation, created_at, updated_at
```

`report_import_issues` 是待确认项和导入诊断的权威来源，禁止只把问题塞进不可查询的 JSON。`association_id` 和 `authority_field_id` 必须引用 R2 冻结矩阵；无法引用时只能登记为 `unmapped`，不能直接写项目字段。`source_locator` 只保存诸如 `table:2/cell:5,3`、`paragraph:164` 的逻辑位置，不保存外部绝对路径。原文保存在本地数据库；API 对展示长度做限制。

置信度：`exact|high|ambiguous|unmapped`。只有 `exact|high`、通过字段类型校验、满足 R2 约束且不是只读投影、模板常量或 R3 派生输出的候选可默认采用；`ambiguous|unmapped` 必须保留原始文本并进入待确认队列。

### 4.3 模板识别

指纹至少包含：

- 55 张顶层表；
- 一级标题序列；
- A-1～A-8 和附录 B 九表的列结构；
- 关键固定文本；
- 纵横向分节模式；
- 模板版本声明。

页数、行数、内容控件数、书签数、分页字段缓存不得作为单独否决条件。结构缺失造成无法确定章节边界时才产生 error；分节数 16/17、书签漂移或旧页数缓存只产生 warning。

### 4.4 API 契约

```text
POST /api/report-imports/docx?mode=migration
GET  /api/report-imports/{job_id}
PUT  /api/report-imports/{job_id}/resolutions
POST /api/report-imports/{job_id}/confirm
GET  /api/projects/{project_uuid}/report/migration-review
POST /api/projects/{target_uuid}/report/appendix-a/copy
```

上传只接受 `.docx` 且校验 ZIP/OOXML 内容类型，不接受 `.docm`。`mode=roundtrip` 返回明确的 `ROUNDTRIP_NOT_IMPLEMENTED`。

confirm 请求：

```json
{
  "job_revision": 4,
  "project_name": "...",
  "appendix_a_source": "document|existing_project",
  "appendix_a_project_uuid": "uuid",
  "accepted_resolutions": [12, 15],
  "keep_unresolved_original": true
}
```

成功返回新项目 ID、迁移摘要、warning、待确认数；任何写入失败不得返回部分项目。

项目创建后的 resolution 请求除 `job_revision` 外，还必须携带读取任务时返回的 `created_project_updated_at`。后端在同一写事务中比较该项目版本；若其他页面已经修改项目则返回 409，禁止迁移审阅覆盖较新的人工编辑。响应中的 resolution `applied` 由实际字段来源状态计算，不由客户端 action 推断。

### 4.5 UI 契约

- 项目首页新增“迁移既有完整报告”，明确写明仅支持当前三级模板、创建新项目、不会修改原文件。
- 预览分为模板匹配、章节统计、自动映射、待确认、未识别内容和附录来源六区。
- 每个候选显示源文本、目标字段、逻辑位置和置信度；不显示本机绝对路径。
- 歧义项提供“采用候选”“保留原文待确认”“暂不迁移”，默认选中保留原文。
- A 来源可选“当前 DOCX”或“从已有附录 A 项目复制”；选择已有项目时显示最近更新时间和 A 完整度。
- 迁移完成进入新项目的“迁移审阅”页，workflow_status 固定为 draft。

### 4.6 R2/R3 权威映射与重算契约

迁移解析器不得直接以段落号、表格号、可见标签或内容控件顺序决定数据库写入路径。每个候选必须经过以下链路：

```text
Word 源定位
  -> R0 槽位/表格身份
  -> R2 association_id
  -> R2 authority_field_id + entity_path
  -> 类型与业务约束校验
  -> imported candidate / ambiguous / unmapped
  -> confirm 写入事实字段
  -> R3 rule_id 重算派生字段和正文状态
```

- 同一权威字段出现在多个 Word 槽位时，先按 R2 的重复投影关系归并。规范化后全部相同才形成一个候选；存在不同值时生成 `REPEATED_SLOT_VALUE_CONFLICT`，保留每个槽位的原文和位置，禁止按首页、正文或“最后一个值”任选。
- 密评机构名称、地址、邮政编码、联系人、固定威胁目录等模板包常量不可由迁移覆盖。源文档值只作为对照证据；与当前模板包不一致时生成明确 issue，由用户选择正确模板包或保留为迁移备注。
- 报告编号、系统名称、被测单位、日期、人员、报告分发、表 2-3 密码产品、附录 B 日期等事实字段按 R2 矩阵落库，并执行与新建项目相同的约束；迁移模式不得绕过唯一性、日期先后、人员互斥和数量对平规则。
- 八层/总体统计、指标结论、结果修正、综合得分、风险数量和等级汇总、高风险判断、评估结论以及 R3 管理的派生正文不得从 Word 直接写入权威字段。系统必须保存源显示值或源文本摘要，基于已确认事实运行当前 R3 规则，并生成“源值/重算值/规则 ID/差异原因”。
- 允许人工改写的总体评价、系统简介、问题及建议等文本，可作为独立的 `imported_manual_draft` 候选保存；它不能覆盖对应的生成基线，也不能自动标记为已确认。底层事实或规则变化后仍按 R3 依赖关系标记过期。
- 附录 A 的 D/A/K、管理符合情况和记录文本属于可迁事实；Ra/Rk、对象分、单元分、结果修正后分值及星号显示属于内部输入或派生投影，不从 Word 取值。写入原始事实后统一调用后端评分、结果修正和最终投影链路。
- 迁移可创建仍含待确认项的 `full_report/draft`，但每个必确认映射必须保留 issue 与 resolution 状态；未解决项、重算失败或 R3 输出过期均进入最终版导出阻断清单。

## 5. 内容映射策略

### 5.1 高置信结构化映射

- R2 矩阵中标记为可导入、可编辑且具有稳定槽位/表格身份的封面、基本信息和固定键值字段；
- 项目成员、资产清单、工具清单、对象清单及附录 B 九类事实数据；
- A-1～A-8 固定指标的原始记录、D/A/K 和管理符合情况；
- 风险记录中的人工事实和等级选择，但不包括由 R3 汇总的风险数量、整体风险等级或结论文案；
- 每个采用值都必须保存 R2 `association_id`、权威字段 ID、逻辑源定位、源值哈希和置信度。

### 5.2 原文保留映射

总体评价、测评过程、密码应用情况、结果分析、改进建议、风险分析说明等长文本，仅在 R2/R3 契约允许人工版本时作为待确认草稿，同时保存：

- `original_text`；
- 可编辑的目标正文；
- 源定位；
- `needs_confirmation=true`。

如果该文本属于 R3 派生块，还必须保存对应 `rule_id`、当前生成基线哈希和与源文本的 diff；迁移原文不得把派生状态直接置为 confirmed。

不得通过关键词替换自动“优化”客户文字。

### 5.3 不迁移内容

- Word 缓存页码和总页数；
- TOC/PAGEREF 的显示缓存；
- 模板作者批注及修改历史；
- 未知 OLE、宏和外链；
- Word 中不存在的 Ra/Rk；
- 对象分、单元分、层面统计、综合得分、风险汇总、高风险判断、评估结论等可由 R3 重算的显示值；
- 模板包常量以及同一权威字段的重复投影副本；
- 仅用于排版的空白段落和占位符。

批注中若包含规范规则，只在预览中生成 warning；不作为正文，也不阻断迁移。

## 6. 可提交工作包

### R6-WP1：模板指纹与安全扫描

- 输入：脱敏基础模板结构摘要、当前三级报告样本的本地只读分析结果。
- 具体改动：实现 ZIP 安全检查、模板指纹、55 表/标题/分节扫描和结构化 issue。
- 失败行为：加密、损坏、docm、路径穿越、解压膨胀或关键结构缺失立即失败；版本漂移返回不支持而非猜测。
- 测试：合法模板、16/17 分节、行扩展、书签缺失、伪 DOCX、ZIP bomb 防护。
- 验收：基础模板和客户复核版均识别为同一模板族；未知模板不进入确认阶段。
- 建议提交：`R6-WP1: 建立完整报告模板识别与安全扫描`。

### R6-WP2：主体解析与来源追踪

- 输入：R0 槽位/表格身份、R2《报告字段及参数关联矩阵》、55 表映射表和章节字段 schema。
- 具体改动：解析封面、基本信息、章节文本、资产、对象、风险事实和附录 B；为每个候选生成 association ID、权威字段 ID、来源、原文、值哈希和置信度；归并重复投影并显式报告不一致。
- 失败行为：单字段解析失败降级为 unresolved，保留原始片段；章节边界无法确定才终止。
- 测试：合并单元格、扩行、空表、长文本、重复槽位一致/冲突、模板常量覆盖尝试、旧字段缓存、模板示例残留、批注存在。
- 验收：每个已采用字段都能追溯到 R2 矩阵；任何 ambiguous/unmapped 内容都可在预览中看到原文，不发生静默丢弃。
- 建议提交：`R6-WP2: 解析完整报告主体并追踪字段来源`。

### R6-WP3：附录 A/B 解析与复制 A 项目

- 输入：现有附录 A 导入器、R5 数据模型、数据库复制能力。
- 具体改动：适配完整报告内 A 表；只提取 Word 可表达的 A 原始事实并由后端重算评分；解析 B 九类；实现从旧 appendix_a 项目复制 A-1～A-8、Ra/Rk、图片和引用并重新映射 ID。
- 失败行为：目标项目必须是空的 full_report draft；来源不存在或图片缺失时不开始复制；事务失败回滚所有行。
- 测试：A2 大量对象、A7 双对象、图片引用重映射、固定对象、管理评分重算、重复请求幂等键。
- 验收：DOCX 来源的 Ra/Rk 标记为 defaulted、权威分值全部重算；项目复制来源的 Ra/Rk 保持 copied；两种路径均不从 Word 接受对象分/单元分，Ra/Rk 不进入 Word。
- 建议提交：`R6-WP3: 支持完整报告附录迁移与A项目复制`。

### R6-WP4：预览、歧义确认与 API

- 输入：解析候选和统一 issue 契约。
- 具体改动：实现 report import job、按 R2 association ID 解决歧义的 resolution API、confirm 事务和清理策略；预览同时展示源值、候选事实值和 R3 预计重算项。
- 失败行为：重复 confirm 返回既有成功结果；过期或已失败任务返回 409；未确认 error 不允许创建项目；未知 association ID、模板常量覆盖和伪造派生值不得进入写入计划。
- 测试：并发确认、重复确认、resolution 越权、未知/错配 association ID、任务删除、confirm 中途文件失败。
- 验收：源文件始终不变；写入计划只包含 R2 事实字段；失败时没有半成品项目和孤儿图片。
- 建议提交：`R6-WP4: 实现完整报告迁移预览与确认事务`。

### R6-WP5：迁移审阅 UI

- 输入：job、candidate、resolution、summary API。
- 具体改动：新增上传、模板匹配、差异预览、待确认、A 来源选择和迁移后审阅页面。
- 失败行为：网络失败保留用户已选 resolution；离开未确认页给出提示；不把 warning 渲染成阻断 error。
- 测试：完整流程、未知模板、仅 warning、存在 error、大量待确认、键盘可访问性。
- 验收：用户能解释每个迁移字段来源，并可在创建项目前看到未识别内容。
- 建议提交：`R6-WP5: 完成既有完整报告迁移审阅界面`。

### R6-WP6：迁移后校验与本地真实报告验收

- 输入：本地客户复核版、脱敏结构夹具、完整报告导出器。
- 具体改动：生成迁移摘要；校验项目类型、章节、55 表覆盖、A/B、图片、R2 映射覆盖、R3 重算差异、评分和待确认数；用本地真实报告进行一次人工验收但不提交文件或数据。
- 失败行为：事实写入、后端评分或 R3 重算失败时任务失败并回滚；warning 和未解决非阻断项仅允许项目保持 draft，禁止 final。
- 测试：R2 关联矩阵黄金映射、R3 黄金向量重算、源显示分数伪造、重复槽位冲突、全量检查、DOCX 导出重解析、XLSX 同源评分、真实报告只读迁移。
- 验收：可从客户复核版创建新项目；所有权威派生值来自当前后端重算；源值与重算差异可追溯；源 SHA-256 前后相同；Git 状态不出现真实文件。
- 建议提交：`R6-WP6: 完成完整报告迁移验收`。

## 7. 迁移与回滚

- schema 升级前创建 SQLite 一致性备份。
- 上传文件复制到 data root 的任务目录；绝不移动、重命名或修改用户原文件。
- confirm 使用新项目创建事务，目标 ID 在全部数据库写入成功后才写回 job。
- 文件先进入任务 staging，提交后移动到项目目录；失败时清理 staging。
- 迁移完成后允许用户删除任务源副本，但删除项目不自动删除仍在保留期内的任务证据，避免审计链断裂。
- 应用回滚后新表保留；旧版本只读不了 full_report 时应提示版本不兼容，不尝试降级转换。
- 项目级回滚采用删除新迁移项目，绝不反向写回原 DOCX。
- 删除迁移项目必须同时按保留策略处理字段来源、issue、resolution 和重算审计；回滚不得用源 Word 的统计、分值或结论反向覆盖当前规则结果。

## 8. 风险与安全

- DOCX 为不可信 ZIP：限制总大小、条目数、解压后大小、压缩比和关系目标路径。
- 禁止处理宏、外部关系、远程模板、DDE、嵌入包和 OLE；记录 warning 后忽略，危险类型直接拒绝。
- 真实报告、解析 JSON、图片和数据库只在本地 data root，日志不得记录完整正文、证件号、电话或绝对客户路径。
- API 返回源文本时按项目/任务授权并限制长度；导出诊断包必须脱敏。
- 不用 AI 或模糊匹配直接覆盖高风险字段；低置信度永远待确认。
- 不因批注中的“应当”把迁移阻断；规则的法律和版本有效性由版本化规则包管理。

## 9. 阶段验收闸门

- 仅接受 migration，roundtrip 明确不支持。
- 只识别 2023/2025-12-08 当前三级模板族，未知模板安全失败。
- 源文件 SHA-256 迁移前后相同。
- ambiguous/unmapped 全部保留原文并进入待确认，不静默猜测。
- 已采用字段全部引用 R2 association ID 和权威字段 ID；重复槽位不一致时不得任选值。
- R3 派生字段、模板包常量和 Word 显示分值不作为迁移权威输入；源值保留、当前规则重算、差异可解释。
- confirm 原子性、幂等性和失败清理测试通过。
- 从旧 appendix_a 项目复制 A-1～A-8 全量通过，评分后端重算。
- Ra/Rk 不从 Word 导入来源、不进入 Word；XLSX 行为保持。
- 模板批注规则只 warning。
- 本地真实报告不进入 Git、构建上下文、测试输出或 PR 附件。
- 迁移后 DOCX/XLSX 回归和桌面安装态验收通过。
