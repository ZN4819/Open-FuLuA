## 1. 验收结论

R5 已完成技术实现、全量自动化检查、Microsoft Word 原生刷新验收、Windows 安装态验收和代码审查，并已创建 [PR #33](https://github.com/ZN4819/Open-FuLuA/pull/33)。阶段交付在 R4 完整报告装配基座上实现表 B-1～表 B-9 的结构化证据管理、人员与日期同源关联、安全图片存储、不可变投影以及 DOCX 装配。

附录 B 缺少材料、图片或题注仍按已确认口径产生 warning，不伪造完成状态；已经填写的数据若与中央人员、日期、组织或备案事实矛盾，或者已引用图片损坏、越权、丢失或哈希不一致，则产生 error 并阻止正式导出。

本阶段未使用 LibreOffice。完整报告结构、分页、字段刷新和兼容性只以 Microsoft Word 原生结果为准。

## 3. 关键实现

### 3.1 九表模型与中央事实关联

- full_report 项目幂等初始化九个固定类别，客户端不能新增、删除、改名或改变类别顺序。
- 记录、图片和用途关系均使用稳定 UUID、项目外键、类别约束和明确索引；跨项目引用统一拒绝。
- B-1 使用 R2 有效委托单位；B-2/B-3 复用项目组成员和现场阶段日期；B-5/B-6 复用方案评审、审核日期规则；B-7/B-8 复用中央人员和审批角色；B-9 复用系统名称及备案状态。
- B-3 现场记录变更通过同源服务更新 R2 现场阶段日期，不新增平行日期字段。
- 类别不适用、记录顺序、人员用途和差旅覆盖现场均为结构化关系，不依赖自由文本推断。

### 3.2 安全图片与文件一致性

- 上传同时校验扩展名、MIME、文件签名、Pillow 实际解码、尺寸和像素总量；在完整解码前先检查像素上限，防止超大图片占用资源。
- 单文件限制 20 MiB、4000 万像素和单边 20000 像素；保存 SHA-256、宽高、DPI、显示尺寸、题注和 alt 文本。
- 项目证据根目录和每个文件路径都拒绝 `..`、符号链接、目录联接及其他重解析点，防止越出 data root。
- 图片替换、删除采用临时 tombstone 和数据库事务补偿：数据库失败恢复旧文件，成功后再清理 tombstone；启动、读取、校验和导出前可恢复崩溃中断状态。
- 删除项目时验证解析后的项目目录仍位于受控证据根目录，再同步清理 R5 文件；不会依据客户端输入递归删除。

### 3.3 API 与九表工作台

- 提供九表读取、类别更新、记录增删改、图片上传/替换/读取、重排、校验和影响预览 API。
- 所有写请求同时校验项目 revision；记录更新额外校验记录 revision，冲突返回结构化 409。
- 前端提供 9 张固定卡片、记录和关系编辑、人员选择、图片预览/替换/删除、warning/error 导航、日期影响预览和未保存离开保护。
- 类别专用字段只在适用类别显示，后端也拒绝把无关字段存入其他类别，避免“保存成功但投影忽略”的隐形数据。

### 3.4 R4 投影与导出一致性

- R4 只消费 R5 不可变投影，不直接查询 R5 表，也不在装配阶段重新判断人员、日期或覆盖关系。
- 每次 R5 业务或图片变更都推进全局项目 revision，并使旧 R3 投影上下文失效；重新确认后才能正式导出。
- Word 刷新完成后、发布文件前再次校验项目 revision、R2/R3 上下文和 R5 `projection_hash`，避免刷新期间并发修改产生混合版本报告。
- 附录 B 图片使用 R4 统一媒体关系、题注和书签分配器写入同一个 OOXML 包；不另建 DOCX 拼接流程，也不从 Word 回收图片。

## 4. 代码审查修正

最终审查修复了以下根因级问题：

1. 初版 R5 修改只推进记录 revision，没有推进报告全局 revision，旧 R3 结果可能与新附录 B 一起导出。现所有 R5 变更推进项目 revision、失效旧 R3 上下文，并在 Word 刷新后再次校验全部上下文。
2. 初版图片替换和删除的文件操作先于数据库提交，提交失败可能使数据库仍引用已删除文件。现使用 tombstone 暂存、提交后清理、失败恢复，并在后续请求前自动协调中断状态。
3. 初版只检查最终文件路径，父级 `report_evidence` 若为目录联接仍可能把项目目录创建到 data root 外。现先验证父级根目录及全部已有路径段，再创建项目目录。
4. 初版在完整解码后才检查像素上限，不能尽早阻止解压炸弹。现先读取图片头并检查尺寸、像素和边长，再执行完整加载验证。
5. 初版项目删除仅级联数据库行，可能遗留证据目录。现将 R5 目录纳入项目删除服务，并验证解析路径不越界。
6. 初版判别式 schema 接受少量类别无关字段但投影不使用，可能形成不可见数据。现前后端同时限制类别字段集合并补充拒绝测试。

复审未发现剩余 P1/P2 级阻断问题。安装包、桌面主程序和后端侧车尚未配置代码签名，这是既有发布链约束，不改变本阶段功能验收结论。

## 6. 阶段闸门与后续交接

R5 阶段闸门已具备通过条件：

- 九类枚举、关系、warning/error 边界与母版表 B-1～B-9 一致。

- R4 只消费同一 revision 下的 R2/R3/R5 投影；并发变化不会发布混合版本 DOCX。
- 全量自动化、Microsoft Word 原生回读、桌面打包、安装态迁移和恢复验收均通过。
