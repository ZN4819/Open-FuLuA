# R3：正文生成与一致性链路实施方案

> 状态：技术实施与本地验收已完成。交付证据见 [R3 实施验收记录](R3-实施验收记录.md)。

## 1. 阶段定位

R3 在 R2 已冻结的报告数据模型和《报告字段及参数关联矩阵》之上，实现 R0 已确认的计算、统计、风险、结论和正文派生规则。R3 交付的是可追溯、可复核、可失效的结构化派生上下文，不装配 DOCX；R4 只能消费 R3 已确认且未过期的输出，不得在 Word 渲染器中重新计算业务规则。

本阶段的判断标准不是“生成了文字”，而是以下链路是否只有一个事实源：

```text
附录A原始输入
  -> 原始对象/单元分值与结论
  -> 双向结果修正
  -> 最终对象/单元/指标分值与结论
  -> 41项统计、风险记录、综合得分和评估结论
  -> 测评情况简介、总体评价、安全问题及改进建议等正文块
  -> 过期传播、人工复核和R4稳定装配上下文
```

复杂度：极高。实施前置条件是 R2 的字段关联矩阵、数据路径和校验服务已通过 G2 追溯验收；任何未在 R0 总方案第 3.6 节确认的新增公式或文案关系，都必须先回到总方案确认，不能在 R3 代码中自行解释。

## 2. 输入、输出与边界

### 2.1 权威输入

- R0：`report-2023-2025.12.08` 模板身份、固定威胁目录、叙述模板和参数关联业务基线。
- R1：`full_report` 项目、工作流状态和不可变模板包绑定。
- R2：报告实体、中央对象库、章节块、对象与子系统关系、结果修正关系、《报告字段及参数关联矩阵》及统一校验服务。
- 现有后端权威评分服务：A-1～A-4 的 D/A/K/Ra/Rk 和技术评分，A-5～A-8 的符合情况和管理评分。
- 已保存数据库数据。未保存的前端状态、Word 文本和 XLSX 公式缓存都不是 R3 输入。

### 2.2 阶段输出

- 版本化《派生计算与文案生成规则矩阵》及哈希。
- 原始结果投影、修正差异投影和最终结果投影。
- `report_findings`、`report_risks`、`report_risk_threat_relations`、`report_block_revisions`。
- 八个层面和总体统计、综合得分、整体风险等级、高风险判断及评估结论。
- 系统简介、测评情况简介、总体评价、安全问题及改进建议、风险分析和第 7 章结论等结构化正文块。
- 面向 R4 的不可变 `R3ProjectionContext`、一致性校验结果、规则集版本和输入哈希。

### 2.3 非目标

- 不填充、修改或分页 DOCX，不处理页眉页脚、目录、SEQ/REF/PAGEREF；这些属于 R4。
- 不重建 R2 的单位、人员、日期、对象或表 2-3 等事实模型。
- 不修改附录 A 权威评分公式；Ra/Rk 可以参与评分服务计算，但不得进入正文块、风险快照或 R4 上下文。
- 不使用 AI、LLM、联网补全、概率生成、`eval` 或用户自定义可执行脚本。
- 不允许人工覆盖统计数量、修正公式、综合得分、高风险判断或评估结论。

## 3. 规则矩阵与版本契约

规则资产使用 `rule_set_id=report-derived-2023-2025.12.08-v1`，随应用只读发布并校验 schema 与 SHA-256。矩阵每条规则至少包含：

| 字段 | 含义 |
| --- | --- |
| `rule_id` | 稳定规则 ID，禁止以代码行号或显示顺序代替 |
| `source_contract_ids` | 对应 R0 第 3.6 节和 R2 字段关联矩阵条目 |
| `input_paths` | 允许读取的实体和字段白名单 |
| `output_paths` | 派生实体、字段或正文块 |
| `algorithm` | 有限表达式、排序、舍入及缺失处理 |
| `confirmation_policy` | 只读派生、人工补录或人工确认 |
| `stale_dependencies` | 哪些输入变化会使结果过期 |
| `failure_code` | 空值、非法值、关系冲突和规则不可用时的稳定错误码 |
| `golden_vectors` | 输入、原始结果、最终结果和预期文案摘要 |

规则加载遇到重复 ID、未知字段、schema 错误、哈希不匹配、循环依赖或越权输入时，整个规则集不可用，返回 `RULE_SET_UNAVAILABLE`；不得跳过错误规则继续生成。

## 4. 原始与最终结果模型

### 4.1 原始事实

- A-1～A-4 保存原始 D/A/K/Ra/Rk、原始对象分值、原始单元分值和原始结论。
- A-5～A-8 保存原始符合情况和后端重算的管理分值；符合、部分符合、不符合、不适用分别映射为 `1`、`0.5`、`0`、`/`。
- 管理指标多个对象取有效数值算术平均；全部不适用时为 `/`；存在未填写或非法值时不计算并阻断正式导出。
- 原始数据只由评分服务产生或重算，R3 不接受客户端提交的单元得分。

### 4.2 指标聚合规则

原始投影和最终投影都调用同一个聚合函数，输入是同一指标下所有对象结论：

1. 存在未填写或非法结论：返回 `incomplete`，阻断后续计算和正式导出。
2. 全部对象结论相同：指标结论等于该结论；因此全部不适用时为不适用，仅有不符合时为不符合。
3. 去除不适用后只剩符合：指标结论为符合。
4. 去除不适用后只剩不符合：指标结论为不符合。
5. 剩余结论中存在部分符合：指标结论为部分符合。
6. 剩余结论仅包含符合和不符合：指标结论为部分符合。

聚合顺序固定使用 41 项指标目录和稳定对象 UUID，不依赖数据库自增 ID 或 UI 排序。

### 4.3 双向结果修正

只允许下列两组同类指标修正，机密性和完整性分别计算，禁止交叉：

- A-2“通信数据完整性” ↔ A-4“重要数据传输完整性”。
- A-2“通信过程中重要数据的机密性” ↔ A-4“重要数据传输机密性”。

关系和算法固定为：

- 一条 A-2 网络通道可关联一个或多个 A-4 重要数据对象；每个 A-4 对象只能关联一条 A-2 通道。
- 全部计算只读取双方原始分值，禁止使用修正结果递归或级联。
- A-2 最终分值：`max(A2原始分值, 0.5 × 关联A4原始分值中的最小有效值)`。
- 每个 A-4 对象最终分值：`max(A4原始分值, 0.5 × 关联A2原始分值)`；只有低于阈值的对象发生修正。
- `/` 不参与最小值、阈值比较或修正，不能按 0 处理；关联对象全部为 `/` 时不修正。
- 关系缺失、跨指标关联、一个 A-4 对象关联多条通道、空值或非法分值均返回字段级错误并阻断正式导出。

修正后必须重新调用权威评分服务计算最终单元分值和最终指标结论，不能只修改展示值。A-5～A-8 的原始投影和最终投影完全相同。

### 4.4 三份投影

R3 同一生成运行必须产出：

- `original_projection`：修正前对象、单元、指标分值和结论，供第 4 章表 4-1～表 4-11。
- `correction_projection`：仅包含“最终分值大于原始分值”的对象及来源关系，供表 5-1；无实际修正时输出空集合并带 `render_empty_as_slash_row=true`。
- `final_projection`：修正后对象、单元、指标、41 项统计和综合得分，供表 5-2、报告附录 A、总体评价、风险、评估结论和 XLSX。

投影中为实际修正对象提供 `was_corrected=true`、原始/最终分值和四位小数展示值；Word 星号和 D/A/K 的显示处理由 R4 完成，R3 不把星号写入数值字段。

## 5. 统计、风险与评估结论

### 5.1 41 项统计

- 按最终指标结论统计八个安全层面及全报告的符合、部分符合、不符合、不适用数量。
- 全报告四类数量之和必须等于 41；各层数量之和必须与所属固定指标数量一致。
- 测评情况简介、总体评价、风险分析和评估结论页只能引用这一份统计快照，禁止各自重算或人工填写。
- 第 3.1.3 节只列出最终结论为不适用的指标；只有所有对象均不适用时指标才可进入，原因按稳定顺序去重合并。无不适用指标时提供一行全 `/` 的渲染指令。

### 5.2 问题和风险记录

- 最终指标结论为部分符合或不符合时，自动且只能生成一条 `report_finding`；符合和不适用不生成问题记录。
- 问题记录不可人工排除，因为风险总数必须等于部分符合指标数加不符合指标数；源指标恢复为符合/不适用时记录转为历史失效，不参与当前投影。
- 一个问题指标对应且只对应一条 `report_risk`。风险等级必须在高、中、低中选择一个；未选择或未确认时为 `needs_input`，不能按 0 项处理。
- 关联威胁可多选，只能引用第 2.6 节固定只读威胁目录中的编号；项目不能新增、删除或修改威胁目录，R4 始终输出完整目录。
- 问题描述按指标生成：多个不符合对象可以合并描述，每个部分符合对象必须逐项描述。
- 风险分析列只概括该指标的整体风险等级，不逐个对象分析风险等级；调整风险等级必须记录理由并重新确认。

风险不变量：

```text
风险总数 = 部分符合指标数 + 不符合指标数
高风险数 + 中风险数 + 低风险数 = 风险总数
```

任一风险缺少等级、关联关系非法或问题与最终指标不一致时，风险统计、高风险判断和评估结论不可用。正文未确认或已过期不影响后端重新计算统计结果，但必须阻止生成 `confirmed` 上下文和正式导出。

### 5.3 整体风险与固定文案

- 高风险数大于 0：输出“判定系统存在高风险”。
- 高风险数等于 0 且风险记录全部完成：输出“判定系统不存在高风险”。
- 整体风险等级取当前风险中的最高等级；无高风险但有中风险时为中风险，仅有低风险时为低风险，风险总数为 0 时为“未发现安全风险”。
- 测评情况简介、风险分析和评估结论使用同一整体风险结果，不允许分别填写。
- 风险总数为 0 时，第 7 章固定输出“系统密码应用未发现安全风险”。

### 5.4 综合得分与评估结论

综合得分只读取最终投影并由权威评分服务计算。R3 使用 `ROUND_HALF_UP` 保留两位小数，并以这一个显示值进行结论判定：

| 条件 | 评估结论 |
| --- | --- |
| 显示综合得分等于 `100.00` | 符合 |
| 显示综合得分大于等于 `60.00` 且小于 `100.00`，并且高风险数为 0 | 基本符合 |
| 其他情况 | 不符合 |

风险分析未完成、评分不完整、统计不守恒或规则无法匹配时不得生成结论，也不得沿用旧结论。评估结论不提供人工覆盖入口。

## 6. 正文生成和人工确认

### 6.1 正文块

R3 至少生成以下稳定块：

- `conclusion.system_summary`：以第 2 章完整系统描述为事实源生成简明系统简介。
- `conclusion.assessment_summary`：使用模板固定句式、有效委托单位、被测单位、测评日期、41 项统计和整体风险结果；取消斜体，首行缩进两个字符。
- `overall_evaluation.intro`、`overall_evaluation.layer.1..8`、`overall_evaluation.outro`：保留母版首段、末段和八层固定开头，层内只汇总附录 A 实际引用对象和最终结果数量。
- `security_issues.layer.*` 与 `recommendations.layer.*`：按“安全层面 → 问题指标”生成并使用相同指标编号。
- `risk_analysis.summary`、`risk_analysis.rows`：引用同一风险快照和完整威胁目录。
- `assessment_conclusion`：引用显示综合得分、整体风险和固定决策表。

最终有效内容不得包含 `XX`、填写说明、模板提示语或最外层占位花括号。

### 6.2 安全问题及改进建议

- 每个安全层面按固定八层顺序处理；没有问题指标的层面整体省略，其余层面连续编号。
- 层内问题按固定 41 项指标顺序编号；一个指标只有一个顶层编号。
- 多个不符合对象可合并为一项描述，每个部分符合对象必须分项写明。
- 改进建议与问题共用指标编号，并可按对象细分；系统生成确定性草稿，用户可修改后确认。
- 风险分析表与“安全问题及改进建议”必须引用同一个问题描述基线，防止两个章节各写一套事实。

### 6.3 基线、人工覆盖和有效内容

`report_block_revisions` 分层保存：

- `baseline_json`、`baseline_hash`：当前规则生成基线。
- `source_snapshot_json`、`source_hash`：最小输入快照，不保存无关敏感字段。
- `override_json`：仅保存允许人工修改的文案字段和说明。
- `generation_status=not_generated|current|stale|failed`。
- `confirmation_status=unconfirmed|confirmed|review_required`。
- `rule_set_id`、`rule_id`、生成时间、确认时间和项目 revision。

统计、分值、指标结论、风险数量、高风险判断和评估结论不在覆盖白名单内。系统不得静默覆盖人工文案；重新生成后若基线变化，人工版本必须进入 `review_required`，由用户选择重新生成、调整人工内容或明确保留后再次确认。

## 7. 过期传播契约

源快照使用键排序、Unicode NFC、ISO 日期、Decimal 固定位数和稳定 UUID 排序计算 SHA-256。变化只标记下游过期，不在后台自动重写正文。

| 上游变化 | 必须过期的下游 |
| --- | --- |
| 第 2 章系统描述 | 评估结论页“系统简介” |
| 附录 A 原始输入、对象、结果记录、评分或修正关系 | 原始/修正/最终投影、总体评价、风险分析、安全问题及建议、综合得分和评估结论 |
| 风险等级、威胁关联或风险确认状态 | 风险统计、整体风险、高风险判断、测评情况简介和第 7 章结论 |
| 人工补充标准或特殊指标 | 特殊指标正文及其引用块；不改变固定 41 项统计和风险数 |
| 有效委托单位、被测单位、日期等 R2 字段 | 所有引用对应字段的正文块 |

过期块或 `review_required` 块可以在草稿中显示明显状态，但阻断 `ready_for_review`、`confirmed` 和 R4 `final` 上下文。历史导出快照不可被重新标记或覆盖。

## 8. 数据模型、约束与迁移

### 8.1 `report_findings`

- 字段：`finding_uuid`、`project_id`、`indicator_code`、`layer_code`、`final_indicator_result`、`source_hash`、`active`、`created_at`、`updated_at`。
- 约束：`UNIQUE(project_id, indicator_code, active)` 对当前活动记录只允许一条；结果仅允许部分符合或不符合；项目外键级联删除。
- 索引：`(project_id, layer_code, indicator_code)`、`(project_id, active)`。
- 删除语义：源结果变化时历史失效，不物理删除；删除项目时级联删除。

### 8.2 `report_risks`

- 字段：`risk_uuid`、`project_id`、`finding_uuid`、`risk_level`、`analysis_baseline`、`analysis_override`、`override_reason`、`confirmation_status`、`source_hash`、时间戳。
- 约束：活动 finding 一对一；`risk_level` 仅为 `high|medium|low` 或未填写；跨项目外键拒绝；人工改级必须有理由。
- 索引：`UNIQUE(finding_uuid)`、`(project_id, risk_level)`、`(project_id, confirmation_status)`。
- 删除语义：finding 失效时风险保留审计但不进入当前投影。

### 8.3 `report_risk_threat_relations`

- 字段：`risk_uuid`、`threat_catalog_id`、`sort_order`。
- 约束：复合唯一键，威胁必须来自当前模板包固定目录；风险删除时级联删除，威胁目录不可由项目删除。

### 8.4 `report_block_revisions`

- 字段：块 UUID、revision、baseline/override/source 快照及哈希、规则集、状态、确认信息。
- 约束：`UNIQUE(block_uuid, revision)`；有效 revision 唯一；JSON 必须通过块类型 schema，不能以无约束 JSON 代替 finding/risk 核心关系。
- 索引：`(project_id, generation_status)`、`(project_id, confirmation_status)`、`(source_hash)`。

迁移顺序：备份数据库 → 新建表和索引 → 为既有 full_report 项目建立空派生状态 → 校验外键与行数 → 启用 R3 feature flag。迁移不从既有自由文本猜测风险、结论或基线。

## 9. 服务、API 与 UI 契约

### 9.1 服务/API

```text
POST /api/projects/{uuid}/report/generation/impact-preview
POST /api/projects/{uuid}/report/generation/runs
GET  /api/projects/{uuid}/report/generation/runs/{run_id}
GET  /api/projects/{uuid}/report/findings
GET  /api/projects/{uuid}/report/risks
PUT  /api/projects/{uuid}/report/risks/{risk_uuid}
PUT  /api/projects/{uuid}/report/blocks/{block_uuid}/override
POST /api/projects/{uuid}/report/blocks/{block_uuid}/confirmation
POST /api/projects/{uuid}/report/consistency-checks
GET  /api/projects/{uuid}/report/consistency-checks/latest
```

写请求必须携带 `expected_project_revision`。revision 冲突返回 409；规则集不可用返回 503；业务不完整返回结构化 `needs_input`，不伪造正文。一次生成在同一只读快照计算，在单写事务提交；系统异常时不提交部分新基线，业务缺失项可以整体记录为 failed/needs_input 供用户定位。

R4 通过内部稳定服务取得 `R3ProjectionContext`，至少含三份结果投影、41 项统计、风险快照、已确认正文、规则集/输入哈希和一致性结果；R4 不直接查询 R3 内部表。

### 9.2 UI

- 展示“未生成、最新、已过期、生成失败”和“未确认、已确认、需复核”。
- 重新生成前显示影响预览，列出将失效的正文和需要复核的人工覆盖。
- 提供基线、人工版本、来源事实和差异视图；统计与结论只读。
- 风险工作台按指标显示对象问题、威胁编号多选、整体风险等级和确认状态，不允许删除系统生成的问题指标。
- 存在过期、未完成风险、未确认正文或一致性错误时，提供可导航清单并禁止进入 confirmed。

## 10. 失败行为

- 评分未完成、非法值或指标聚合失败：停止最终投影，保留旧结果但标记 stale，不按旧值导出。
- 修正关系非法或源分值不可用：返回关系、指标、通道、对象和字段级原因，不进行部分修正。
- 风险数不守恒、风险等级未确认或威胁引用失效：整体风险、高风险判断和结论不可用。
- 规则资产或哈希失败：整个规则集不可用，不降级为硬编码或前端计算。
- 人工覆盖越权：拒绝写入并保留现有版本；不允许修改只读派生字段。
- 并发 revision 冲突：不覆盖他人结果，返回 409 和最新 revision。
- 任一运行失败均不得删除旧基线或历史导出快照。
