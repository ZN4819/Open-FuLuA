# 密评报告工具升级实施方案索引

## 1. 文档目的

本目录是“附录A编写工具”升级为“密评报告工具”的权威实施入口。升级工作按 R0 至 R8 九个阶段推进，每个阶段均有独立、可执行、可验收的开发实施方案。

本目录同时记录已完成阶段的交付基线和尚未实施阶段的开发路线；阶段状态以第 4 节和第 8 节为准，不得仅凭方案内容判断功能已经交付。现有附录A项目、DOCX 导入导出、Ra/Rk 权威评分、XLSX 打分表和 Windows 客户端能力，在相应阶段完成并通过回归前均保持现状。

## 2. 已确认的产品边界

- 首版只支持当前三级报告模板，规范版本为 `2023`，机构修订版本为 `2025-12-08`。
- 新建完整报告以工具内结构化数据为事实源，Word 是受控复核载体，不是第二套项目数据库。
- 旧项目继续保留附录A模式，并可通过“复制升级”生成新的完整报告草稿；源项目不被修改。
- 正文由确定性模板生成草稿，允许人工改写并追踪与生成基线的偏差；不使用 AI。
- 模板批注只转化为帮助或警告，不直接成为阻断导出的正式规则。
- 正式交付为完整报告 DOCX 和 XLSX 打分表；首版不内置 PDF 输出。
- 附录B首版只接收 PNG/JPEG 图片，不自动转换 PDF、DOCX 或 XLSX。
- 继续依赖 Windows 当前用户账户、目录权限和现有备份机制，不增加项目密码或数据库静态加密。
- 禁止使用 superpowers 插件或其工作流实施本路线。

## 3. 跨阶段统一契约

以下契约一经在 R0 固化，后续阶段不得自行改名或改变语义。确需变更时，必须先更新本索引及所有受影响阶段方案，再实施代码。

### 3.1 项目与流程枚举

| 契约 | 固定值 | 说明 |
| --- | --- | --- |
| `project_type` | `appendix_a`、`full_report` | 旧项目迁移后统一为 `appendix_a`。 |
| `workflow_status` | `draft`、`ready_for_review`、`confirmed` | 单人状态闸门，不引入账户或角色审批。 |
| `template_edition` | `2023` | 规范版。 |
| `template_revision` | `2025-12-08` | 当前机构修订版。 |
| 报告导出模式 | `draft`、`final` | 草稿可不完整但必须带可见标识；最终版受系统不变量约束。 |
| 报告导入类型 | `migration`、`roundtrip` | 既有报告一次性迁移与同源 Word 回收使用不同流程。 |

完整报告新增 API 统一使用稳定项目 UUID 作为路径标识；现有附录A兼容接口继续保留数值 ID，不在同一阶段强制改造。

### 3.2 R0 运行时母版交接契约

R0 当前交付的唯一完整报告运行时母版包为：

```text
package_id        = report-2023-2025.12.08
asset_path        = templates/report/2023-2025.12.08/
template_edition  = 2023
template_revision = 2025-12-08
```

以运行时 `manifest.json` 和 `field_dictionary.json` 为机器权威，当前结构基线为：

- 17 个分节、55 张表；其中 33 张保持固定结构，22 张允许按 manifest 规则动态扩行。
- 26 个业务字段、29 个语义标量槽位；同一业务字段可以投影到多个正文、封面、声明或基本信息表槽位。
- 583 个原模板内容控件，运行时 OOXML 共 612 个内容控件。
- 六项受信运行时资产：母版 DOCX、字段字典、manifest、批注提示、叙述模板和资产哈希清单；任一摘要不匹配时禁用完整报告模板能力。
- 正文页码采用 `PAGE` 与指向 `report_body_end` 的 `PAGEREF` 组合，不使用 `NUMPAGES`；目录、页码和交叉引用必须由 Microsoft Word 原生刷新。
- 母版、字段字典、manifest、页眉页脚关系和固定正文属于 R0 权威资产；后续阶段只能修改 manifest 明确允许的槽位、块锚点和动态行区域。

当前包已在 R0 最终冻结。后续若修改母版字节、字段字典、manifest 或任何受信资产，必须建立新的 `package_id` 和资产哈希，禁止原位覆盖已绑定项目使用的包。

母版结构、主要可见内容和业务契约已完成本轮校正并最终冻结；121 条模板批注已脱敏为待裁决提示，但仍未完成业务规则审批。母版可见内容确认和批注规则审批是两个独立状态，不得相互替代。

### 3.3 评分和 Word 边界

- A-1 至 A-4 的 D/A/K/Ra/Rk、对象评分和单元得分继续由后端权威计算。
- A-5 至 A-8 的符合情况和管理单元得分继续由后端权威计算。
- Ra、Rk 只保存于数据库并进入 XLSX 打分表，不进入任何 Word 导入或导出结构。
- 附录A继续保持技术表 8 列、管理表 5 列，不因完整报告升级改变列结构。
- XLSX 导出继续以已保存数据库数据为准，评分未完成时阻断导出。

### 3.4 Word 回收边界

- 日常回收只接受本项目导出的、带有效项目 UUID、导出快照和模板版本的草稿 DOCX。
- 只回收稳定标识的固定字段、受控正文和已有表格行字段。
- Word 中新增、删除、复制或重排业务行不自动应用到项目。
- Word 中新增、替换或删除图片不回收；图片只在工具证据模块管理。
- 检测到未接受修订时阻止回收；Word 批注不写入项目。
- 同一字段在数据库和 Word 中均发生变化时，必须执行基线、数据库、Word 三方比较并逐项解决冲突。
- 不支持的 Word 结构必须形成明确问题，禁止静默丢弃或自动猜测。

R0 运行时母版和最终版继续禁止任意 `customXml`。R7 如需在受控 roundtrip 草稿中保存签名 manifest，必须建立单独的输出校验档位，只允许一个由本工具生成、符合固定 schema、签名可验证且能与服务端快照匹配的受控部件；不得放宽为接受任意自定义 XML。

### 3.5 参数关联确认与阶段归属

模板中参数之间的关系分为四类，不允许统一拖到 DOCX 装配阶段再凭版面推断：

| 关联类型 | 权威确认阶段 | 典型示例 | 后续阶段责任 |
| --- | --- | --- | --- |
| 模板位置和重复槽位 | R0 已确认 | 报告编号投影到首页和批准母版页眉；系统名称投影到首页、页眉、基本信息表、评估结论页、第2章、相关正文和附录 | R2 建模，R4 只执行同源投影 |
| 字段间业务约束 | R0 已确认业务口径 | 四个测评阶段时间的先后关系；报告总份数与各接收方份数的关系 | R2 固化为 API、数据库和 UI 同源校验 |
| 计算和文案派生 | R0 已确认业务口径 | 附录A结果生成八个层面统计；问题生成改进建议；风险数量生成高风险判定 | R3 实现，R4 只消费派生结果 |
| Word 字段和分页关系 | R4 确认 | `PAGE + PAGEREF(report_body_end)`、目录页码、SEQ/REF/PAGEREF 刷新 | R7 不回收字段缓存或分页结果 |

R2 必须依据本节业务基线交付《报告字段及参数关联矩阵》，至少包含：关联 ID、权威字段 ID、数据实体及路径、目标槽位或块、关联类型、是否可编辑、约束表达式、缺失/冲突行为、负责阶段和确认状态。R2 负责把已确认口径转换为可执行契约，不得重新解释规则；确需偏离时必须先回到本索引重新确认。

R3 必须依据本节业务基线交付《派生计算与文案生成规则矩阵》，至少覆盖：八个层面及总体统计、测评情况简介、总体评价、安全问题及改进建议、风险数量和等级、是否存在高风险、评估结论及其阻断条件。规则必须有稳定 ID、输入字段、输出字段或块、确认要求和黄金测试向量。

同一业务字段投影到多个槽位时只允许存在一个权威值。R4 导出时统一填充，R7 回收时按字段 ID 比较；多个 Word 槽位值不一致时必须报告冲突，不得按位置任选一个值。

### 3.6 R0 已确认参数关联基线

以下规则是本轮 R0 母版校正后已经确认的业务基线。R2、R3 和 R4 必须逐条建立稳定规则 ID、数据路径、测试向量和导出映射，不得把规则分散为前端临时判断、自由文本约定或 DOCX 位置推断。

#### 3.6.1 报告身份、单位和版本

- `system_name` 是项目级唯一数据源，自动投影到首页、批准母版页眉、基本信息表、评估结论页、第2章、相关正文及附录；各位置不得独立修改。
- `report_number` 是项目级唯一数据源，按批准母版投影到首页和报告编号页眉。预览时允许为空，正式导出时必填且在全部项目中唯一；重复编号阻断正式导出但不阻断预览。
- 被测单位必填；委托单位选填。有效委托单位按“已填委托单位优先，否则回退为被测单位”计算。
- 首页始终显示被测单位；仅存在独立委托单位时，才在被测单位下增加委托单位一行。
- 正文“受 XX 委托”和报告分发范围中的委托单位使用有效委托单位；“对 XX 的 XX 系统”中的单位使用被测单位。
- 报告不存在可编辑的系统运营单位字段；内部确需该语义时固定回退为被测单位。
- 密评机构名称、地址、邮政编码和联系人等信息属于模板包常量，项目不可修改或导入覆盖；更换机构必须建立新的模板包。
- 原模板和报告正文不显示报告版本。导出版本是独立管理元数据，默认 `V1.0`、由用户手动调整且不自动递增。
- 正式导出文件名固定为“`报告编号-被测单位-系统名称商用密码应用安全性评估报告版本号.docx`”，不包含“客户复核版”等状态字样，也不设置报告状态参数。
- 允许重复导出同一版本；每次导出必须保存独立、不可变的数据快照和导出记录，历史快照不随项目后续修改而变化。

#### 3.6.2 日期、人员和报告分发

- 测评开始日期等于测评准备阶段开始日期；测评结束日期等于分析与报告编制阶段结束日期。
- 首页报告日期、声明页日期和编制日期均等于测评结束日期。
- 编制日期不得单独修改；审核日期和批准日期独立选填，正式导出时允许为空。填写时必须满足“编制日期不晚于审核日期，审核日期不晚于批准日期”。
- 附录 B.6 报告评审时间是审核日期的唯一来源；B.6 为空时审核日期为空。附录 B.5 方案评审时间独立填写，且必须早于现场测评开始日期。
- 编制人正式导出时必填，必须来自项目组、角色为组员、已通过密评人员考核，且不得为项目负责人；附录 B.4 自动显示“组员、密评报告编制人”。
- 审核人、批准人正式导出时允许为空；若附录 B.4 已填写相应人员，则自动回填基本信息表，角色分别显示“密评报告审核人”和“密评报告批准人”。
- 编制人、审核人、批准人不得由同一人员兼任；审核人或批准人存在时必须填写考核通过时间，同一审批角色出现多个人员时阻断导出。
- 项目组至少有两名已通过密评人员考核的成员。附录 B.2、B.3 的人员必须来自项目组。
- 一次现场测评时，现场阶段起止日期等于 B.3 进场和离场日期；多次现场测评时分别取最早进场和最晚离场。B.2 差旅日期可以覆盖更宽范围，但必须覆盖对应现场记录；本地项目无差旅时保留 B.2 结构并填写“/”。
- 附录 B.9 的备案系统名称在“备案系统与被测系统相同”时自动使用被测系统名称且只读；选择不同时必须人工填写备案系统名称和差异说明。未备案但 B.9 已存在数据时提示并要求确认，数据仍予保留。
- 报告总份数等于监管部门份数、有效委托单位份数和密评机构留存份数之和；各分项允许为 0，但总份数必须大于 0。

#### 3.6.3 基本信息、标准和密码产品

- 基本信息表按原母版完整输出所有选项文字和已填写数据。互斥选择只控制勾选状态，不隐藏、清空或丢弃未选分支的数据。
- 已选分支缺少必填数据时阻断正式导出；未选分支存在填写值时提示并要求二次确认，但不阻断且仍按原值导出。未填写字段保持空白，不生成占位符。
- 首版只支持三级报告模板。等保备案的 S、A、G 均支持人工填写，G 允许为空，备案等级不得由 S/A/G 自动推导；未定级备案时仍保留并导出已定级分支中已经填写的数据。
- 关键信息基础设施选择“已认定”时必须填写安全保护工作部门；选择“未认定”但已填写部门时提示并要求确认，仍保留导出。
- 等保测评状态分为已测评、正在测评和未测评：已测评必须填写机构、时间和结论，正在测评必须填写机构，未测评不增加必填项。
- 云平台依赖分为是、否。选择“是”时必须填写云平台名称和测评状态；云平台已测评时必须填写机构、时间和结论，正在测评时必须填写机构，未测评不增加必填项。
- 密码应用方案分为已通过密评、有方案但未通过密评、无方案。已通过密评时必须填写通过时间和自行评估/委托评估方式；委托评估时还必须填写测评机构。
- 系统运行状态选择“已投入运行”时必须填写投入运行年月且不得晚于报告日期；选择“未投入运行”时必须填写当前建设阶段。
- 服务范围为全国、跨省、省内、跨市、本地或其他单选；跨省、跨市必须填写正整数范围数量，选择“其他”必须填写说明。上述分支均遵守“未选分支有数据只提示、不删除”的全局规则。
- 密码产品总数量与表 2-3 为同一事实源：整数按实际数量统计，文字“若干”按 1 计入统计但 Word 保留原文，其他非整数、负数或小数阻断导出。
- 密码产品总数量必须同时等于表 2-3 归一化数量之和、独享与共享数量之和、已认证与未认证国产及国外产品数量之和；这些基本信息统计值只读派生。
- 表 2-3 每项产品在系统内部记录独享/共享和已认证/未认证国产/国外分类，但不改变母版列结构。“系统未使用密码产品”与非零产品数量并存时只警告并要求确认。
- 密码算法由人工勾选。正式导出时在最终版附录A结构化文字、表格和题注中进行别名及大小写归一化匹配，不执行图片 OCR；每个已勾选算法至少匹配一次，否则阻断导出。
- 附录A出现但未勾选的算法只产生警告，不阻断导出；“其他”算法必须按人工填写的完整名称精确匹配。
- 1.2.2 前五项标准固定，允许人工补充标准。每条特殊指标必须且只能关联一项人工补充标准；一项人工补充标准可以不关联特殊指标，也可以关联多条。固定前五项不得作为特殊指标来源，被引用的人工标准不得删除。
- 特殊指标不进入固定 41 项指标、评分、结果数量和风险数量；无特殊指标时输出“无”和“0项”。

#### 3.6.4 附录A、测评对象和章节投影

- 附录A结构化数据是测评对象和结果的唯一事实源；第2章不与附录A直接关联，第3章和第4章只消费附录A派生投影，不得反向覆盖附录A。
- A-1 至 A-8 共 41 个固定指标。A-1 至 A-4 保留 D/A/K/Ra/Rk 原始输入和后端权威评分；A-5 至 A-8 保留符合情况和后端权威管理评分。Ra、Rk 进入数据库和 XLSX，不进入 Word。
- A-5 至 A-8 的对象结论映射为符合 `1`、部分符合 `0.5`、不符合 `0`、不适用 `/`；同一指标多个对象取有效数值算术平均，全部不适用则单元得分为“/”，存在未填写或非法值时不计算。管理单元得分只读且由后端在保存时重算。
- 第3章 3.3 节中，A-1、A-2、A-3 分别生成表 3-4、表 3-5、表 3-6 的唯一测评对象；表 3-4 至表 3-7 的对象列只读，不允许独立编辑。
- 每个 A-4 对象必须且只能归属一个子系统；跨多个子系统的逻辑对象必须拆分为多条记录。表 3-7 只生成实际引用的 A-4 子系统去重集合，不直接列出 A-4 原始对象。
- A-4 子系统必须从表 2-7 唯一的应用名称中选择，因此表 3-7 对象集合必须是表 2-7 应用名称的子集；缺失、重名或无法匹配时阻断导出。
- 测评方式固定为访谈、文档审查、现场检查、配置检查和工具测试多选；测评方式及备注属于第3章独立数据。A-4 按去重后的子系统保存，引用暂时消失时不导出，但保留历史数据以便恢复。
- “总体评价”只汇总附录A实际引用的对象，不以第3章手工内容补充对象。
- 表 4-1 至表 4-11 从附录A结构化记录生成。表 4-4 的测评对象是 A-4 对象所属子系统，并按“子系统 + 指标”聚合对象结论。
- 表 4-5 只筛选 A-4 身份鉴别指标对象；表 4-6 筛选访问控制信息完整性、重要数据传输机密性、重要数据存储机密性、重要数据传输完整性、重要数据存储完整性五个指标对象；表 4-7 只筛选不可否认性指标对象。
- 表 4-6 不修改母版结构，访问控制信息完整性映射到现有“存储完整性”列。对象没有对应指标记录时输出“不适用”；同一对象不得同时作为访问控制信息完整性和重要数据存储完整性对象。

#### 3.6.5 指标结论、结果修正和最终投影

- 同一指标对应多个对象时，全部对象结论相同则指标结论相同；全部不适用则指标为不适用。去除不适用对象后，全部符合则为符合，存在部分符合则为部分符合，符合与不符合并存也为部分符合，不符合与不适用并存或仅有不符合则为不符合。存在未填写或非法值时阻断计算和正式导出。
- 第5章只允许两组同类指标双向修正：A-2 通信数据完整性与 A-4 重要数据传输完整性；A-2 通信过程中重要数据的机密性与 A-4 重要数据传输机密性。机密性和完整性分别计算，禁止交叉修正。
- 一条 A-2 网络通道可以关联一个或多个 A-4 重要数据对象，每个 A-4 对象只能关联一条 A-2 通道。修正只使用原始分值，禁止递归或级联。
- A-2 修正值为 `max(A2原始分值, 0.5 × 关联A4原始分值中的最小有效值)`；A-4 每个对象的修正值为 `max(A4原始分值, 0.5 × 关联A2原始分值)`，只修改低于阈值的对象。
- “/”不参与最小值和修正，也不得当作 0；关联对象全部为“/”时不发生修正，空值或非法值阻断导出。
- 表 5-1 只填写最终分值大于原始分值的对象；没有任何修正时仍输出标题、表头和一行内容全部为“/”的数据行。
- 第4章使用修正前投影；表 5-1 展示差异；表 5-2、报告附录A、总体评价、风险分析、综合得分、评估结论和 XLSX 使用修正后最终投影。A-5 至 A-8 的原始值等于最终值。
- 发生实际修正的技术测评对象在 Word 附录A中将 D、A、K 显示为“/”，对象评分显示为四位小数最终分值加星号，例如 `0.5000*`；单元得分显示最终数值且不加星号。数据库保留原始输入，XLSX 保留原始 D/A/K/Ra/Rk 和纯数值最终分值，不增加星号，也不在 Word 中补充星号说明。

#### 3.6.6 统计、风险、结论和正文生成

- 八个安全层面和全报告的符合、部分符合、不符合、不适用数量按最终指标结论统计，四类数量之和固定为 41；测评情况简介、总体评价和评估结论页必须消费同一统计结果。
- 风险总数量固定等于部分符合指标数量加不符合指标数量。一条问题指标对应且只对应一条风险记录，并只能选择高、中、低中的一个等级，因此高风险、中风险、低风险数量之和必须等于风险总数量。
- 风险分析表按指标生成。一个指标存在多个不符合对象时可以合并描述；每个部分符合对象必须逐项描述。风险分析列只汇总该指标的整体风险等级，不逐个分析对象风险等级。
- 关联威胁允许多选，来源是第 2.6 节固定、只读的完整母版威胁目录；每次导出始终输出完整目录，不允许项目级增删或修改。
- 高风险数量大于 0 时输出“判定系统存在高风险”，否则输出“判定系统不存在高风险”。存在未完成风险记录时不得生成该判断。
- 测评情况简介、风险分析和评估结论使用同一整体风险等级：存在高风险时描述高风险，无高风险但存在中风险时描述中风险，仅存在低风险时描述低风险，风险数量全部为 0 时描述未发现安全风险问题；不得分别填写。
- 综合得分使用修正后最终分值，先按 `ROUND_HALF_UP` 保留两位小数，再以该显示值判定结论：等于 100 为符合；大于等于 60 且小于 100 并且无高风险为基本符合；其他情况为不符合。风险分析未完成时阻断结论。
- 风险数量全部为 0 时，第7章固定输出“系统密码应用未发现安全风险”，评估结论为符合。
- 总体评价保留母版第一段和最后一段；中间八个层面由实际引用对象和最终结果生成草稿，保留每层开头说明和结果数量句。用户可以人工调整并确认，最终版不得保留 `XX`、提示语或外层占位花括号。
- 安全问题及改进建议按“安全层面 → 问题指标”生成。同一指标为一个顶层编号，多个不符合对象可以合并、每个部分符合对象逐项描述；建议与问题使用相同指标编号并允许按对象分项。没有问题指标的层面整体省略，其余层面按固定八层顺序连续编号。
- 第 3.1.3 节不适用指标按最终指标结论生成；只有全部对象均不适用时才列入，原因去重合并。无不适用指标时保留表头并以“/”填充数据单元格。
- 第2章完整系统描述是评估结论页“系统简介”的事实源；评估结论页先生成简明草稿，允许人工调整并确认。
- 上游数据变化时，下游内容必须标记为待重新确认：第2章变化使“系统简介”失效；附录A或结果修正变化使总体评价、风险分析、安全问题及改进建议、综合得分和评估结论失效；风险等级变化使风险统计、高风险判断和第7章结论失效。
- 系统不得静默覆盖人工编辑正文。用户可以明确重新生成，或在查看差异后保留人工版本并再次确认；未确认或已过期内容阻断正式导出，历史导出快照不受影响。

### 3.7 最终版导出闸门

以下系统不变量可以阻断 `final`：

- 运行时模板、分节、核心表格或稳定锚点不完整。
- 报告编号、报告日期、系统名称、被测单位、密评机构或编制人等核心身份字段缺失，或者报告编号不唯一。导出版本号属于导出管理元数据，不写入首页或正文。
- 附录A评分未完成、存在非法值或权威计算失败。
- 密码产品数量无法与表 2-3 对平，或者已勾选密码算法无法在最终附录A中匹配。
- 结果修正关系不完整、非法或最终投影无法确定。
- 风险数量、指标结果数量、综合得分或评估结论不满足第 3.6 节不变量。
- 图片、题注、书签或交叉引用断链。
- 已正式纳入字段关联矩阵或派生规则矩阵的规则尚未确认、输入不完整、结果过期或多个槽位值不一致。仍处于待审批状态的模板批注提示不属于该阻断范围。
- 一次性迁移仍存在未解决的必确认映射。
- 派生正文因底层数据变化而过期，且用户尚未重新生成或明确确认保留人工版本。
- Word 回收仍存在未解决冲突或来源校验失败。
- Microsoft Word 未完成全部 story ranges、目录、页眉页脚和正文域刷新，或 `PAGE/PAGEREF`、SEQ、REF 等 manifest 声明字段无法回读。

模板批注提取出的来源核对、编写建议和附录B材料完整性要求只产生 `warning` 或 `info`，不直接阻断最终版。

## 6. 工作包、分支和提交规则

- 每个阶段从最新 `main` 创建独立分支，建议命名为 `codex/report-rN-<scope>`。
- 一个阶段对应一个 Pull Request；一个可独立验证和回滚的工作包对应一个清晰提交。
- 数据库、模板、公共 API 或导入导出契约变化必须先落后端契约与测试，再接入前端。
- 每个工作包至少包含：输入、具体改动、失败行为、测试、验收、提交范围和回滚边界。
- 阶段完成后必须更新本表状态、数据库 schema 版本、模板哈希和 PR 链接。
- R2、R3 阶段完成时必须同时更新对应关联矩阵的版本、确认状态和测试向量；R4 不得在装配代码中新增未经矩阵登记的业务关联。
- 提交前必须检查暂存范围，不得使用 `git add -A` 将根目录真实报告、源模板、XLSX、`.codex/`、storage 或临时文件纳入提交。
- 每个阶段完成后运行阶段测试和 `scripts/run_checks.ps1`，形成清晰中文提交，推送至 `https://github.com/ZN4819/Open-FuLuA.git` 并创建 Pull Request。

## 7. 变更控制

发生下列任一情况时，必须先修改本索引和相关阶段方案，再继续实施：

- 增加新的报告等级或机构模板。
- 改变 Word 回收边界或允许 Word 增删业务行/图片。
- 将模板批注提示升级为阻断规则。
- 引入 AI、多用户权限、PDF 输出或新的证据文件格式。
