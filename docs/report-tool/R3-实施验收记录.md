## 3. 关键实现与失败行为

### 3.1 权威投影和结果修正

- A-1～A-4 重新调用现有后端 D/A/K/Ra/Rk 权威评分；A-5～A-8 由符合情况映射并重算管理分值，不信任历史缓存。
- 指标结论严格执行多对象聚合规则；全部不适用为不适用，符合与不适用为符合，仅不符合与不适用为不符合，其余混合规则按已确认口径确定。
- 只允许两组 A-2/A-4 双向修正。A-2 多来源取 A-4 原始分值最低值；A-4 只在低于 `0.5 × A-2 原始分值` 时提高；双方始终只引用原始分值，避免递归修正。
- 修正表只保留实际提高分值的对象；没有实际修正时携带 `render_empty_as_slash_row=true`。
- 最终公开投影保留 D/A/K 和修正来源，不含 Ra/Rk。

### 3.2 问题、风险、得分和结论

- 每个部分符合或不符合指标确定性生成一条活动问题和一条风险；指标恢复后旧记录转历史失效。
- 同一指标的多个不符合对象合并描述，每个部分符合对象分项描述；风险表与安全问题章节共用同一问题基线。
- 风险至少关联一个固定威胁编号，风险等级和分析经人工确认后才参与当前快照；始终输出完整 24 项威胁目录。
- 固定执行 `风险总数 = 部分符合指标数 + 不符合指标数 = 高 + 中 + 低`。
- 综合得分使用固定指标/层面权重和 `ROUND_HALF_UP` 两位显示值；结论只由显示得分和高风险数量决定。
- 高风险判断只输出“判定系统存在高风险”或“判定系统不存在高风险”。

### 3.3 正文、人工版本和一致性

- 生成评估结论页、总体评价、安全问题、改进建议、风险分析和第 7 章结论所需的 33 个结构化块。
- 测评情况简介取消斜体并设置首行两字符缩进；正文不含模板提示语、最外层占位花括号或模糊占位符。
- 统计、分值、指标结论、风险数量和评估结论只读；只允许系统简介、总体评价层面情况和改进建议进入人工覆盖白名单。
- 人工覆盖必须填写非空理由；基线变化后人工版本进入 `review_required`，不被静默覆盖。
- 上游变化只标记依赖块过期。系统简介、特殊指标和修正关系分别具有独立源哈希，不扩大到无关块。
- `ready_for_review` 现在同时受 R2 校验和当前 R3 一致性上下文约束。

### 3.4 审阅工作台

- 完整报告工作台新增“正文生成与一致性”稳定深链接。
- 页面提供影响预览、生成/重生成、风险等级和多威胁选择、人工风险分析、正文覆盖、保留/放弃人工版本、逐块确认和一致性校验。
- 页面不计算评分、修正、风险数量或结论；全部显示后端响应。
- 存在未保存编辑时阻止生成和一致性校验；上游事实变化后旧“已通过”状态立即显示为“已过期”。

## 4. 代码审查修正

独立审查发现并修复以下根因级问题：

1. 修正关系最初与附录 A 共用源哈希，R4 无法定位失效来源。现拆为独立 `correction_relations` 哈希，并为所有最终投影下游登记显式依赖。
2. 特殊指标数量最初被重复纳入通用报告事实，会使无关结论块过期。现只由 `special_indicators` 源组驱动总体评价对应块。
3. 初版上下文缺少生成运行 ID、分组源哈希和机器契约。现增加 v1 JSON Schema、运行时语义校验、哈希核对和 R4 接口测试夹具。
4. 规则资产缺失时原始异常详情可能带出本地路径。现公开错误只保留稳定 reason 及允许的逻辑字段。
5. 人工正文覆盖理由仅依赖前端非空判断，空白字符可绕过。现由后端裁剪并强制非空。
6. 前端曾在上游已变化时继续显示旧一致性结果“已通过”。现结合影响预览立即显示“已过期”。
7. schema 升至 6 后，桌面端仍声明 5，且空桌面数据库的迁移白名单不识别 R3 派生表。现统一桌面 schema 契约、安装验收脚本和迁移白名单，并对 schema 6 派生结构执行完整审计。
8. 同一指标问题消失后再次以完全相同的事实恢复时，确定性 UUID 会命中已停用历史问题，初版会尝试重复插入。现改为按 UUID 重激活原问题和风险链路，并用“出现→消失→恢复”回归向量验证历史记录不重复。

修正后重新执行专项与全量检查，未发现剩余的 P1/P2 级阻断问题。
