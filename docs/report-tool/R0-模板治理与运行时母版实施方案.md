# R0 模板治理与运行时母版实施方案

> 状态：技术实施完成，121 条批注业务审批待处理。R0 不把待审批规则投入运行。

## 1. 阶段定位

R0 是“附录 A 编写工具”升级为“完整报告生成工具”的基础阶段。本阶段不生成完整报告，而是把外部 Word 模板中的版式、字段、批注规则和示例内容转换为可版本化、可校验、可打包的运行时资产。

后续 R4 完整报告装配和 R7 受控 Word 回收必须依赖本阶段产出的稳定字段标识、块锚点、模板清单和哈希。未经 R0 验收，不得直接使用原始模板按段落序号、表格序号、可见文字或内容控件序号进行生产填充。

### 1.1 复杂度

- 复杂度：高。
- 主要难点：Word OOXML 结构取证、批注规则裁决、动态表识别、内容控件标记、表格网格规范化、模板脱敏、模板兼容性治理。
- 风险等级：高。错误的模板治理会使后续所有导出结果具有不可追溯的格式和数据风险。

### 1.2 前置依赖

- 当前仓库中的附录 A 数据模型、DOCX 导入/导出、图片、交叉引用和评分能力保持可用。
- 原始基础模板和客户复核版仅作为只读分析输入。
- 需要能够读取 ZIP/OOXML、`python-docx` 和 `lxml`。
- 正式运行时模板的业务字段和规则需要由报告负责人审核确认。

## 2. 统一业务契约

本阶段必须建立并固化以下枚举，后续阶段不得另造同义值：

```text
project_type    = appendix_a | full_report
workflow_status = draft | ready_for_review | confirmed
template_edition = 2023
template_revision = 2025-12-08
export_mode     = draft | final
import_mode     = migration | roundtrip
```

约束：

- `appendix_a` 项目继续使用现有 A-1～A-8 工作流。
- `full_report` 项目才允许绑定完整报告运行时模板。
- 新建项目默认 `workflow_status=draft`。
- `ready_for_review` 表示自动校验已通过，但不能替代专业复核。
- `confirmed` 必须由用户明确确认，不得由后端自动升级。
- `draft` 导出必须带显式草稿标识；`final` 导出必须通过阶段验收闸门。
- `Ra`、`Rk` 只在系统内部和 XLSX 中使用，禁止进入任何 Word 字段、表格、批注或回收数据。
- 从模板批注提取的规则在第一版一律只产生 `warning`，不能单独阻止保存、确认或导出。

## 3. 经仓库与样本文档验证的当前基线

### 3.1 代码基线

- SQLite schema 当前版本为 `3`。
- `projects` 当前只有名称和时间字段，没有 `project_type`、`workflow_status` 或模板绑定。
- 项目创建后固定初始化 A-1～A-8 八个 `appendix_sections`。
- DOCX 导出接口为 `POST /api/projects/{project_id}/exports/docx`，当前参数为 `editable|final`，只生成附录 A。
- DOCX 导入接口为 `/api/imports/docx`，当前仅识别附录 A 核心表、图片和引用。
- 当前 DOCX 生成器从空白 `Document()` 重建 8 个横向分节和 8 张附录表。
- 当前已持久化 D/A/K/Ra/Rk、对象分、单元分和管理符合情况；后端负责权威重算。
- 当前 Word 结构仍是 8 列技术表和 5 列管理表，Ra/Rk 不进入 Word。
- 已有证据图片、题注、书签、SEQ/REF、异步预览和结构校验基础设施。

### 3.2 基础模板基线

只读基础模板：

```text
02-商用密码应用安全性评估报告模板(2023版)—系统密评报告--三级-20251208修改.docx
```

结构取证结果：

- 442 个正文段落。
- 55 张表格。
- 17 个分节，其中前 8 个为纵向主体，后 9 个为横向附录区域。
- 8 个页眉部件、7 个页脚部件。
- 583 个内容控件：423 个下拉、159 个隐式富文本、1 个目录控件。
- 240 组技术下拉为 `√/×//`，182 组管理下拉为“符合/部分符合/不符合/不适用”。
- 所有业务内容控件均缺少稳定 `tag`、`alias` 和 `dataBinding`。
- 556 个书签、296 个 `instrText` 片段。
- 121 条批注。
- A-7 对应表存在不规则合并网格，不能未经修复直接作为运行时表格。

### 3.3 客户复核版对照基线

- 客户版同样有 55 张表，但只有 16 个分节。
- 客户版附录 A 标题样式已退化，A-7 与 A-8 的分节结构与基础模板不一致。
- 客户版通过扩行形成实际数据规模，例如 A-2 从基础模板的 12 行扩展为 167 行。
- 客户版仍有残留批注和真实客户敏感信息。

结论：基础模板是规范来源，客户版是填写示例和迁移样本；两者都不得直接成为公共运行时模板。

## 4. 目标与非目标

### 4.1 目标

1. 对 121 条批注做到 121/121 可追溯分类，不静默丢弃。
2. 形成完整报告字段字典，明确字段类型、来源、敏感级别、导出位置和校验关系。
3. 形成只读规则提示库，第一版所有批注规则只产生警告。
4. 将编写示例从运行时正文中移出，形成叙述模板知识库。
5. 制作脱敏、无批注、无客户示例、带稳定标签和块锚点的运行时模板。
6. 建立 55 张表、17 个分节、页眉页脚、样式和关键域的 manifest。
7. 对运行时模板、字段字典、manifest、规则提示和叙述模板计算哈希并形成资产包版本。
8. 让桌面打包环境可以定位并验证完整报告模板资产。

### 4.2 非目标

- 不在 R0 生成完整报告。
- 不修改、覆盖、移动或重命名原始模板与客户复核版。
- 不把原始模板、客户数据、批注意见或未经业务确认的个人联系方式直接提交到仓库；经业务确认的密评机构资料除外，其中机构名称可在报告内重复使用，联系人资料只固化在基本信息表。
- 不在本阶段实现 R7 Word 回收。
- 不把批注中的机构内部写法未经审核升级为强制规则。
- 不改变现有附录 A Word 表结构，也不把 Ra/Rk 加入 Word。

## 5. 目标资产架构

建议目录：

```text
templates/report/
  2023-2025.12.08/
    runtime_template.docx
    field_dictionary.json
    manifest.json
    rule_hints.json
    narrative_templates.json
    asset_hashes.json
    README.md
backend/app/services/report_templates/
  analyzer.py
  registry.py
  validator.py
  models.py
tests/fixtures/report_templates/
  sanitized_minimal_report.docx
```

`runtime_template.docx` 是唯一运行时 Word 母版。其他 JSON 是其不可拆分的伴随资产；任意一个哈希不匹配都必须拒绝生成。

### 5.1 字段字典契约

每个字段至少包含：

```json
{
  "field_id": "report.system.name",
  "label": "被测系统名称",
  "data_type": "string",
  "data_domain": "system_profile",
  "cardinality": "one",
  "required_when": {"operator": "equals", "field_id": "project.project_type", "value": "full_report"},
  "source_kind": ["manual", "imported"],
  "source_evidence": ["level_protection_filing"],
  "format": {"min_length": 1, "max_length": 200},
  "sensitivity": "internal",
  "review_required": true,
  "export_slots": ["sdt:report.system.name"],
  "template_edition": "2023",
  "template_revision": "2025-12-08"
}
```

字段 ID 必须稳定，显示名称允许调整。禁止使用段落序号、表序号或“第几个内容控件”作为字段 ID。

字段类型至少覆盖：

- 标量字符串、长文本、日期、日期区间、布尔值、枚举、整数、小数。
- 单值附件、多值附件。
- 重复对象列表。
- 派生值和人工确认值。
- 条件显示块。

### 5.2 Manifest 契约

`manifest.json` 至少包含：

- 资产包 ID、模板 edition、revision、数据 schema 最低/最高兼容版本。
- 运行时模板 SHA-256。
- 17 个分节的顺序、方向、纸张、边距、起始类型和页眉页脚引用。
- 55 张表的稳定 `table_id`、表头签名、固定列数、动态行策略和所属块。
- 所有块级锚点的起止标签。
- 所有标量 SDT 标签及期望数量。
- TOC、PAGE、NUMPAGES、SEQ、REF、PAGEREF、STYLEREF 等关键域期望。
- 必须存在的样式、编号、书签命名规则、关系类型和内容类型。
- 禁止存在的批注、修订、外链、宏、OLE、客户示例和未替换占位符。

### 5.3 批注分类与规则提示契约

121 条批注必须归入以下之一：

| 类型 | 用途 | 第一版行为 |
|---|---|---|
| `field_source` | 字段来源或证明依据 | warning |
| `consistency` | 跨章节、跨表、跨附件一致性 | warning |
| `conditional` | 条件显示、条件必填 | warning |
| `authoring_help` | 编写方法、对象选择建议 | UI 帮助 |
| `evidence` | 证据类型、图片或附件要求 | warning/UI 清单 |
| `layout` | 图片大小、横竖版、题注要求 | 待审批 warning；批准进入 manifest 后才可成为生成器配置 |
| `history` | “新增”“修改”等模板修订记录 | 仅归档，不运行 |

运行时记录只保留原始批注 ID、批准源指纹、锚点哈希、脱敏摘要、分类、人工裁决状态和目标字段，不保存作者、时间或批注原文。确需保存作者、时间和原文的裁决审计件只能位于不提交、不打包的受控私有目录。`approval_status` 只能为 `pending|approved|rejected|deprecated`。

运行时规则引擎只执行 `approved` 规则；即使执行，R0/R4 第一版也只能返回 `warning`。

### 5.4 叙述模板契约

`narrative_templates.json` 存放从模板示例中提炼出的可选写作帮助，例如层面总结、问题描述、建议、附录 A 测评验证记录。

要求：

- 示例与项目数据完全分离。
- 每条模板带适用章节、适用结论、占位变量和来源版本。
- 套用后生成草稿文本，用户必须确认。
- 示例中的 `XX`、具体机构、人员、产品、证书和图号不得作为默认值写入报告。
- Ra/Rk 计算说明不得进入 Word 叙述模板。

### 5.5 哈希与信任边界

`asset_hashes.json` 对以下文件计算 SHA-256：

- `runtime_template.docx`
- `field_dictionary.json`
- `manifest.json`
- `rule_hints.json`
- `narrative_templates.json`

应用启动或首次导出时验证哈希。`asset_hashes.json` 的 SHA-256 固定在代码侧注册表中，运行时读取同一批字节完成校验和使用，避免校验后重新打开造成竞态。哈希失败、缺文件或版本不兼容时返回明确错误，不允许退回“按可见文本猜测填充”。该机制保证资产与已审查代码的一致性；未签名安装包的真实性仍依赖后续代码签名闭环。

## 6. 资源 Registry、只读 API 与诊断契约

### 6.1 文件型 Registry

R0 不修改 SQLite，不增加项目字段、项目模板绑定或旧项目迁移。模板 registry 从随应用打包的只读资源目录加载，建议内存模型为：

```text
ReportTemplatePackage
  package_id
  template_edition
  template_revision
  runtime_template_path
  manifest_path
  field_dictionary_path
  rule_hints_path
  narrative_templates_path
  asset_hashes_path
  validation_status
```

registry 只描述“应用当前可用的模板资产”，不表达“某个项目绑定哪个模板”。项目类型、工作流状态、模板绑定及其数据库迁移统一在 R1 实施。

### 6.2 只读 API

可新增：

```text
GET  /api/report-templates
GET  /api/report-templates/{package_id}
GET  /api/report-templates/{package_id}/fields
GET  /api/report-templates/{package_id}/rule-hints
POST /api/report-templates/{package_id}/validate
```

失败行为：

- 模板缺失、哈希不匹配或版本不兼容返回结构化 503，只包含稳定错误码和逻辑资产名，不返回路径、源文件名或正文片段。
- 未知 package ID 返回 404。
- API 仅允许读取和校验随应用提供的包，不接受上传模板、本地绝对路径或运行时写入 registry。

### 6.3 诊断界面边界

- R0 不修改新建项目、项目页或模板绑定 UI。
- 如现有运行时健康信息需要展示模板状态，只返回 package ID、edition、revision 和通过/失败状态。
- 不向用户展示模板绝对路径、原始批注作者或示例正文。
- 完整项目类型选择、模板绑定和工作流 UI 统一留给 R1。

## 7. 可提交工作包

### 7.0 安全前置闸门

- 源 DOCX 必须先校验批准 SHA-256，再通过纯 ZIP/OPC 静态分析；清理前禁止交给 Word 自动化或 python-docx。
- ZIP 按流读取，拒绝绝对路径、盘符、UNC、反斜杠、`..`、NUL、规范化重名、Windows 大小写碰撞、加密条目、符号链接、异常压缩比以及超出条目数、单部件和总解压量预算的输入。
- XML 禁止 DTD、ENTITY、外部实体和网络访问，并限制 XML 字节数、节点数及嵌套深度。
- 运行时母版按允许的 OPC 部件重建，移除宏、ActiveX、OLE/embedding、customXml、数字签名、attachedTemplate、altChunk、外部关系、批注关联部件和个人元数据。
- 如源模板出现未裁决修订，构建直接失败；不得以简单删除修订节点代替人工接受或拒绝。
- JSON 使用 `extra=forbid` 的固定模型、操作符白名单和严格 ID；禁止自由字符串表达式、重复键、NaN/Infinity、未知键及重复 ID。

### WP-R0-1：模板取证器与基线快照

**输入**

- 只读基础模板。
- 只读客户复核版。

**具体改动**

- 新增 OOXML 模板分析器。
- 统计分节、表格、控件、批注、域、书签、关系、图片和修订。
- 生成机器可读取证 JSON，不复制原始正文和敏感值。
- 固化 55 表、17 分节、121 批注基线断言。

**失败行为**

- DOCX 非法、加密、缺少主文档部件时立即失败。
- 统计与已批准基线不一致时返回 diff，不自动更新基线。

**测试**

- 合法模板分析测试。
- 缺部件、重复关系、非法 ZIP 测试。
- 客户版差异识别测试。

**验收**

- 基础模板输出精确为 55 表、17 分节、121 批注。
- 不修改源文件时间、哈希和内容。

**建议提交**

`R0-1: 增加完整报告模板取证器`

### WP-R0-2：批注裁决、字段字典与规则提示

**输入**

- WP-R0-1 取证结果。
- 业务负责人对批注的人工分类和批准结果。

**具体改动**

- 建立字段字典 schema 和校验器。
- 将 121 条批注全部映射为 7 类规则之一。
- 建立 rule hints schema，支持来源、条件和审批状态。
- 建立叙述模板 schema，迁移可复用示例。

**失败行为**

- 批注数量未达到 121/121 时构建失败。
- 一个批注映射到互斥规则且未人工裁决时失败。
- 未批准规则不得进入运行时执行集。

**测试**

- JSON schema 测试。
- 批注覆盖率测试。
- 规则只产生 warning 的合同测试。
- 叙述模板不含客户信息和 Ra/Rk 测试。

**验收**

- 121 条批注均可追溯。
- 字段 ID 唯一且不依赖文档顺序。

**建议提交**

`R0-2: 建立字段字典和模板规则提示库`

### WP-R0-3：运行时模板提纯

**输入**

- 原始基础模板的只读副本。
- 已批准字段字典和 manifest 草案。

**具体改动**

- 在隔离临时目录生成脱敏副本。
- 清除 121 条批注、个人元数据、修订记录、外链和客户示例。
- 清除 `XX`、大括号示例、“选择一项。”和预填示例分数。
- 为标量字段添加稳定 SDT tag/alias。
- 为动态块添加唯一开始/结束锚点。
- 修复 A-7 表格网格，确保 `tblGrid`、`gridSpan`、`vMerge` 一致。
- 保留 17 分节、55 表骨架、样式、页眉页脚和必要域。

**失败行为**

- 清理后仍有批注、修订、外链、宏、OLE 或禁用占位符时失败。
- 锚点重复、缺失或交叉嵌套时失败。
- 表格网格审计失败时不生成运行时模板。

**测试**

- OOXML 清洁度测试。
- 17 分节/55 表结构测试。
- 标签唯一性测试。
- 表格网格和 python-docx 重开测试。
- 原始模板哈希不变测试。

**验收**

- 运行时模板 Word 打开无修复提示。
- 不含真实客户数据、批注和未替换示例。

**建议提交**

`R0-3: 制作脱敏完整报告运行时母版`

`R0-4: 完成报告模板注册和资产完整性校验`

## 8. 迁移与回滚

### 8.1 数据边界

- R0 没有数据库 schema 迁移。
- 不更新 `projects`，不创建模板绑定表，不改变既有项目状态。
- 如实现只读模板查询 API，registry 每次从受信资源加载或从进程内不可变缓存读取。

### 8.2 模板迁移

- 模板包不可原位覆盖；新 revision 必须创建新 package ID。
- 项目绑定后默认固定模板 package，不随应用升级自动切换。
- 模板升级通过显式迁移预览和确认完成。

### 8.3 回滚

- 数据库回滚使用升级前备份，不依赖逆向 SQL 猜测。
- 模板包回滚只切换启用状态，不删除旧资产。
- 若新模板包校验失败，完整报告功能禁用，但附录 A 项目继续可用。

## 9. 风险与安全

- 原始模板和客户报告含个人信息、联系方式和机构内部批注，禁止提交仓库或写入日志。
- 临时提纯目录必须位于应用数据目录或安全临时目录，成功或失败后均清理。
- 禁止执行 DOCX 中的宏、OLE、外部链接或嵌入脚本。
- 对 ZIP 解压实施文件数量、单文件大小、总大小和路径穿越限制。
- 规则提示只能提供辅助，不替代密评专业判断。
- 模板哈希只证明资产未变化，不证明业务内容正确；仍需人工批准字段字典和规则。
