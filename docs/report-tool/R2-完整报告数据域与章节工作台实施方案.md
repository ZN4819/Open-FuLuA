# R2：完整报告数据域与章节工作台实施方案

> 状态：未实施。本文档为开发实施基线，不代表功能已交付。

## 1. 阶段定位

R2 在 R1 双项目底座上建立完整报告的结构化数据域和章节工作台。本阶段回答“完整报告的数据存在哪里、同一对象如何被多个章节复用、用户如何按章节编辑”，但不负责正文派生或最终 Word：正文确定性派生与一致性链路由 R3 实现，DOCX 模板装配由 R4 实现。

复杂度：高。复杂度来源是业务实体关系、中央测评对象库与现有附录 A 行的兼容关联、结构化块版本控制、跨章节复用和前端工作台拆分，而不是单纯增加表单。

前置依赖：R1 已提供 `project_uuid`、`project_type`、`workflow_status`、固定模板身份 `2023/2025-12-08` 和类型化初始化服务。若 R1 未合并，不得以项目名称或 A 章节数量临时推断完整报告项目。

## 2. 经仓库验证的当前基线

- 当前 `projects` 只有项目级名称和时间；没有报告编号、委托/被测单位、人员、系统概况、测评对象库等正文实体。
- `assessment_rows.object_name` 是每行文本快照，A-1～A-4 可按子系统分组，但同一设备、应用或链路无法在章节间以稳定 ID 复用。
- `evidence_images` 依赖 `section_code`，`cross_references` 的来源只能是 `assessment_row`，无法表达普通正文块到图、表、章节或问题的引用。
- 前端 `ProjectPage` 同时处理首页、导入、A-1～A-8 草稿、图片、模板、校验和导出；`SectionNav` 固定显示 A-1～A-8，继续叠加完整报告功能会扩大耦合。
- 当前模板 profile 只描述附录 A 页面、两种测评表、字体和图片规则，不包含完整报告章节树和字段定义。
- 现有结果记录模板槽位适用于 A 章节测评结果，不等同于报告章节模板，不能拿来保存任意正文。

## 3. 统一契约继承

R2 必须原样继承：

- `project_type=appendix_a|full_report`
- `workflow_status=draft|ready_for_review|confirmed`
- `template_edition=2023`、`template_revision=2025-12-08`
- `export_mode=draft|final`
- `import_mode=migration|roundtrip`
- Ra、Rk 不进入 Word
- Word 批注只产生 warning

R2 中所有报告实体只允许属于 `full_report`。访问 `appendix_a` 项目的 `/report/*` API 返回 409 `REPORT_DOMAIN_NOT_AVAILABLE`，不得自动创建隐藏报告数据。

## 4. 目标与非目标

### 4.1 目标

- 固定并实现八类核心实体：`report_metadata`、`report_organizations`、`report_members`、`system_profiles`、`assessment_objects`、`object_relations`、`report_sections`、`report_blocks`。
- 建立中央测评对象库，以稳定 UUID 贯通系统概述、测评范围、附录 A 和后续问题/风险链路。
- 从模板 manifest 初始化完整报告章节实例，章节顺序和能力来自模板版本，不在前端硬编码。
- 提供类型安全的结构化块编辑器，覆盖文本、列表、键值表、数据表、图片、引用和只读生成块占位。
- 拆分完整报告工作台路由、导航和保存状态，保留现有附录 A 编辑器作为独立入口。
- 建立乐观并发、审计时间和工作流回退规则，避免多个页面覆盖更新。

### 4.2 非目标

- 不提供通用 WYSIWYG Word 编辑器，不允许用户粘贴任意 HTML/OOXML。
- 不在 R2 自动生成问题、风险、总结或结论，不使用 AI。
- 不生成完整报告 DOCX；只保留现有附录 A DOCX/XLSX能力。
- 不实现任意模板版本；只支持 `2023/2025-12-08`。
- 不强制一次性把所有现有 `object_name` 自动合并成一个中央对象；有歧义时必须由用户确认。
- 不把 Ra、Rk 暴露到报告块或 Word 字段。

## 5. 总体架构

后端按以下边界拆分：

```text
report_core/
  contracts.py        # 实体枚举、块 schema、错误码
  metadata.py         # 报告基本信息
  organizations.py    # 组织与人员
  systems.py          # 系统画像
  objects.py          # 中央对象库与关系
  sections.py         # 章节实例、完成度、顺序
  blocks.py           # 结构化块和并发控制
  initializer.py      # 按模板 manifest 初始化
appendix_a/
  adapter.py          # 现有A行与 assessment_object_uuid 的兼容桥
```

数据库函数只负责持久化；组合校验、工作流回退、跨实体引用和删除保护必须在服务层。API 不直接接收数据库 JSON 字符串，统一使用经过 Pydantic 判别联合校验的 payload。

前端建议路由：

```text
/projects/:uuid/overview
/projects/:uuid/report/:sectionKey
/projects/:uuid/objects
/projects/:uuid/appendix-a/:code
/projects/:uuid/review
```

## 6. 固定数据实体与约束

所有实体使用数值内部主键和对外稳定 UUID；`project_id` 继续作为本地外键。时间使用 UTC ISO 字符串。用户可编辑实体增加整数 `revision`，每次成功更新加一。

### 6.1 `report_metadata`

一项目一行，字段包括：

- `project_id`（唯一外键）
- `report_no`、`report_version`
- `report_title`、`system_name`
- `security_level`
- `confidentiality_level`
- `assessment_start_date`、`assessment_end_date`
- `issue_date`
- `document_status`
- `contact_name`、`contact_phone`
- `extra_fields_json`（只允许 manifest 声明的扩展键）
- `revision`、创建/更新时间

日期关系由后端校验；报告编号可在本地项目间重复警告但不强制唯一，因为历史版本可能共享编号。敏感联系方式不得写入普通日志。

### 6.2 `report_organizations`

保存报告参与组织，不把单位名称散落到多个章节块：

- `organization_uuid`、`project_id`
- `organization_type`：`assessment`、`client`、`assessed`、`operator`、`vendor`、`other`
- `name`、`short_name`、`unified_social_credit_code`
- `address`、`contact_name`、`contact_phone`
- `sort_order`、`is_primary`、`revision`

同一项目同一 type 最多一个 `is_primary=1`；删除被成员、系统或报告字段引用的组织返回 409，并列出引用位置。

### 6.3 `report_members`

- `member_uuid`、`project_id`、`organization_uuid`
- `name`、`role_type`、`job_title`
- `certificate_no`、`responsibilities`
- `display_order`、`is_active`、`revision`

证书编号按敏感数据处理；列表接口可返回完整值给本地客户端，但日志、异常和诊断包默认脱敏。

### 6.4 `system_profiles`

一项目一个主画像，保存会被多章节复用的系统事实：

- `system_uuid`、`project_id`
- `system_name`、`system_abbreviation`
- `operator_organization_uuid`
- `security_level`、`deployment_scope`
- `business_description`
- `network_architecture_summary`
- `data_summary`
- `crypto_application_summary`
- `service_population`、`geographic_scope`
- `boundary_description`
- `extra_fields_json`（manifest allowlist）
- `revision`、时间

长文本仍是纯文本/受控 Markdown 子集，不保存 HTML。系统名称与 `report_metadata.system_name` 必须由单一字段权威化：建议以 `system_profiles.system_name` 为权威，metadata 响应中作为派生显示，禁止两处独立修改。

### 6.5 `assessment_objects`

中央对象库是 R2 的核心：

- `object_uuid`、`project_id`
- `object_type`：`physical_environment`、`network_channel`、`device`、`platform`、`application`、`data`、`crypto_product`、`crypto_service`、`document`、`personnel_group`、`other`
- `name`、`code`、`subsystem`
- `manufacturer`、`model`、`version`
- `deployment_location`、`ip_or_endpoint`
- `description`
- `properties_json`（按 object_type 的 JSON Schema 校验）
- `source`：`manual`、`appendix_a_migration`、`import`
- `active_status`：`active`、`inactive`
- `revision`、排序和时间

同一项目内不以名称强制去重；提供规范化名称+类型+子系统的重复候选警告。合并对象必须是显式命令，重写所有关系和 A 行关联并保留旧 UUID 的 alias 记录，不能简单删除。

现有 `assessment_rows` 增加 nullable `assessment_object_uuid`。`object_name` 继续保留为导出快照，避免对象重命名导致历史记录无提示变化。绑定对象时同步快照；对象改名后把相关 A 行标为“对象名称过期”，由用户选择批量同步。未绑定的旧行仍可编辑、评分和导出。

### 6.6 `object_relations`

- `relation_uuid`、`project_id`
- `source_object_uuid`、`target_object_uuid`
- `relation_type`：`contains`、`connects_to`、`depends_on`、`protects`、`uses_product`、`uses_service`、`stores_data`、`managed_by`
- `direction`、`description`、`sort_order`、`revision`

禁止自环；`contains` 禁止形成循环；端点必须同项目。删除对象前必须处理关系和报告块引用。

### 6.7 `report_sections`

章节实例由模板 manifest 初始化：

- `section_uuid`、`project_id`
- `template_section_key`（例如 `cover`、`overview.system`、`assessment.result`、`appendix_a`、`appendix_b`）
- `parent_section_uuid`
- `title`、`heading_level`、`sort_order`
- `section_kind`：`form`、`blocks`、`generated`、`appendix_a`、`appendix_b`
- `edit_policy`：`structured`、`generated_only`、`appendix_module`
- `completion_status`：`empty`、`in_progress`、`complete`
- `template_edition`、`template_revision`
- `revision`、时间

章节不能由用户任意删除或改层级；模板允许时可修改显示标题。顺序调整只允许 manifest 标注的可移动同级章节。A、B 附录节点不可删除。

### 6.8 `report_blocks`

- `block_uuid`、`project_id`、`section_uuid`
- `block_key`（模板槽位稳定键）
- `block_type`：`paragraph`、`bullet_list`、`numbered_list`、`key_value_table`、`data_table`、`figure`、`reference`、`generated`
- `payload_json`（按 block_type 判别 schema）
- `source_kind`：`manual`、`template_default`、`generated`
- `edit_policy`：`editable`、`overrideable`、`readonly`
- `sort_order`、`revision`
- 为 R3 预留：`baseline_json`、`baseline_hash`、`override_json`、`source_hash`、`generation_status`（`current|stale|not_generated`）
- 时间

块内容限制：段落只允许纯文本及受控引用 token；表格必须有列 schema 和行对象；figure 只引用通用资产 UUID；reference 只引用受支持目标。单块 payload 设大小上限，禁止脚本、外链 iframe、任意 OOXML 和 base64 图片。

## 7. API 契约

所有 `/report/*` 请求先校验 `project_type=full_report` 和模板身份。更新使用 `If-Match: <revision>` 或请求体 `expected_revision`；冲突返回 409 `REVISION_CONFLICT` 并返回当前 revision，不做最后写入者覆盖。

### 7.1 概览与元数据

- `GET /api/projects/{uuid}/report/overview`
- `GET|PUT /api/projects/{uuid}/report/metadata`
- `GET|PUT /api/projects/{uuid}/report/system-profile`

overview 返回章节完成度、对象数量、未绑定 A 行数、warning/error 数和工作流状态，不返回全部大文本。

### 7.2 组织与成员

- `GET|POST /api/projects/{uuid}/report/organizations`
- `PUT|DELETE /api/projects/{uuid}/report/organizations/{organization_uuid}`
- `GET|POST /api/projects/{uuid}/report/members`
- `PUT|DELETE /api/projects/{uuid}/report/members/{member_uuid}`

删除冲突响应包含 `references[]`，供 UI 导航处理。

### 7.3 对象与关系

- `GET|POST /api/projects/{uuid}/report/objects`
- `GET|PUT|DELETE /api/projects/{uuid}/report/objects/{object_uuid}`
- `POST /api/projects/{uuid}/report/objects/duplicate-candidates`
- `POST /api/projects/{uuid}/report/objects/{source_uuid}/merge`
- `GET|POST /api/projects/{uuid}/report/object-relations`
- `PUT|DELETE /api/projects/{uuid}/report/object-relations/{relation_uuid}`
- `POST /api/projects/{uuid}/report/appendix-a-bindings/preview`
- `POST /api/projects/{uuid}/report/appendix-a-bindings/confirm`

绑定预览返回 exact、candidate、ambiguous、unmatched 四类；confirm 只接受用户明确选择，不自动猜测 ambiguous。

### 7.4 章节与块

- `GET /api/projects/{uuid}/report/sections`
- `GET /api/projects/{uuid}/report/sections/{section_uuid}`
- `PUT /api/projects/{uuid}/report/sections/{section_uuid}`
- `POST /api/projects/{uuid}/report/sections/{section_uuid}/blocks`
- `PUT|DELETE /api/projects/{uuid}/report/blocks/{block_uuid}`
- `POST /api/projects/{uuid}/report/blocks/reorder`

批量重排必须在单事务中验证同一 section 和连续顺序。只读 generated 块在 R2 只能显示占位，修改返回 409 `BLOCK_READ_ONLY`。

### 7.5 错误格式

```json
{
  "code": "REVISION_CONFLICT",
  "message": "内容已在其他页面更新，请刷新后重试。",
  "entity_type": "report_block",
  "entity_uuid": "...",
  "field": null,
  "details": {"expected_revision": 3, "current_revision": 4}
}
```

## 8. UI 契约

### 8.1 工作台布局

- 左侧为 manifest 驱动的完整报告章节树，显示完成度和未保存状态；附录 A 节点展开到 A-1～A-8。
- 中间为当前章节编辑器；表单章节使用专用字段组件，blocks 章节使用结构化块组件，generated 节点只显示来源和待生成状态。
- 右侧为当前章节引用的数据摘要、校验问题和对象选择器，不默认常驻全部图片库。
- 顶部显示项目类型、模板版本和 `draft|ready_for_review|confirmed` 状态。

### 8.2 中央对象库

- 支持按类型、子系统、关键词过滤；显示被哪些章节/A 行引用。
- 新建和编辑使用 object_type 对应字段 schema；未知扩展进入受控“其他属性”，不能任意增加数据库列。
- A 行绑定向导先预览匹配，不自动合并；名称歧义必须人工选择。
- 对象删除前展示关系、章节块和附录 A 引用，存在引用时引导停用或迁移引用。

### 8.3 结构化块编辑

- 用户从 manifest 允许的 block_type 中新增；模板固定块不能删除。
- 文本编辑不提供字体、字号、颜色等版式控制；版式规则由 R0 固化的运行时模板定义，并在 R4 装配时应用。
- 表格编辑按列 schema 校验；粘贴数据先预览并报告截断/非法单元格。
- 引用选择器保存目标 UUID，不把“图 3-2”一类显示编号作为数据键。
- 保存后内容变化自动把项目工作流回退到 `draft`；前端显示原因。

### 8.4 附录 A 复用

现有 `AssessmentTable`、模板管理、图片面板和评分逻辑保持原功能。完整报告工作台只包裹路由与对象绑定入口，不在 R2 重写 A 表。Ra/Rk 仍可在 A 表评分区使用，但任何报告章节、块预览和 Word 相关 UI 不显示它们。

## 9. 可提交工作包

### WP-R2.1：报告核心 schema 与模板初始化器

**输入**：R1 full_report 项目、固定模板身份、章节 manifest 草案。

**具体改动**：创建八类固定实体、索引、外键和 revision；实现按 `2023/2025-12-08` manifest 幂等初始化；扩展项目删除级联与运行文件清理。

**失败行为**：任一实体或章节初始化失败时事务回滚；模板身份不匹配返回明确错误，不用默认章节替代。

**测试**：空项目初始化、重复初始化、appendix_a 拒绝、外键/唯一约束、删除级联、异常 manifest、schema 升级恢复。

**验收**：一个 full_report 项目恰有一套 metadata/system profile 和确定性章节树；重复启动不新增重复块。

**建议提交**：`R2.1: 建立完整报告核心实体与章节初始化`

### WP-R2.2：元数据、组织、成员和系统画像 API

**输入**：R2.1 实体和字段 schema。

**具体改动**：实现应用服务、Pydantic 契约、CRUD、组合校验、revision 冲突和敏感日志脱敏。

**失败行为**：引用中组织删除返回 409；非法日期或跨项目 UUID 返回 422/404；并发冲突不覆盖数据。

**测试**：合法/非法字段、主组织唯一、跨项目访问、并发 revision、日志脱敏、内容变化回退 draft。

**验收**：正文公共事实只需在一个结构化位置维护，API 响应无重复权威字段。

**建议提交**：`R2.2: 完成报告基础信息与参与方数据域`

### WP-R2.3：中央测评对象库与关系

**输入**：现有 A 行对象名称、对象类型 schema。

**具体改动**：对象/关系 CRUD、重复候选、合并、循环检测、引用保护；为 assessment_rows 增加可空对象 UUID 和名称过期标志。

**失败行为**：关系跨项目、自环或 contains 循环时拒绝；合并中任一引用重写失败时整体回滚；绝不按名称静默合并。

**测试**：重复名称、不同类型同名、关系循环、对象停用/删除、合并回滚、A 行绑定后原评分不变。

**验收**：同一对象能稳定被多个章节和 A 行引用；未绑定旧行仍完全兼容。

**建议提交**：`R2.3: 建立中央对象库及附录A兼容关联`

### WP-R2.4：A 行绑定预览与确认

**输入**：升级项目中的现有 A 行和中央对象库。

**具体改动**：确定性规范化匹配、四类预览结果、人工确认 API、对象名称同步预览。

**失败行为**：ambiguous/unmatched 不自动写；确认载荷引用已变化时返回 revision 冲突；失败不部分绑定。

**测试**：完全匹配、空格/标点规范化、多候选、无候选、批量原子性、重新运行幂等。

**验收**：用户可解释每个自动候选依据，任何不确定匹配都保留人工决策。

**建议提交**：`R2.4: 完成附录A对象绑定向导`

### WP-R2.5：章节与结构化块 API

**输入**：manifest 章节树和 block JSON Schema。

**具体改动**：章节读取、完成度、块 CRUD/重排、payload 校验、只读策略、引用 UUID 校验、大小限制。

**失败行为**：未知 block type、非法 payload、跨章节重排、只读修改和悬空引用均返回结构化错误；数据库不保存半合法 JSON。

**测试**：每类块契约、固定块保护、排序事务、revision 冲突、payload 上限、恶意 HTML/OOXML、跨项目引用。

**验收**：所有可编辑正文内容都可被确定性 JSON 表达并重新读取，前后端 schema 一致。

**建议提交**：`R2.5: 提供报告章节与结构化块服务`

### WP-R2.6：完整报告章节工作台

**输入**：R2 API、现有附录 A 组件。

**具体改动**：拆分路由和页面状态；实现章节树、概览、基础表单、对象库、块编辑器、未保存保护、并发冲突提示；嵌入附录 A 路由。

## 10. 迁移与回滚

- R2 schema 迁移只新增表、索引和 `assessment_rows` 可空关联字段，不重写现有 `object_name`。
- R1 已创建但尚无 R2 数据的 full_report 项目，在启动时由 initializer 幂等补齐；记录模板版本，不按当前最新模板猜测。
- 升级项目的对象库导入必须先生成预览；用户未确认前 A 行保持未绑定，不影响现有导出。
- 回滚到 R1 版本时，R2 新表会被旧程序忽略，但数据库 user_version 不允许旧后端直接打开；正式回滚仍使用升级前备份。
- 对单个项目可提供“重建未编辑模板章节”诊断命令，仅删除 `template_default` 且未修改的块；不得清空人工块或 A 数据。

## 11. 风险与安全

- **重复事实不一致**：为系统名、组织名等定义唯一权威实体，章节只保存引用或渲染快照。
- **JSON 变成无约束垃圾桶**：所有 `properties_json/payload_json` 必须按版本化 schema 校验和限制大小。
- **对象错误合并**：只提供候选和显式确认；合并事务保留 alias 与审计信息。
- **并发覆盖**：实体 revision + If-Match；冲突保留本地草稿。
- **跨项目引用泄漏**：所有 UUID 解析必须同时限定 project_id。
- **富文本攻击/格式漂移**：不接受 HTML、JavaScript、外部 iframe、任意 OOXML；显示层转义纯文本。
- **敏感信息泄漏**：电话、证书编号、IP/端点和报告内容不写入普通日志，诊断包按既有安全规则处理。
- **删除级联误伤**：组织、对象等业务实体使用引用保护/停用；只有项目删除执行级联。
- **Ra/Rk 泄漏**：报告 API DTO 和 report_blocks schema 中不存在 Ra/Rk 字段；只在 Appendix A 评分接口和 XLSX 使用。
- **批注误阻断**：批注扫描结果固定 severity=warning，不能被通用“存在 issue 即失败”的实现错误提升。

## 12. 阶段验收闸门

- 八类固定实体、索引、约束、revision 和模板初始化均有自动化测试。
- 完整报告章节树完全来自 `2023/2025-12-08` manifest，前端无硬编码章节清单。
- 中央对象库支持明确引用、关系、重复候选和人工合并；不存在名称自动合并。
