# R2：完整报告数据域与章节工作台实施方案

> 状态：技术实施与本地验收已完成，待本阶段 Pull Request 合入 `main`。验收证据见 [R2 实施验收记录](R2-实施验收记录.md)。

## 1. 阶段定位

R2 在 R1 双项目底座上建立完整报告的结构化数据域、字段及参数关联矩阵和章节工作台。本阶段回答“完整报告的权威数据存在哪里、R0 确认的关联如何成为 API/数据库/UI 同源契约、用户如何按章节编辑”。R2 不负责指标统计、结果修正计算、风险/结论/正文派生或最终 Word：派生计算与一致性链路由 R3 实现，DOCX 模板装配由 R4 实现。

复杂度：高。复杂度来源是业务实体关系、中央测评对象库与现有附录 A 行的兼容关联、结构化块版本控制、跨章节复用和前端工作台拆分，而不是单纯增加表单。

前置依赖：R0 已冻结完整字段字典、manifest 和总方案第 3.6 节业务基线；R1 已提供 `project_uuid`、`project_type`、`workflow_status`、不可变 `report-2023-2025.12.08` 模板包绑定和类型化初始化服务。若 R0/R1 未合并，不得以项目名称、A 章节数量或当前最新模板临时推断项目类型/模板身份。

## 2. 经仓库验证的当前基线

- 当前 `projects` 只有项目级名称和时间；没有报告编号、委托/被测单位、人员、系统概况、测评对象库等正文实体。
- `assessment_rows.object_name` 是每行文本快照，A-1～A-4 可按子系统分组，但同一设备、应用或链路无法在章节间以稳定 ID 复用。
- `evidence_images` 依赖 `section_code`，`cross_references` 的来源只能是 `assessment_row`，无法表达普通正文块到图、表、章节或问题的引用。
- 前端 `ProjectPage` 同时处理首页、导入、A-1～A-8 草稿、图片、模板、校验和导出；`SectionNav` 固定显示 A-1～A-8，继续叠加完整报告功能会扩大耦合。
- 当前模板 profile 只描述附录 A 页面、两种测评表、字体和图片规则，不包含完整报告章节树和字段定义。
- 现有结果记录模板槽位适用于 A 章节测评结果，不等同于报告章节模板，不能拿来保存任意正文。

## 3. 统一契约继承

R2 必须原样继承：

- `project_type=appendix_a|full_report`
- `workflow_status=draft|ready_for_review|confirmed`
- `template_edition=2023`、`template_revision=2025-12-08`
- `export_mode=draft|final`
- `import_mode=migration|roundtrip`
- Ra、Rk 不进入 Word
- Word 批注只产生 warning

R2 中所有报告实体只允许属于 `full_report`，且必须与项目已绑定的 package ID/资产集指纹一致。访问 `appendix_a` 项目的 `/report/*` API 返回 409 `REPORT_DOMAIN_NOT_AVAILABLE`，不得自动创建隐藏报告数据。字段 `source_kind` 原样继承 R0 闭集 `manual|imported|derived|template_constant`，不得在 R2 引入同义枚举。

## 4. 目标与非目标

### 4.1 目标

- 实现总方案第 5 节固定的 15 类 R2 实体：`report_metadata`、`report_organizations`、`report_members`、`report_phase_dates`、`report_distribution`、`system_profiles`、`system_crypto_products`、`report_standards`、`special_indicators`、`assessment_objects`、`assessment_object_subsystems`、`object_relations`、`result_correction_relations`、`report_sections`、`report_blocks`。
- 建立对象稳定标识与引用层，但严格保持“附录 A 是测评对象和结果唯一事实源”；第 2 章不反向生成/覆盖附录 A，第 3、4 章只使用可追溯派生投影。
- 交付版本化、机器可读的《报告字段及参数关联矩阵》，对总方案第 3.6.1～3.6.6 每条规则建立稳定 ID、数据路径、编辑权、缺失/冲突行为、负责阶段和测试向量。
- 从模板 manifest 初始化完整报告章节实例，章节顺序和能力来自模板版本，不在前端硬编码。
- 提供类型安全的结构化块编辑器，覆盖文本、列表、键值表、数据表、图片、引用和只读生成块占位。
- 拆分完整报告工作台路由、导航和保存状态，保留现有附录 A 编辑器作为独立入口。
- 建立乐观并发、审计时间和工作流回退规则，避免多个页面覆盖更新。

### 4.2 非目标

- 不提供通用 WYSIWYG Word 编辑器，不允许用户粘贴任意 HTML/OOXML。
- 不在 R2 自动生成问题、风险、总结或结论，不使用 AI。
- 不在 R2 实现多对象指标结论算法、A-2/A-4 双向修正公式、八层统计、综合得分、风险等级、高风险判断或评估结论；R2 只建模其输入、关系和输出槽位。
- 不生成完整报告 DOCX；只保留现有附录 A DOCX/XLSX能力。
- 不实现任意模板版本；只支持 `2023/2025-12-08`。
- 不强制一次性把所有现有 `object_name` 自动合并成一个中央对象；有歧义时必须由用户确认。
- 不把 Ra、Rk 暴露到报告块或 Word 字段。

### 4.3 《报告字段及参数关联矩阵》交付契约

矩阵必须与代码同库版本化，且由后端契约测试读取，不得只作为人工 Markdown 说明。每条至少包含：

- `relation_id`、`readme_rule_ref`、`authority_field_id`、`source_kind`。
- 权威实体/字段路径、参考实体或输入路径、目标语义槽位/章节块。
- 关联类型（重复投影、条件必填、参照完整性、聚合输入、派生输出槽位等）、可编辑性、约束表达式。
- 缺失、非法值、重复、未选分支有值、上游变化和冲突时的结构化错误/warning 代码。
- 负责实现阶段、当前确认状态、测试向量 ID 和导出阶段映射 ID。

对总方案第 3.6 节的承接按下表固定：

| 基线 | R2 必须实现 | 留给后续阶段 |
| --- | --- | --- |
| 3.6.1 报告身份、单位和版本 | `system_name`、`report_number`、被测/委托单位、有效委托单位派生、模板机构常量引用、导出版本默认值；报告编号建立跨项目查重服务 | R4 按槽位投影、建立导出快照并组装文件名 |
| 3.6.2 日期、人员和分发 | 四阶段日期、B.2/B.3/B.5/B.6/B.9 关联输入、项目组/编审批角色、分发份数及所有条件校验 | R5 复用同一人员/日期路径组装证据；R4 执行 Word 投影 |
| 3.6.3 基本信息、标准和密码产品 | 完整互斥分支保存/warning 契约，S/A/G、等保/云平台/密码方案/运行状态/服务范围，表 2-3 产品数量和分类，人工算法勾选，固定/人工标准及特殊指标外键 | R4 执行最终附录 A 算法全文匹配与 Word 投影 |
| 3.6.4 附录 A、测评对象和章节投影 | 附录 A 唯一事实源、A-1～A-4 对象/子系统约束、表 2-7 应用名称子集校验、表 3-4～3-7 及 4-1～4-11 只读投影查询和测评方式/备注独立数据 | R3 消费对象/指标输入生成结论和正文；R4 组装对应表格 |
| 3.6.5 指标结论、结果修正和最终投影 | 原始评分及结论输入路径、A-2/A-4 关系建模、多对象基数约束、原始/最终输出槽位和只读预览占位 | R3 实现指标聚合、双向修正和最终投影公式；R4 实现星号、D/A/K 显示和章节差异装配 |
| 3.6.6 统计、风险、结论和正文 | 预留稳定输出字段/块、`derived` 只读策略、源哈希/过期/确认状态和 R3 输入完整性接口 | R3 实现派生规则矩阵、公式、正文草稿和过期链路；R4 只消费已确认输出 |

R2 实现的“派生”只限于单纯字段关联（如有效委托单位、总份数、日期同源和表 2-3 数量归一化），不包含 R3 的评分、风险、结论或自然语言生成。

## 5. 总体架构

后端按以下边界拆分：

```text
report_core/
  contracts.py        # 实体枚举、块 schema、错误码
  field_matrix.py     # R0 字段契约与第 3.6 节关联矩阵
  metadata.py         # 报告身份、单位、阶段日期与分发
  organizations.py    # 组织、项目组与编审批人员
  systems.py          # 系统画像、基本信息分支、密码产品与算法
  standards.py        # 固定/人工标准与特殊指标
  objects.py          # 对象稳定标识、子系统与章节投影
  corrections.py      # A-2/A-4 修正关系输入，不包含 R3 公式
  sections.py         # 章节实例、完成度、顺序
  blocks.py           # 结构化块和并发控制
  initializer.py      # 按模板 manifest 初始化
appendix_a/
  adapter.py          # 现有A行与 assessment_object_uuid 的兼容桥
```

数据库函数只负责持久化；组合校验、工作流回退、跨实体引用和删除保护必须在服务层。API 不直接接收数据库 JSON 字符串，统一使用经过 Pydantic 判别联合校验的 payload。

前端建议路由：

```text
/projects/:uuid/overview
/projects/:uuid/report/:sectionKey
/projects/:uuid/objects
/projects/:uuid/appendix-a/:code
/projects/:uuid/review
```

## 6. 固定数据实体与约束

所有实体使用数值内部主键和对外稳定 UUID；`project_id` 继续作为本地外键。时间使用 UTC ISO 字符串。用户可编辑实体增加整数 `revision`，每次成功更新加一。

### 6.1 `report_metadata`

一项目一行：`project_id`、`report_number`、`default_export_version`（默认 `V1.0`）、等级/密级等项目级属性、受控扩展键、`revision`和时间。不保存 `report_status`，不保存会进入正文的“报告版本”，也不重复保存系统名称。

- `system_profiles.system_name` 是唯一权威值，metadata API 可只读返回其派生显示。
- `report_number` 预览时可空；R2 提供跨项目查重服务和非唯一索引，但不用数据库唯一约束阻止草稿保存。进入 `ready_for_review` 和最终导出时发现重复必须阻断。
- 每次导出的实际版本和不可变快照由 R4 的导出实体保存；R2 的默认版本只是管理偏好。

### 6.2 `report_organizations`

仅保存项目可编辑的 `assessed`、`client`、`vendor|other` 等组织。被测单位必填，委托单位选填；`effective_client_organization_uuid = coalesce(client, assessed)` 是 `derived` 只读字段。不创建可编辑 `operator`，内部需要该语义时回退为被测单位。

密评机构的名称、地址、邮编和联系人来自模板包 `template_constant`，不写入项目可编辑表。删除被成员、分发或块引用的组织返回 409 并列出 `references[]`。

### 6.3 `report_members`

字段至少包含 `member_uuid`、所属项目/组织、姓名、项目组角色、是否项目负责人、考核通过时间、职务/职称、证书编号、活动状态、排序和 `revision`。项目级编制人/审核人/批准人使用外键指向本表，不重复保存姓名。

后端必须校验：项目组至少两名已通过考核人员；编制人必填、为组员、已通过考核且不是项目负责人；审核人/批准人可空，存在时必须有考核通过时间；三者不得重复，同一审批角色不得多人。B.2/B.3 人员必须引用项目组成员。敏感字段默认不进日志/诊断包。

### 6.4 `report_phase_dates`

保存四个测评阶段起止日期、B.2 差旅区间、B.3 一次或多次进离场记录、B.5 方案评审时间、B.6 报告评审时间及批准日期。

- 测评开始日期=准备阶段开始；测评结束日期=分析与报告编制阶段结束=首页/声明页/编制日期。
- 审核日期只来自 B.6，B.6 空则审核日期空；批准日期独立选填。有值时满足编制≤审核≤批准。
- B.5 必须早于现场开始。一次现场的阶段起止取该 B.3 记录；多次取最早进场/最晚离场。B.2 必须覆盖对应现场区间，本地无差旅保留结构并显式标记 `/`。

### 6.5 `report_distribution`

一项目一行，保存监管部门、有效委托单位、密评机构留存份数；分项是非负整数，可为 0，`total_copies` 是只读派生和且必须大于 0。有效委托单位引用第 6.2 节的单一派生结果。

### 6.6 `system_profiles`

一项目一个主画像，`system_name` 是项目级唯一数据源。除系统概述长文本外，还必须以显式字段/受控子表保存关键信息基础设施、等保备案 S/A/G、等保测评、云平台依赖、密码应用方案、运行状态、服务范围、算法勾选及其各分支数据。

互斥选择只控制勾选，不删除未选分支已录入值。已选分支缺必填值返回 error；未选分支有值返回可确认 warning。具体枚举和条件必填须逐条复制总方案 3.6.3，禁止用自由 JSON 代替。长文本仅允许纯文本/受控 Markdown 子集。

B.9 备案系统与被测系统相同时名称派生为 `system_name` 且只读；不同时名称和差异说明必填。未备案但 B.9 有数据只产生可确认 warning，不删数据。

### 6.7 `system_crypto_products`

表 2-3 每项产品一行，至少保存名称/型号等母版列、Word 原始数量、归一化统计数量、`exclusive|shared` 使用方式和 `certified|uncertified_domestic|foreign` 分类。整数按实际数量，字面值“若干”统计为 1 但保留 Word 原文；其他文本、负数或小数返回 error。

产品总数、独享/共享、三类认证分类总数是 `derived` 只读值，必须三路对平。“系统未使用密码产品”与非零总数并存产生可确认 warning。内部分类不改变母版表 2-3 列结构。

### 6.8 `report_standards` 与 `special_indicators`

前五项标准由模板包常量提供，项目只读；人工补充标准可增删改。每条特殊指标必须且只能外键引用一条人工标准，被引用标准禁止删除；一条人工标准可对应 0～N 条特殊指标。特殊指标不进入 41 项、评分、结果数或风险数；无数据时的“无/0项”为后续投影值。

### 6.9 `assessment_objects` 与 `assessment_object_subsystems`

`assessment_objects` 为附录 A 对象提供稳定 UUID、类型、名称快照、来源行、活动状态和受控扩展属性，但不成为可以反向改写附录 A 结果的第二事实源。附录 A 行的对象和结果仍为权威，第 2 章数据不与附录 A 直接同步。

- A-1/A-2/A-3 分别向表 3-4/3-5/3-6 提供去重只读对象集。
- 每个 A-4 对象必须且只能通过 `assessment_object_subsystems` 关联一个子系统；跨子系统逻辑对象必须拆行。子系统必须选自表 2-7 唯一应用名称，表 3-7 是实际引用子系统去重子集。
- 测评方式固定为访谈、文档审查、现场检查、配置检查、工具测试多选；方式和备注是第 3 章独立数据，A-4 按去重子系统保存。引用暂时消失时不投影，但保留历史值以恢复。
- 表 4-1～4-11 只读查询严格按总方案 3.6.4 筛选。表 4-6 的访问控制信息完整性映射到“存储完整性”列，没有对应指标记录时投影为“不适用”；同一对象同时标记为访问控制信息完整性和重要数据存储完整性时返回 error。

名称候选只作为绑定建议，不允许自动合并歧义对象。`assessment_rows.object_name` 继续保留；稳定 UUID 绑定不改变已有评分、导出或未绑定旧项目能力。

### 6.10 `object_relations` 与 `result_correction_relations`

`object_relations` 保存同项目对象间受控关系，禁止自环、跨项目端点和 `contains` 循环。删除/停用对象前必须列出章节、附录 A 和关系引用。

`result_correction_relations` 只允许两组同类对应：A-2 通信数据完整性↔A-4 重要数据传输完整性，A-2 通信过程中重要数据机密性↔A-4 重要数据传输机密性。一条 A-2 通道可关联多个 A-4 对象，每个 A-4 对象在对应指标上只能关联一条 A-2 通道。机密性/完整性不得交叉。R2 仅保存关系、原始值引用和 revision，不计算 0.5 阈值、最小值或最终分值。

### 6.11 `report_sections`

章节实例必须由项目已绑定包的 manifest 幂等初始化，保存稳定 section key、父子关系、标题、级别、顺序、`form|blocks|generated|appendix_a|appendix_b` 类型、编辑策略、完成状态、模板包身份和 `revision`。用户不得删除/改层级；只有 manifest 允许的同级章节可调整顺序，附录 A/B 节点不可删除。

### 6.12 `report_blocks`

保存稳定 block key、章节外键、`paragraph|bullet_list|numbered_list|key_value_table|data_table|figure|reference|generated` 判别载荷、R0 同源 `source_kind`、`editable|overrideable|readonly` 策略、顺序、`revision` 和时间。模板默认内容使用独立 `baseline_kind=template_default`，不得冒充新的 `source_kind`。

为 R3 预留 `baseline_json`、`baseline_hash`、`override_json`、`source_hash`、`generation_status=current|stale|not_generated` 和 `confirmation_status`。R2 中 `source_kind=derived` 块只能显示输入完整度与“待 R3 生成”，不允许人工写入伪生成结果。

块内容限制：段落只允许纯文本及受控引用 token；表格必须有版本化列 schema 和行对象；figure/reference 只保存同项目目标 UUID。设定 payload 上限，禁止脚本、HTML/iframe、任意 OOXML、base64 图片和跨项目引用。

## 7. API 契约

所有 `/report/*` 请求先校验 `project_type=full_report` 和模板身份。更新使用 `If-Match: <revision>` 或请求体 `expected_revision`；冲突返回 409 `REVISION_CONFLICT` 并返回当前 revision，不做最后写入者覆盖。

### 7.1 概览与元数据

- `GET /api/projects/{uuid}/report/overview`
- `GET|PUT /api/projects/{uuid}/report/metadata`

## 8. UI 契约

### 8.1 工作台布局

- 左侧为 manifest 驱动的完整报告章节树，显示完成度和未保存状态；附录 A 节点展开到 A-1～A-8。
- 中间为当前章节编辑器；表单章节使用专用字段组件，blocks 章节使用结构化块组件，generated 节点只显示来源和待生成状态。
- 右侧为当前章节引用的数据摘要、校验问题和对象选择器，不默认常驻全部图片库。
- 顶部显示项目类型、模板版本和 `draft|ready_for_review|confirmed` 状态。

### 8.2 中央对象库

- 支持按类型、子系统、关键词过滤；显示被哪些章节/A 行引用。
- 新建和编辑使用 object_type 对应字段 schema；未知扩展进入受控“其他属性”，不能任意增加数据库列。
- A 行绑定向导先预览匹配，不自动合并；名称歧义必须人工选择。
- 对象删除前展示关系、章节块和附录 A 引用，存在引用时引导停用或迁移引用。

### 8.3 结构化块编辑

- 用户从 manifest 允许的 block_type 中新增；模板固定块不能删除。
- 文本编辑不提供字体、字号、颜色等版式控制；版式规则由 R0 固化的运行时模板定义，并在 R4 装配时应用。
- 表格编辑按列 schema 校验；粘贴数据先预览并报告截断/非法单元格。
- 引用选择器保存目标 UUID，不把“图 3-2”一类显示编号作为数据键。
- 保存后内容变化自动把项目工作流回退到 `draft`；前端显示原因。

### 8.4 附录 A 复用

现有 `AssessmentTable`、模板管理、图片面板和评分逻辑保持原功能。完整报告工作台只包裹路由与对象绑定入口，不在 R2 重写 A 表。Ra/Rk 仍可在 A 表评分区使用，但任何报告章节、块预览和 Word 相关 UI 不显示它们。

## 10. 迁移与回滚

- R2 schema 迁移只新增表、索引和 `assessment_rows` 可空关联字段，不重写现有 `object_name`。
- R1 已创建但尚无 R2 数据的 full_report 项目，在启动时由 initializer 幂等补齐；记录模板版本，不按当前最新模板猜测。
- 升级项目的对象库导入必须先生成预览；用户未确认前 A 行保持未绑定，不影响现有导出。
- 回滚到 R1 版本时，R2 新表会被旧程序忽略，但数据库 user_version 不允许旧后端直接打开；正式回滚仍使用升级前备份。
- 对单个项目可提供“重建未编辑模板章节”诊断命令，仅删除 `template_default` 且未修改的块；不得清空人工块或 A 数据。

## 11. 风险与安全

- **重复事实不一致**：为系统名、组织名等定义唯一权威实体，章节只保存引用或渲染快照。
- **JSON 变成无约束垃圾桶**：所有 `properties_json/payload_json` 必须按版本化 schema 校验和限制大小。
- **对象错误合并**：只提供候选和显式确认；合并事务保留 alias 与审计信息。
- **并发覆盖**：实体 revision + If-Match；冲突保留本地草稿。
- **跨项目引用泄漏**：所有 UUID 解析必须同时限定 project_id。
- **富文本攻击/格式漂移**：不接受 HTML、JavaScript、外部 iframe、任意 OOXML；显示层转义纯文本。
- **敏感信息泄漏**：电话、证书编号、IP/端点和报告内容不写入普通日志，诊断包按既有安全规则处理。
- **删除级联误伤**：组织、对象等业务实体使用引用保护/停用；只有项目删除执行级联。
- **Ra/Rk 泄漏**：报告 API DTO 和 report_blocks schema 中不存在 Ra/Rk 字段；只在 Appendix A 评分接口和 XLSX 使用。
- **批注误阻断**：批注扫描结果固定 severity=warning，不能被通用“存在 issue 即失败”的实现错误提升。

## 12. 阶段验收闸门

- 八类固定实体、索引、约束、revision 和模板初始化均有自动化测试。
- 完整报告章节树完全来自 `2023/2025-12-08` manifest，前端无硬编码章节清单。
- 中央对象库支持明确引用、关系、重复候选和人工合并；不存在名称自动合并。
- 所有结构化块可 roundtrip JSON，非法/恶意载荷被后端拒绝。
- 两种项目类型 API 和 UI 隔离；appendix_a 项目行为不变。
- A 行可选绑定中央对象，未绑定项目仍可正常保存、评分、DOCX/XLSX导出。
- 结构化内容修改会可靠回退到 draft；ready_for_review 前校验可解释。
- Ra/Rk 不出现在报告 API/块；批注只警告。
- 全量后端、前端、桌面、备份恢复和附录 A 黄金回归通过。
