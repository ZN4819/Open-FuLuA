# R4：完整报告 DOCX 装配实施验收记录

## 1. 验收结论

R4 已完成技术实现、全量自动化检查、Microsoft Word 原生刷新验收和 Windows 隔离安装态验收。阶段交付将 R0 受信母版、R2 稳定报告上下文和 R3 原始/修正/最终投影装配为完整报告 DOCX，并建立了 schema 7 导出任务、不可变快照、结构化错误、草稿/正式版闸门和前端导出工作台。

完整报告装配不重新计算评分、修正、风险或结论，也不从 Word 位置反推业务字段。正式版仅消费同一项目 revision 下的 R2/R3 稳定上下文；上下文过期、哈希变化、字段校验失败、Word 刷新失败或检测到 Ra/Rk 时均不提供下载。

R5 尚未实施，因此附录 B 保留冻结母版空结构，并明确产生 `APPENDIX_B_NOT_IMPLEMENTED` 警告，不伪造证据材料。R4 未调用 LibreOffice，也未使用 LibreOffice 结果进行结构、分页或验收判断。

## 3. 关键实现

### 3.1 稳定上下文和正式版闸门

- 新增 R2 稳定上下文服务，一次读取项目、单位、人员、阶段日期、分发份数、系统画像、产品、标准、特殊指标、对象关系、章节块和证据，并记录项目 revision 与更新时间。
- 装配层不查询业务表，只消费稳定 R2 服务和已经确认的 R3 投影；装配结束前再次核对项目 revision、R2 更新时间和 R3 上下文哈希。
- 正式版校验覆盖报告编号、系统名称、被测单位、报告日期、编制人、项目状态、算法与附录 A 匹配、证据路径、R2 字段矩阵和 R3 一致性结果。
- 草稿保留结构化问题但不伪造分数、结论、风险或附录 B 材料；正式版存在 error 时直接失败。

### 3.2 白名单 OOXML 装配

- 基于 R0 运行时母版原包修改 `word/document.xml`、获准语义槽位、字段设置和新增图片关系；其余原始部件逐字节保持不变。
- 每次生成均回读 17 个分节签名、55 张表、原始关系、内容类型、新增媒体命名、页眉页脚和禁止内容。
- 新增图片仅允许使用确定性 `word/media/r4_<hash>` 路径及内部 image relationship；禁止外链、宏、OLE、ActiveX、批注、自定义 XML 和未接受修订。
- 非公式斜体全部阻断；公式中的斜体保持不变。
- 附录 A 在同一 OOXML 包内生成图片、题注、书签和交叉引用，不拼接独立 DOCX。

### 3.3 原始、修正和最终投影

- 第 4 章表 4-1～表 4-11只使用 R3 `original_projection.chapter4_tables`。
- 表 5-1 只列实际提高分值的修正对象；没有修正时保留标题和表头，数据行全部为 `/`。
- 表 5-2、综合得分、评估结论和附录 A 只使用 R3 `final_projection`。
- 实际修正的技术对象在 Word 附录 A 中将 D/A/K 显示为 `/`，对象评分显示为 `0.5000*` 形式，单元得分不加星号，也不增加星号说明。
- R3 补充了 11 张第 4 章权威原始投影和汇总，R4 只格式化，不在导出阶段二次聚合。

### 3.4 导出任务、快照和页面

- 新增异步校验、任务、状态、问题和 DOCX 下载 API；只有 `succeeded` 且文件位于受控 `storage` 路径内时才允许下载。
- 每次导出创建独立 job、上下文快照、上下文哈希和 DOCX 哈希；同一版本可重复导出，但同一 revision/模式只允许一个活动任务。
- 输出采用任务临时目录、刷新落盘和原子改名；失败不覆盖上次成功产物。
- 前端提供版本号、草稿/正式版、轮询、错误/警告分组、Word 刷新状态、页数、上下文哈希和重新下载入口；存在未保存内容时阻断导出。
- PyInstaller 和 Electron 打包资源已包含 Word 刷新脚本、R0 母版及全部前端/后端运行资源。

## 4. 代码审查修正

实施期间完成两轮自审并修复以下根因级问题：

1. 初版在替换固定叙述前先写入语义槽位，槽位值会破坏后续母版文本锚点。现改为先完成固定锚点装配，再统一投影语义槽位。
2. 初版正文通用表字段映射与冻结表头不完全一致。现按表号建立显式列顺序，并为产品表、应用表和管理对象表建立独立投影。
3. 初版 R4 直接查询 R2 业务表，违反稳定上下文边界。现提取 `report_context` 服务，R4 装配器不包含 `database.connect` 或 `SELECT`。
4. R3 初版没有向 R4 交付第 4 章 11 张原始投影。现由 R3 权威生成对象聚合、指标列和单元汇总，R4 只消费冻结结果。
5. 初版 ZIP 写回只遍历原母版条目，新增图片部件可能未落盘。现显式写入新增媒体并校验内容类型和关系。
6. 初版白名单证明只检查部件变化。现增加分节规范化签名、原始关系与内容类型保留、新媒体路径和禁止内容回读。
7. Word 自动化初版依赖窗口句柄获取 PID，隐藏启动时句柄可能为空。现以启动前后 WINWORD 进程集合差异为兜底，只记录和终止本任务进程。
8. Windows PowerShell 5.1 会错误解析无 BOM UTF-8 中文脚本。Word 刷新脚本现保持 ASCII，业务错误由 Python 层映射为中文。
9. 运行时已要求第 4 章 11 张权威投影，但机器可读 JSON Schema 最初仍只声明通用投影。现同步约束完整表集合、每表 `projection_id` 和结构；schema 6→7 时使旧 R3 当前快照失效，保留人工确认内容并要求重新生成/校验一次。
10. 文件原子改名后若最终任务状态提交失败，初版可能留下无成功任务引用的孤儿目录。现把已发布目录纳入任务回滚边界，状态冲突时清理本任务产物。

第二轮审查未发现剩余的 P1/P2 级阻断问题。安装包未配置代码签名，这是现有发布链约束，留待正式发布流程处理，不改变本阶段 DOCX 装配结果。
