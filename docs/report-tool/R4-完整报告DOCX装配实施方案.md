# R4：完整报告 DOCX 装配实施方案

> 状态：未实施。本文档为开发实施基线，不代表功能已交付。

## 1. 阶段定位

R4 将 R0 受信运行时母版、R2 稳定字段上下文和 R3 稳定派生上下文装配为完整报告 DOCX。R4 是严格的“投影与渲染层”，不再解释组织、日期、对象、评分、修正、风险或结论规则。

```text
R0受信母版包
  + R2ReportContext（权威字段、对象、表格数据和校验结果）
  + R3ProjectionContext（原始/修正/最终投影、正文、风险和结论）
  -> manifest白名单装配
  -> Word原生字段刷新和结构回读
  -> 不可变导出快照与DOCX
```

R4 不直接查询业务表，不调用评分公式重新计算分数，也不从 Word 位置推断字段含义。若 R2/R3 上下文缺失、过期、未确认或哈希不一致，草稿可显示问题，最终版必须失败。

复杂度：极高。主要风险是越过母版白名单、原始/最终结果混用、动态表破版、附录 A 星号展示错误、字段缓存未刷新、导出快照与文件不一致。

## 2. 前置输入与稳定接口

### 2.1 R0 输入

- `package_id=report-2023-2025.12.08` 的六项受信资产及哈希。
- 17 个分节、55 张表、字段字典、29 个语义标量槽位、块锚点和动态行区域。
- manifest 中的 `allowed_parts`、表渲染策略、内容控件、书签、关系类型和禁止项。
- `PAGE + PAGEREF(report_body_end)` 页码契约以及 Microsoft Word 原生刷新脚本基线。

### 2.2 R2 输入

`R2ReportContext` 至少包含：

- 项目和不可变模板绑定、报告编号、被测单位、有效委托单位、系统名称。R2 可提供默认导出版本偏好，但本次实际版本必须由 R4 导出请求确认，不进入报告正文业务投影。
- 单位、人员、四阶段日期、分发份数、基本信息、系统画像、表 2-1～表 3-7 数据。
- 41 项目录、附录 A 原始输入的稳定引用、特殊指标和人工补充标准。
- 字段关联矩阵版本/哈希、项目 revision、必填/分支/重复槽位一致性校验结果。

### 2.3 R3 输入

R4 只通过已冻结的 [`R3ProjectionContext v1`](contracts/R3ProjectionContext-v1.md) 取得 R3 输入，并按机器 schema `templates/report/contracts/2023-2025.12.08/r3_projection_context.v1.schema.json` 校验。上下文至少包含：

- `original_projection`、`correction_projection`、`final_projection`。
- 表 4-1～表 4-11、表 5-1、表 5-2 的结构化行。
- 最终附录 A 投影、41 项统计、风险、完整威胁目录、显示综合得分和评估结论。
- 已确认且未过期的系统简介、测评情况简介、总体评价、安全问题及建议、风险分析和第 7 章结论。
- 规则集版本/哈希、生成运行 ID、源哈希和一致性校验结果。

`R3_CONTEXT_NOT_AVAILABLE|R3_CONTEXT_STALE|R3_CONTEXT_NOT_CONFIRMED` 属于可由用户回到 R3 处理的导出阻断；`RULE_SET_UNAVAILABLE|R3_CONTEXT_HASH_MISMATCH|R3_CONTEXT_SCHEMA_INVALID|R3_PRIVATE_FACTOR_LEAK` 属于系统级失败，R4 不得降级读取内部表或沿用旧上下文。

### 2.4 R5 扩展接口

R4 先提供稳定 `AppendixBProjection` 和 `render_appendix_b()` 扩展点。R5 在此接口上提供附录 B 数据；R4 不提前建立第二套证据、人员或日期逻辑。R5 未实施时，附录 B 槽位保持母版允许的空结构并产生 warning，不能伪造材料。

## 3. 统一边界

- 只为 `project_type=full_report` 生成完整报告。
- `export_mode=draft|final`；现有附录 A `editable|final` 接口继续兼容，不静默改义。
- 正式交付仍为 DOCX 和独立 XLSX；不提供 PDF 下载。
- Ra/Rk 只存在于数据库和 XLSX，禁止进入 `ReportAssemblyContext`、DOCX、快照中的 Word 投影或日志。
- 批注提炼的编写提示只产生 warning；评分、关系、字段一致性、派生过期、结构和 Word 刷新错误可以阻断 final。
- R4 不回收 Word 修改；R7 只接受带有效快照的同源草稿。
- LibreOffice、WPS 或 PDF 转换结果不得作为完整报告结构、分页、字段刷新或验收依据。

## 4. 不可变装配上下文

装配开始时通过 R2/R3 稳定服务取得同一 `expected_project_revision` 下的上下文，并组装不可变 `ReportAssemblyContext`：

```text
ReportAssemblyContext
  project_identity
  template_binding
  r2_context + r2_matrix_hash
  r3_context + r3_rule_set_hash
  scalar_slot_values
  chapter_blocks
  table_rows_by_table_id
  appendix_a_final_projection
  appendix_b_projection_or_empty
  validation_summary
  warning_summary
```

上下文规范化后计算 SHA-256。构建期间项目 revision 变化、R2/R3 哈希不匹配或上下文含 stale/failed/review_required 时终止 final；不允许装配器回查数据库“补齐”缺失值。

所有重复字段只使用字段 ID 的一个权威值后批量投影：系统名称投影至首页、批准母版页眉、基本信息表、评估结论页、第 2 章、正文和附录；报告编号投影至首页和批准母版的报告编号页眉。多个槽位不一致属于上游契约错误，不能按位置任选一个。

## 5. 母版白名单装配

### 5.1 白名单原则

装配器只能修改 manifest 明确声明的：

- 标量内容控件和重复槽位。
- 块锚点包围的正文内容。
- 22 张动态表的批准行区域及固定表的批准单元格。
- 附录 A、附录 B 专用锚点。
- 生成所需的图片关系、书签、SEQ/REF/PAGEREF 字段缓存和 `w:updateFields`。

以下内容默认不可修改：固定正文、未登记表格、样式定义、编号模板、分节属性、页眉页脚关系、主题、字体表和非目标媒体。确需改变必须发布新模板包，不在 R4 运行时“顺手修复”。

### 5.2 白名单证明

每次导出在装配前后计算 OOXML 结构签名：

- 对不可变部件做字节或规范化 XML 哈希对比。
- 对 `word/document.xml` 先剔除白名单节点和允许更新的字段缓存，再比较剩余结构。
- 校验 17 分节、55 张表顺序、表头签名、固定列数、核心书签和页眉页脚关系。
- 任一非白名单漂移返回 `TEMPLATE_OUTSIDE_ALLOWLIST_CHANGED`，不发布文件。

### 5.3 动态行与关系分配

- 通过稳定锚点和 `table_id` 定位，不使用表格序号猜测业务含义。
- 只克隆 manifest 指定模板行；删除示例行后保留表头、样式、列宽和重复表头属性。
- 多行按稳定业务 UUID 和规则指定顺序生成，不按数据库 ID。
- 统一分配关系 ID、图片名、书签 ID、编号 ID，避免附录 A/B 与正文冲突。
- 不设置固定行高截断长文本；动态表允许跨页并按 manifest 重复表头。

## 6. 章节、表 4/表 5 与附录 A 投影

### 6.1 章节对象投影

- 表 3-4、表 3-5、表 3-6 分别使用 R2 从 A-1、A-2、A-3 派生的唯一对象集合。
- 表 3-7 使用 A-4 对象所属子系统去重集合，并且只能是表 2-7 应用名称的子集。
- 表 3-4～表 3-7 的对象列只读；测评方式和备注使用 R2 独立字段，R4 不从附录 A 文本回推。

### 6.2 第 4 章原始投影

- 表 4-1～表 4-11 必须只消费 R3 `original_projection`，即结果修正前对象和指标结论。
- 表 4-4 对 A-4 按“子系统 + 指标”聚合；不得直接输出原始 A-4 对象作为测评对象列。
- 表 4-5 只使用身份鉴别对象。
- 表 4-6 使用五类指定指标；访问控制信息完整性写入母版现有“存储完整性”列，无对应记录写“不适用”，不新增列。
- 表 4-7 只使用不可否认性对象。
- R4 不再次执行聚合，只验证 R3 行的指标、对象和列签名与 manifest 匹配。

### 6.3 第 5 章修正投影

- 表 5-1 只消费 `correction_projection` 中最终分值大于原始分值的对象。
- 没有实际修正时仍保留标题和表头，并生成一行所有内容单元格均为 `/` 的数据行。
- 表 5-2 只消费 `final_projection`；R4 不读取表 4 数据作为表 5-2 来源。
- 修正关系、公式和阈值由 R3 决定，R4 仅格式化并验证原始/最终值配对完整。

### 6.4 Word 附录 A 最终投影

附录 A 只使用 R3 最终投影，并保持技术表 8 列、管理表 5 列：

- 未实际修正对象按现有 Word 规则输出 D/A/K、结果记录、对象评分和单元得分。
- 实际修正的技术对象在 Word 中把 D、A、K 三列显示为 `/`。
- 该对象评分显示为四位小数最终分值加星号，例如 `0.5000*`。
- 单元得分显示最终数值，不加星号。
- 不在 Word 中增加星号说明。
- 数据库存留原始 D/A/K/Ra/Rk；XLSX 保留原始 D/A/K/Ra/Rk 和纯数值最终分值，不加星号。
- Ra/Rk 不得写入正文、附录 A XML、内容控件 tag、alt、题注或自定义属性。

R4 必须复用可嵌入式附录 A 渲染接口，在同一 OOXML package 内生成图片、题注、书签和 REF，禁止把独立附录 A DOCX 与完整报告直接拼接。

## 7. 草稿与最终版

### 7.1 草稿

`draft` 可用于 `draft|ready_for_review|confirmed` 项目：

- 必须在母版允许位置显示“草稿—未完成复核”，文件名增加“草稿”标识。
- 允许缺失和 warning，但不得伪造数值、结论、风险或附录 B 材料。
- 结构化问题清单随导出任务保存；正文占位只能使用 R4 统一草稿样式，不能保留母版 `XX`、填写示例或外层花括号。
- Word 字段刷新失败时可保留“字段未完成刷新”的草稿产物，但不得标记为 final 或 succeeded-final。

### 7.2 最终版前置闸门

`final` 必须同时满足：

- 项目为 `full_report` 且 `workflow_status=confirmed`。
- R0 模板包和六项资产哈希有效；17 分节、55 表和稳定锚点完整。
- 报告编号正式必填且全项目唯一；系统名称、被测单位、密评机构常量、编制人和报告日期等核心字段完整。
- R2 字段矩阵校验通过：人员/日期/份数/分支、表 2-3 产品数量、A-4 子系统等关系无错误。
- 已勾选密码算法均能在最终附录 A 结构化文字、表格或题注中匹配；不执行 OCR。附录 A 提及但未勾选仅 warning。
- R3 三投影、评分、修正、41 项统计、风险、综合得分、结论和正文均 current/confirmed，一致性校验无 error。
- 无未确认或过期派生块、未解决迁移映射或 Word 回收冲突。
- 图片、题注、书签、交叉引用和本地文件均存在且归属正确。
- 无 `XX`、填写说明、外层花括号、“待补充”、批注、未接受修订、外链、宏或 OLE。

附录 B 材料缺失只产生 warning；但已引用文件损坏、路径越权、人员/日期关系冲突属于 error。批注提示未审批或未满足不能单独阻断 final。

## 8. 文件名、版本和不可变快照

### 8.1 文件名

正式版文件名固定为：

```text
报告编号-被测单位-系统名称商用密码应用安全性评估报告版本号.docx
```

示例：`BGSMSP01202616401-中国建设银行宁夏区分行-特色系统商用密码应用安全性评估报告V1.0.docx`。

- 版本号是导出管理元数据，默认 `V1.0`，用户可手动调整，系统不自动递增。
- 版本号不写入首页或正文，不设置“客户复核版”等报告状态参数。
- 文件名进行 Windows 非法字符、保留名、尾随空格和最大长度校验；显示名称不回写项目字段。
- 允许重复导出同一版本，每次生成独立任务、快照和文件；不得覆盖历史成功导出。

### 8.2 数据模型

`report_export_jobs`：

- 字段：`job_uuid`、`project_id`、`export_mode`、`export_version`、`status`、`project_revision`、模板/R2/R3 哈希、快照 UUID、输出相对路径、DOCX 哈希、页数、错误码、时间戳。
- 约束：项目外键；状态只允许 `queued|running|succeeded|failed|cancelled`；成功任务必须有快照、路径和哈希。
- 索引：`(project_id, created_at)`、`(project_id, status)`、`UNIQUE(job_uuid)`。

`report_export_snapshots`：

- 字段：`snapshot_uuid`、`project_id`、`job_uuid`、`project_revision`、`export_mode`、`export_version`、`context_path`、`context_hash`、模板/R2/R3 版本与哈希、验证摘要、创建时间。
- 约束：与 job 一对一；成功后不可更新；附件只记录稳定 ID、哈希和相对路径，不复制大二进制。
- 索引：`UNIQUE(job_uuid)`、`(project_id, created_at)`。
- 删除语义：普通项目编辑和重复导出不得删除历史快照；删除项目时先按备份和审计策略处理，再级联数据库记录并安全删除项目内相对路径。

快照和 DOCX 均使用任务隔离临时目录、刷新落盘和原子改名。只有快照、文件、哈希、Word 回读全部成功后任务才为 `succeeded`；任一步失败不得覆盖或删除上次成功产物。

## 9. Word 字段刷新与结构回读

### 9.1 唯一刷新机制

1. 生成 OOXML 并设置 `w:updateFields=true`，但不把该标志视为刷新完成。
2. 保存到与输出文件不同的临时路径。
3. 启动本任务专用、不可见的 Microsoft Word 进程，禁用宏、外链更新和交互对话框。
4. 更新全部 story ranges、目录、图表目录、正文、页眉页脚和文本框字段。
5. 重新分页，更新目录页码，再保存并关闭文档。
6. 重新打开/回读 OOXML，校验字段、书签、缓存、页数和结构签名。

页码必须使用 R0 固化的 `PAGE + PAGEREF(report_body_end)`。不得生成或校验 `NUMPAGES`，也不得把 Word 计算的目录页码或分页缓存写回项目数据库。

### 9.2 失败处理

- Word 超时、COM 断开、保护视图、文件占用、弹窗、修复提示或字段回读失败均使 final 任务失败。
- 只结束本任务创建并记录 PID 的 Word 进程，不影响用户现有 Word 会话。
- final 禁止使用 LibreOffice/WPS 或未刷新缓存替代；无 Word 环境只允许生成明确标记的草稿。
- 可使用 Word 临时导出 PDF/PNG 做内部视觉 QA，但不公开、不归档、不作为产品 PDF 功能；任务结束后清理。

## 10. API 与 UI

### 10.1 API

```text
POST /api/projects/{project_uuid}/report-validations
GET  /api/projects/{project_uuid}/report-validations/latest
POST /api/projects/{project_uuid}/report-export-jobs
     {"mode":"draft|final","version":"V1.0","expected_project_revision":18}
GET  /api/report-export-jobs/{job_uuid}
GET  /api/report-export-jobs/{job_uuid}/issues
GET  /api/report-export-jobs/{job_uuid}/docx
```

所有问题返回 `severity`、`code`、`field_id|rule_id|table_id|block_id`、业务对象和原因。revision 冲突返回 409，模板/规则上下文不可用返回 503，业务错误返回 422 并保留完整问题列表。失败任务不得提供半成品下载地址。

### 10.2 UI

- 显示模板包、R2/R3 上下文版本、项目 revision、导出版本、快照时间和任务状态。
- 分别提供“生成草稿”和“生成最终版”；final 按钮前端预检查，后端仍独立执行全部闸门。
- 错误与 warning 分开显示并可定位章节、字段、表格、指标或对象。
- 任务运行中阻止同项目同 revision 的重复提交；允许新 revision 建立新任务，不覆盖旧任务。
- 只有成功任务显示 DOCX 下载；不提供 PDF 下载。

## 11. 可提交工作包

### WP-R4.1：稳定上下文与白名单骨架

- **输入**：R0 manifest、R2ReportContext、R3ProjectionContext。
- **改动**：建立不可变装配上下文、哈希、锚点解析、白名单修改器和 OOXML 统一 ID 分配器。
- **失败**：模板资产、revision、上下文哈希、锚点或业务 ID 不一致时写文件前失败。
- **测试**：上下文确定性、锚点缺失/重复、非白名单改动检测、关系/书签冲突、临时目录清理。
- **验收**：相同三方输入产生相同上下文哈希，装配器没有业务表查询和评分调用。
- **迁移/回滚**：仅新增装配服务和 feature flag，不影响旧附录 A 导出。
- **交接**：冻结渲染器输入 schema 和白名单差异报告格式。
- **建议提交**：`R4.1: 建立稳定装配上下文与母版白名单`。

### WP-R4.2：55 表与章节块渲染

- **输入**：manifest 55 表策略和稳定上下文。
- **改动**：为 55 个 `table_id` 显式注册固定表、重复行、矩阵、派生汇总、风险、附录 A/B 渲染策略；实现标量和正文块投影。
- **失败**：无渲染器、列 schema 不符、行对象无稳定 ID 或动态行越界时返回 table_id/对象错误。
- **测试**：55/55 覆盖、0/1/大量行、长文本、合并、表头重复、17 分节和固定结构签名。
- **验收**：只修改白名单，固定正文、样式、页眉页脚和非目标表格零漂移。
- **迁移/回滚**：渲染器可按 feature flag 回退，不原位修改模板包。
- **交接**：向附录 A 和 Word 刷新工作包提供结构通过的临时 DOCX。
- **建议提交**：`R4.2: 实现55表和章节块白名单渲染`。

## 12. 测试和阶段验收

- 契约测试：R0 manifest、R2/R3 schema/hash/revision 和错误码。
- 白名单测试：固定部件、文档非目标节点、分节、表头、样式和页眉页脚零漂移。
- 结构测试：17 分节、55 表、动态长表、图片关系、书签、SEQ/REF/PAGEREF。
- 投影测试：表 4 原始、表 5-1 差异、表 5-2/附录 A 最终，41 项统计和结论不在 R4 重算。
- 星号测试：实际修正对象 D/A/K 为 `/`、对象分四位小数加星号、单元分无星号、无说明。
- final 测试：核心字段、报告编号唯一、产品数量、算法匹配、过期/未确认、图片断链、占位符和 Word 刷新。
- 快照测试：同版本重复导出、不可变历史、哈希、失败原子性、跨项目下载。
- 桌面测试：有 Word/无 Word、安装态资源、用户 Word 会话隔离。

阶段完成必须满足：

- 55/55 表有显式策略；17 分节和固定结构符合 manifest。
- 证明所有修改均位于 manifest 白名单，固定正文、样式、页眉页脚关系无漂移。
- Word 中不存在 Ra/Rk；正文、附录 A、XLSX 和快照使用规定的同源投影。
- final 只消费 current/confirmed 的 R2/R3 上下文，不调用业务计算或数据库补值。
- `PAGE + PAGEREF(report_body_end)`、TOC、SEQ、REF、PAGEREF 经 Word 刷新并回读；不存在 `NUMPAGES` 依赖。
- 每次成功导出均有独立版本、不可变快照和文件哈希，文件名符合已确认规则。
- G4、全量检查、桌面安装态验收和独立代码审查通过。
