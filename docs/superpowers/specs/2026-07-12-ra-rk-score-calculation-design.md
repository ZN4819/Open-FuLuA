# Ra、Rk 参数与自动评分功能设计

## 目标

在 A-1 至 A-4 技术测评记录中增加 Ra、Rk 两个评分参数，并依据商用密码应用安全性评估打分表自动计算对象评分和单元得分。Ra、Rk 只用于工具内部评分，不导出到 Word。

## 需求基准

- Ra 选项为 `1`、`0.5`、`0.2`，默认值为 `1`。
- Rk 选项为 `1`、`1.2`，默认值为 `1`。
- Ra、Rk 仅适用于 A-1 至 A-4 技术测评记录。
- 对象评分由 D、A、K、Ra、Rk 自动计算并只读展示，禁止人工覆盖。
- D、A、K 全部为 `/` 时视为不适用，对象评分为 `/`。
- Ra、Rk 不写入 editable 或 final DOCX，也不从 DOCX 读取。

## 评分规则

只有 D、A、K 都已选择时才计算对象评分；任意一项为空时对象评分为空。

| 条件 | 对象评分 |
| --- | --- |
| D、A、K 全部为 `/` | `/` |
| D 不为 `√` | `0.0000` |
| D=`√`、A=`√`、K=`√` | `1.0000` |
| D=`√`、A 不为 `√`、K=`√` | `0.5 × Ra` |
| D=`√`、A=`√`、K 不为 `√` | `0.5 × Rk` |
| D=`√`、A 不为 `√`、K 不为 `√` | `0.25 × Ra × Rk` |

这里的“不为 `√`”同时包括 `×` 和 `/`。因此，只有 D、A、K 三项全部为 `/` 才判定整条记录不适用；其他包含 `/` 的组合仍按上表计算。

同一测评单元的单元得分为所有数值型对象评分的算术平均值，忽略评分为 `/` 的对象，结果保留四位小数。如果该单元所有对象均为 `/`，单元得分为 `/`；如果仍有对象评分为空，且没有可计算的数值评分，单元得分为空。

## 架构与职责

采用“前端即时计算、后端权威重算”的双层实现：

- 前端在用户修改 D、A、K、Ra 或 Rk 后立即计算对象评分和单元得分，使录入结果即时可见。
- 对象评分输入框改为只读输出，前端提交时不依赖用户输入的对象评分。
- 后端保存章节时忽略请求中的对象评分值，依据 D、A、K、Ra、Rk 重新计算对象评分，再统一计算单元得分。
- 前后端使用同一组明确规则和测试向量，避免计算语义漂移。
- 后端返回值和数据库持久化值均使用四位小数字符串；不适用使用 `/`，未满足计算条件使用空值。

## 数据模型与兼容策略

`metric_results` 表新增两个可空文本列：

- `ra TEXT`
- `rk TEXT`

数据库初始化与升级逻辑必须能够为现有数据库安全补列。兼容规则如下：

- 已有技术测评记录的 Ra、Rk 为空时，API 读取结果按 `1`、`1` 返回。
- 记录下一次保存时将默认值正式写入数据库。
- 新建技术测评记录直接使用 `ra="1"`、`rk="1"`。
- 管理测评记录不使用 Ra、Rk，数据库中保持空值。
- 章节复制、项目内章节导入和桌面数据迁移必须保留已存在的 Ra、Rk。
- 从 DOCX 导入创建的技术记录统一初始化为 `1`、`1`，管理记录保持空值。

后端请求模型只接受以下值：

- Ra：`1`、`0.5`、`0.2`
- Rk：`1`、`1.2`

技术记录缺省值由服务端补为 `1`；管理记录忽略传入的 Ra、Rk。范围外的值返回请求校验错误，不进入数据库。

## 前端交互

技术测评表列顺序调整为：

1. 测评单元
2. 测评对象
3. 结果记录
4. D
5. A
6. K
7. Ra
8. Rk
9. 对象评分
10. 单元得分
11. 操作

Ra 和 Rk 使用紧凑下拉框，新建行默认显示 `1`。对象评分使用只读 `output` 或只读输入控件，视觉上与可编辑字段区分。用户改变五个评分参数中的任意一个后，当前对象评分及所属测评单元得分立即刷新。

管理测评表不显示 Ra、Rk，现有符合情况和单元得分交互保持不变。

## Word 导入导出边界

DOCX 技术表结构保持现状，不增加 Ra、Rk 列：

- 模板 profile 的技术表列定义不变。
- DOCX 生成器继续只读取 D、A、K、对象评分和单元得分。
- editable DOCX 不为 Ra、Rk 创建内容控件。
- DOCX 解析器继续按现有 8 列技术表识别，不识别 Ra、Rk。
- DOCX 导入确认阶段为技术记录补 `Ra=1`、`Rk=1`。

这可以保证新增评分能力不改变现有 Word 模板、交叉引用、导入识别和 roundtrip 结构。

## 错误处理与数据一致性

- 前端只提供合法下拉选项，避免普通交互产生非法值。
- 后端仍执行独立枚举校验，防止绕过前端的非法请求。
- 后端保存时始终重新计算对象评分和单元得分，防止客户端提交陈旧或伪造分数。
- 数据库升级采用幂等补列逻辑，重复启动不重复修改结构。
- 读取旧数据库时不要求一次性批量改写所有记录，避免启动时产生不必要的大范围写入。

## 测试与验收

### 后端

- 数据库新建和旧库升级后均存在 `ra`、`rk` 列。
- 技术记录缺省读取为 `Ra=1`、`Rk=1`，保存后完成持久化。
- 管理记录不应用 Ra、Rk。
- 覆盖评分表的六个数值分支、全 `/` 分支和参数未填完整分支。
- Ra、Rk 非法值被拒绝。
- 单元平均分忽略 `/`，全部 `/` 时返回 `/`。
- 章节复制、章节导入和数据迁移保留 Ra、Rk。
- DOCX 导入的技术记录默认使用 `1`、`1`。

### 前端

- 新建技术记录默认显示 Ra、Rk 为 `1`。
- Ra、Rk 下拉选项与需求完全一致。
- 修改 D、A、K、Ra、Rk 会即时刷新只读对象评分。
- 对象评分不可手工编辑。
- 单元得分随对象评分即时更新，并忽略 `/`。
- 管理表不显示 Ra、Rk。

### DOCX 回归

- editable 和 final DOCX 的技术表仍为原 8 列。
- DOCX XML 中不存在 Ra、Rk 表头或内容控件。
- 现有 D、A、K、对象评分和单元得分导出保持正确。
- DOCX roundtrip 测试继续通过，导入记录的 Ra、Rk 为默认值。

### 全量回归

- 运行 `scripts/run_checks.ps1`。
- 运行桌面客户端 TypeScript 测试与依赖审计。
- 如数据库结构变化影响打包侧车，执行桌面开发模式冒烟测试。

## 非目标

- 不修改管理测评表评分规则。
- 不改变 DOCX 模板列数或样式。
- 不从外部 DOCX 推断 Ra、Rk。
- 不允许人工覆盖自动计算的对象评分。
- 不在本功能中增加安全层面得分、整体得分或权重分配能力。
