# 结果记录模板知识库实施方案

## 1. 背景

当前工具已经支持从 `附录A编写.docx` 只读抽取结果记录模板，并在测评表录入时通过“套用结果模板”下拉快速填充结果记录。现有模板资产保存在 `templates/appendix_a/record_templates.json`，适合作为系统初始模板，但不适合承载用户后续维护：

- 用户希望手动录入新的结果记录模板。
- 用户希望修改和删除自己维护的模板。
- 模板需要继续按 A-1 至 A-8、测评单元、测评对象和表格类型组织。
- 固定测评单元仍需要稳定，不应因为用户删除某条模板而丢失系统基准。

因此本专项将“结果记录模板”从静态 JSON 升级为本地模板知识库。第一版仍以 SQLite 为主，保留 JSON 作为系统模板种子，不引入额外服务或云端依赖。

## 2. 目标

本专项目标：

- 支持系统模板与用户模板并存。
- 支持用户新增、编辑、删除结果记录模板。
- 支持按章节、测评单元、测评对象和关键词筛选模板。
- 保持现有“套用模板后可继续手动修改”的录入体验。
- 保持固定测评单元来自系统基准模板，不被用户误删影响。
- 保持已有 `GET /api/record-templates` 接口兼容，避免一次性改动前端录入主流程。
- 后续可扩展导入、导出、全文搜索和模板推荐。

## 3. 设计原则

### 3.1 SQLite 作为运行时知识库

模板运行时数据落入 SQLite，原因：

- 与当前本地 Web 应用和项目数据存储方式一致。
- 支持用户增删改查和软删除。
- 可用事务保证模板维护过程稳定。
- 后续可以使用 SQLite FTS5 做轻量全文检索。

### 3.2 JSON 作为系统模板种子

`templates/appendix_a/record_templates.json` 继续保留：

- 作为从样本文档抽取的系统模板基准。
- 作为重新初始化、回归测试和版本追踪的只读来源。
- 应用启动或首次访问模板接口时，将系统模板同步到 SQLite。

用户模板不写回 JSON，避免污染样本文档抽取结果。

### 3.3 系统模板与用户模板分层

模板分为两类：

- `system`：来自样本文档，只能由系统种子同步更新，不允许用户直接删除。
- `user`：用户在界面中新增、复制或保存当前结果记录形成，可编辑、可禁用、可软删除。

系统模板用于固定测评单元提取和基础套用，用户模板用于补充真实项目经验。

### 3.4 软删除优先

用户删除模板时优先写入 `deleted_at`，而不是直接物理删除：

- 防止误删造成不可恢复。
- 方便后续增加“恢复模板”或审计记录。
- 避免历史项目中曾套用模板时无法追溯来源。

第一版 UI 可只展示未删除模板。

## 4. 数据模型

新增数据表 `record_templates`：

```text
record_templates
- id                INTEGER PRIMARY KEY
- template_key      TEXT UNIQUE NOT NULL
- source_type       TEXT NOT NULL       system | user
- section_code      TEXT NOT NULL       A-1 至 A-8
- table_type        TEXT NOT NULL       technical | management
- unit              TEXT NOT NULL       测评单元
- object_name       TEXT NOT NULL       测评对象
- title             TEXT NOT NULL       下拉展示标题
- record_text       TEXT NOT NULL       结果记录正文
- tags              TEXT NOT NULL       JSON 数组字符串
- source_row        INTEGER             系统模板来源行号，用户模板可为空
- is_enabled        INTEGER NOT NULL    1 启用，0 停用
- deleted_at        TEXT                软删除时间
- created_at        TEXT NOT NULL
- updated_at        TEXT NOT NULL
```

索引：

- `idx_record_templates_section_unit`：按章节和测评单元筛选。
- `idx_record_templates_source_type`：区分系统模板和用户模板。
- `idx_record_templates_enabled`：过滤启用模板。

后续全文检索阶段可新增 FTS5 虚表：

```text
record_templates_fts(title, unit, object_name, record_text, tags)
```

## 5. 服务层设计

新增或扩展 `backend/app/services/record_templates.py`：

- `load_record_template_library()`：继续读取并校验 JSON 系统模板。
- `ensure_system_record_templates_seeded()`：将 JSON 系统模板同步到 SQLite。
- `list_record_templates(section_code=None)`：从 SQLite 读取启用且未删除模板。
- `create_user_record_template(payload)`：新增用户模板。
- `update_user_record_template(template_key, payload)`：编辑用户模板。
- `delete_user_record_template(template_key)`：软删除用户模板。
- `copy_system_record_template(template_key)`：复制系统模板为用户模板后再编辑。

本阶段先完成数据库化和系统种子同步，CRUD 在后续阶段实现。

## 6. API 设计

保持现有读取接口：

```text
GET /api/record-templates
GET /api/record-templates?section_code=A-1
```

后续新增维护接口：

```text
POST   /api/record-templates
PUT    /api/record-templates/{template_key}
DELETE /api/record-templates/{template_key}
POST   /api/record-templates/{template_key}/copy
```

读取接口响应继续包含现有字段：

```json
{
  "id": "A-1-001",
  "section_code": "A-1",
  "table_type": "technical",
  "unit": "身份鉴别",
  "object_name": "XX机房",
  "title": "身份鉴别 / XX机房",
  "record_text": "测评验证记录：...",
  "source_row": 1
}
```

后续可扩展返回：

```json
{
  "source_type": "system",
  "tags": [],
  "is_enabled": true,
  "updated_at": "..."
}
```

前端未使用扩展字段时保持兼容。

## 7. 前端交互设计

### 7.1 录入区

测评表中保留现有“套用本单元模板”下拉：

- 默认只显示当前章节、当前测评单元下的模板。
- 系统模板和用户模板分组展示。
- 套用后写入结果记录文本域，用户仍可继续编辑。
- 不把模板与测评行强绑定，避免模板更新影响已填写内容。

### 7.2 模板管理入口

新增模板管理面板或独立页面：

- 按章节筛选。
- 按测评单元筛选。
- 关键词搜索标题、测评对象和正文。
- 新增模板。
- 编辑用户模板。
- 删除用户模板。
- 从系统模板复制为用户模板。
- 从当前测评行保存为新模板。

### 7.3 固定测评单元规则

固定测评单元继续优先来自系统模板：

- 系统模板中的测评单元构成 A-1 至 A-8 的默认分组。
- 用户模板可补充新的测评对象和正文模板。
- 若后续确需新增自定义测评单元，应作为单独功能开关处理，避免影响基准导出结构。

## 8. 数据迁移与兼容

迁移策略：

1. 应用启动时 `init_db()` 创建 `record_templates` 表。
2. 首次调用模板服务时读取 JSON。
3. 以 JSON 中模板 `id` 作为 `template_key` 写入或更新 `system` 模板。
4. 查询模板时从 SQLite 返回，兼容现有接口字段。

兼容要求：

- 不修改原始样本文档。
- 不删除 `record_templates.json`。
- 不改变已有项目数据结构。
- 现有前端套用模板、固定测评单元分组继续可用。
- 现有测试需要继续验证 117 条系统模板覆盖 A-1 至 A-8。

## 9. 测试策略

后端测试：

- 系统模板 JSON 校验测试。
- 数据库初始化测试。
- 系统模板种子导入测试。
- 按章节筛选测试。
- 系统模板 ID 稳定性测试。
- 后续 CRUD 测试：新增、编辑、软删除、复制系统模板。

前端测试或手动验收：

- 测评表模板下拉仍可显示模板。
- 固定测评单元仍正常展示。
- 用户模板新增后可在下拉中出现。
- 删除用户模板后不再出现在下拉中。
- 系统模板不可直接删除。

回归测试：

- `scripts/run_checks.ps1`。
- 后端单元测试。
- 前端构建。
- 样本文档只读分析保持稳定。

## 10. 风险与控制

- 风险：系统模板重复导入。
  - 控制：使用 `template_key` 唯一约束和 upsert。

- 风险：用户删除模板导致固定测评单元消失。
  - 控制：固定测评单元优先来自 `system` 模板；系统模板不允许用户删除。

- 风险：模板正文包含旧图号。
  - 控制：继续复用现有 JSON 校验，确保旧图号已替换为 `[插入图片引用]`。

- 风险：前端一次性改动过大。
  - 控制：先保持读取接口兼容，再逐步增加模板管理 UI。
