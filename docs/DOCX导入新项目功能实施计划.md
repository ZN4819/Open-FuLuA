# DOCX 导入新项目功能实施计划

## 1. 总体策略

本专项命名为 `DI`，含义是 `DOCX Import`。实施采用“先可解析、再可预览、再可确认创建项目、最后补齐前端体验和回归”的顺序。

每个阶段完成后需要：

- 更新相关项目文档。
- 运行阶段相关测试或统一检查脚本。
- 提交并推送到远程仓库 `https://github.com/ZN4819/FuLuA`。
- 涉及数据库、解析器、API 或前端主流程的重要阶段使用独立 `codex/` 分支。

推荐阶段：

1. DI-1：导入数据模型、任务表和解析结果模型。
2. DI-2：DOCX 包读取与文档结构扫描。
3. DI-3：核心表格解析。
4. DI-4：图片、题注和引用解析。
5. DI-5：导入预览 API。
6. DI-6：确认导入并创建新项目。
7. DI-7：前端导入向导。
8. DI-8：端到端回归、文档和验收。

## 2. DI-1：数据模型与导入任务基座

### 2.3 验收标准

## 3. DI-2：DOCX 包读取与文档结构扫描

### 3.1 目标

能够安全打开上传的 DOCX，识别是否具备附录A结构，并生成章节/表格候选预览。

### 3.2 任务

- 实现 DOCX zip 安全读取，拒绝非 DOCX、损坏包和缺少 `word/document.xml` 的文件。
- 读取 `word/document.xml` 和 `word/_rels/document.xml.rels`。
- 按 body 顺序抽取段落、表格和分节信息。
- 识别总标题 `附录A测评结果记录`。
- 识别 A-1 至 A-8 章节标题和表题。
- 识别核心表格候选，记录表格 XML 位置、章节 code、表格类型和置信度。
- 输出结构扫描结果，不写项目数据。

### 3.3 验收标准

- 本工具导出的 editable/final DOCX 可识别为附录A候选。
- 非 DOCX 或损坏 DOCX 返回清晰错误。
- 缺少章节、缺少表题或表格数量异常会生成导入问题。

### 3.4 测试

- 使用生成器动态生成 DOCX fixture 并扫描。
- 损坏文件测试。
- 缺少 `document.xml` 测试。
- 章节标题和表题识别测试。

### 3.5 完成记录（2026-06-22）

- 已新增 `backend/app/services/docx_importer/package.py`，支持安全读取 `.docx` OpenXML 包、拒绝非 DOCX/损坏包/缺少 `word/document.xml` 的文件，并读取 `word/_rels/document.xml.rels` 与 `word/media/*` 清单。
- 已新增 `backend/app/services/docx_importer/document.py`，支持按 Word body 顺序抽取段落和表格，识别“附录A测评结果记录”总标题、A-1 至 A-8 章节标题、表题和核心表候选。
- 已新增结构扫描结果模型 `DocxStructureScan` 和核心表候选模型 `DocxTableCandidate`。
- 已补充 6 项 DI-2 单元测试，覆盖 editable/final 导出 DOCX 扫描、关系和媒体读取、非 DOCX/损坏 DOCX、缺少 `document.xml`、部分章节缺失的问题报告。
- 已通过统一检查脚本 `scripts/run_checks.ps1`，当前自动化测试为 69 项。

## 4. DI-3：核心表格解析

### 4.1 目标

解析 A-1 至 A-8 的核心测评表，恢复测评行和评分结果。

### 4.2 任务

- 基于 `template_profile.json` 建立技术表和管理表列映射。
- 实现 Word 表格 cell 文本归一化。
- 支持 `vMerge` 纵向合并，继承测评单元文本。
- 支持 `gridSpan` 和技术表两行表头。
- 解析技术表字段：
  - 测评单元。
  - 测评对象。
  - 结果记录。
  - D/A/K。
  - 测评对象得分。
  - 测评单元得分。
- 解析管理表字段：
  - 测评单元。
  - 测评对象。
  - 结果记录。
  - 符合情况。
  - 测评单元得分。
- 支持从内容控件中读取选中值。
- 生成行级问题：空测评对象、非法 D/A/K、非法符合情况、疑似错列表格。

### 4.3 验收标准

- 本工具导出的 DOCX 再解析后，测评单元、测评对象、结果记录和评分核心字段一致。
- 合并测评单元列能够正确展开到多行。
- 空行不会导入。

### 4.4 测试

- 技术表解析测试。
- 管理表解析测试。
- 合并单元格测试。
- 内容控件文本测试。
- 空行过滤测试。

### 4.5 完成记录（2026-06-22）

- 已新增 `parse_docx_core_tables` 核心表格解析入口，返回后续 DI-6 可写入项目的章节和测评行结构。
- 已支持技术表和管理表列映射，恢复测评单元、测评对象、结果记录、D/A/K、符合情况、测评对象得分和测评单元得分。
- 已支持 `vMerge` 纵向合并测评单元继承、`gridSpan` 展开、内容控件实际文本读取、技术表两行表头跳过和空白占位行过滤。
- 已生成行级导入问题：空必填单元格、非法 D/A/K、非法符合情况。
- 已新增 5 项 DI-3 单元测试，覆盖 editable/final 反解析、合并单元格、内容控件文本、空行过滤和非法选项提示；当前自动化测试共 74 项。

## 5. DI-4：图片、题注和引用解析

### 5.1 目标

恢复证据图片、图片题注、章节内排序和结果记录中的图片引用位置。

### 5.2 任务

- 从 `w:drawing` 解析 `r:embed` 图片关系。
- 根据 rels 找到 `word/media/*` 并复制到导入任务临时目录。
- 用 Pillow 读取图片尺寸、DPI 和建议显示尺寸。
- 识别图题注：`图A-x-y`。
- 将图题注映射到图片和章节。
- 解析 REF 字段和可见图号文本。
- 在结果记录中将图号引用替换为临时 token：`[[FIG:import:A-1-1]]`。
- 生成图片和引用问题：无题注、重复图号、引用找不到图片、图片格式不支持。

### 5.3 验收标准

- 本工具导出的图片和题注可被恢复。
- 图片章节、排序和题注基本一致。
- 结果记录中原引用位置被替换为临时 token。
- 无法映射的引用不会静默丢失。

### 5.4 测试

- 图片提取测试。
- 图题注解析测试。
- 图号排序测试。
- REF 字段映射测试。
- 可见图号文本映射测试。
- 断链引用问题测试。

## 6. DI-5：导入预览 API

### 6.1 目标

打通“上传 DOCX -> 解析 -> 返回导入预览”的后端接口。

### 6.2 任务

- 新增 `POST /api/imports/docx`。
- 新增 `GET /api/imports/{job_id}`。
- 保存上传文件到 `storage/imports/{job_id}/source.docx`。
- 调用 DI-2 至 DI-4 解析器生成 `parsed.json`。
- 返回章节、行数、图片数、引用数和问题清单。
- 根据问题严重程度决定是否允许确认创建项目。
- 限制文件扩展名和大小。

### 6.3 验收标准

- 上传本工具导出的 DOCX 后能获得预览结果。
- API 返回的章节统计与解析数据一致。
- 错误文件不会创建项目。
- 临时文件路径不会暴露真实绝对路径。

### 6.4 测试

- 上传成功 API 测试。
- 非 DOCX 上传失败测试。
- 解析错误状态测试。
- 导入预览问题统计测试。

## 7. DI-6：确认导入并创建新项目

### 7.1 目标

用户确认预览后，后端将解析结果写入正式项目数据模型。

### 7.2 任务

- 新增 `POST /api/imports/{job_id}/project`。
- 支持传入项目名称覆盖值。
- 在数据库事务中创建项目、章节、测评行、评分、证据图片和交叉引用。
- 将临时图片复制到 `storage/uploads/{project_id}/{section_code}/`。
- 将 `[[FIG:import:A-x-y]]` 替换为真实 `[[FIG:imageId]]`。
- 写入 `cross_references`。
- 失败时回滚数据库并清理新项目运行时文件。
- 导入成功后更新 job 的 `created_project_id` 和状态。

### 7.3 验收标准

- 确认导入后项目列表出现新项目。
- 新项目可打开，章节详情能读取。
- 图片、题注、引用 token 和交叉引用可用。
- 导入后的项目能通过现有保存、校验和 DOCX 导出流程。

### 7.4 测试

- 确认导入创建项目测试。
- 图片复制和 evidence_images 写入测试。
- 临时 token 替换测试。
- 事务回滚测试。
- 导入后校验服务测试。

## 8. DI-7：前端导入向导

### 8.1 目标

在前端提供完整可用的“导入 DOCX 创建项目”体验。

### 8.2 任务

- 扩展 `frontend/src/api/client.ts`：新增导入 API 类型和函数。
- 首页新增导入入口，不与新建项目和已有项目列表混淆。
- 新增导入面板或组件：
  - 选择 DOCX。
  - 上传并解析。
  - 显示解析状态。
  - 显示预览摘要。
  - 显示问题清单。
  - 编辑项目名称。
  - 确认创建项目。
- 创建成功后刷新项目列表并自动打开项目。
- 窄屏下保证导入入口和问题清单可读。

### 8.3 验收标准

- 用户可以在首页上传 DOCX。
- 有错误时能看到原因，确认按钮禁用。
- 只有警告时可确认创建项目。
- 创建成功后自动进入新项目。
- 不影响原有新建项目和打开已有项目流程。

### 8.4 测试

- 导入入口渲染测试。
- 错误/警告状态文案测试。
