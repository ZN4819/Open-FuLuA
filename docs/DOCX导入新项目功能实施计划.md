# DOCX 导入新项目功能实施计划

## 1. 总体策略

本专项命名为 `DI`，含义是 `DOCX Import`。实施采用“先可解析、再可预览、再可确认创建项目、最后补齐前端体验和回归”的顺序。

每个阶段完成后需要：

- 更新相关项目文档。
- 运行阶段相关测试或统一检查脚本。
- 提交并推送到模板仓库 `https://github.com/ZN4819/Open-FuLuA.git`。
- 涉及数据库、解析器、API 或前端主流程的重要阶段使用独立 `codex/` 分支。

推荐阶段：

1. DI-1：导入数据模型、任务表和解析结果模型。
2. DI-2：DOCX 包读取与文档结构扫描。
3. DI-3：核心表格解析。
4. DI-4：图片、题注和引用解析。
5. DI-5：导入预览 API。
6. DI-6：确认导入并创建新项目。
7. DI-7：前端导入向导。
8. DI-8：端到端回归、文档和验收。

## 3. DI-2：DOCX 包读取与文档结构扫描

### 3.1 目标

能够安全打开上传的 DOCX，识别是否具备附录A结构，并生成章节/表格候选预览。

### 3.2 任务

- 实现 DOCX zip 安全读取，拒绝非 DOCX、损坏包和缺少 `word/document.xml` 的文件。
- 读取 `word/document.xml` 和 `word/_rels/document.xml.rels`。
- 按 body 顺序抽取段落、表格和分节信息。
- 识别总标题 `附录A测评结果记录`。
- 识别 A-1 至 A-8 章节标题和表题。
- 识别核心表格候选，记录表格 XML 位置、章节 code、表格类型和置信度。
- 输出结构扫描结果，不写项目数据。

### 3.3 验收标准

- 本工具导出的 editable/final DOCX 可识别为附录A候选。
- 非 DOCX 或损坏 DOCX 返回清晰错误。
- 缺少章节、缺少表题或表格数量异常会生成导入问题。

### 3.4 测试

- 使用生成器动态生成 DOCX fixture 并扫描。
- 损坏文件测试。
- 缺少 `document.xml` 测试。
- 章节标题和表题识别测试。

## 5. DI-4：图片、题注和引用解析

### 5.1 目标

恢复证据图片、图片题注、章节内排序和结果记录中的图片引用位置。

### 5.2 任务

- 从 `w:drawing` 解析 `r:embed` 图片关系。
- 根据 rels 找到 `word/media/*` 并复制到导入任务临时目录。
- 用 Pillow 读取图片尺寸、DPI 和建议显示尺寸。
- 识别图题注：`图A-x-y`。
- 将图题注映射到图片和章节。
- 解析 REF 字段和可见图号文本。
- 在结果记录中将图号引用替换为临时 token：`[[FIG:import:A-1-1]]`。
- 生成图片和引用问题：无题注、重复图号、引用找不到图片、图片格式不支持。

### 5.3 验收标准

- 本工具导出的图片和题注可被恢复。
- 图片章节、排序和题注基本一致。
- 结果记录中原引用位置被替换为临时 token。
- 无法映射的引用不会静默丢失。

### 5.4 测试

- 图片提取测试。
- 图题注解析测试。
- 图号排序测试。
- REF 字段映射测试。

- 已支持从 `w:drawing` / `a:blip` 解析 `r:embed`，通过 `document.xml.rels` 找到 `word/media/*`，并将 PNG/JPEG 复制到导入任务目录。
