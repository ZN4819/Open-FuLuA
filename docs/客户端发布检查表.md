# Windows 客户端发布检查表

## 版本与触发

- [ ] 版本号符合语义版本格式，标签为 `v主版本.次版本.修订版本`。
- [ ] 发布来源是版本标签或人工发布任务，不是 PR 或普通分支推送。
- [ ] `package.json` 版本与 `latest.yml` 版本一致。

## 签名门槛

- [ ] 稳定版同时配置证书和证书密码。
- [ ] Setup、`win-unpacked/FuLuA.exe` 与 `win-unpacked/resources/backend/fulua-backend.exe` 的 Authenticode 状态均为 `Valid`。
- [ ] 缺少任一签名凭证时，发布明确标记为预发布。

## 测试与产物

- [ ] 后端、前端、桌面和发布契约测试通过。
- [ ] 桌面依赖审计无 high 或 critical 漏洞。
- [ ] 产物包含 Setup、`latest.yml`、blockmap、`SHA256SUMS.txt` 和 workflow 动态生成的发布检查报告；仓库中的本表只用于发布前核对，不作为已完成证据上传。
- [ ] `latest.yml` 中的安装包路径、版本和 SHA-512 已按实际 Setup 校验。
- [ ] 安装包资源不包含数据库、storage、日志、备份、迁移目录、测试、fixture、DOCX 或 source map。

## 恢复验收

- [ ] 更新错误、业务忙、用户取消、备份失败和侧车停止失败均不会开始安装。
- [ ] 异常关闭时，业务页面在数据库完整性检查前不会加载。
- [ ] 升级失败可以从对应的升级前备份恢复；恢复失败会保留现场和待恢复标记。
