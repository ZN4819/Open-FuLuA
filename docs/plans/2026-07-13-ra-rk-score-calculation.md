# Ra、Rk 参数与自动评分功能实施计划

## 目标

为 A-1 至 A-4 技术测评记录增加 Ra、Rk 参数，依据评分表自动计算只读对象评分和单元得分，同时保持现有 Word 技术表为 8 列，不向 Word 导入或导出 Ra、Rk。

## 实施边界

- Ra 允许 `1`、`0.5`、`0.2`，默认 `1`。
- Rk 允许 `1`、`1.2`，默认 `1`。
- D/A/K 只接受 `√`、`×`、`/` 或未填写状态。
- 技术对象评分和单元得分由后端权威重算；旧客户端提交的分数字段继续兼容，但不能覆盖计算结果。
- 任一对象未完成时整个单元得分留空；数值平均时忽略 `/`；全部为 `/` 时单元得分为 `/`。
- 管理章节、Word 模板列定义、安全层面得分和总分计算不在本阶段修改范围内。

## 实施阶段

### 1. 统一评分内核

- 在后端建立唯一评分服务，集中处理默认系数、对象评分、单元平均和四位小数格式。
- 为历史脏数据提供宽松读取：保留原始非法值供校验报告，评分留空，不导致项目无法打开。
- 前端建立无运行时依赖的同规则纯函数，用相同测试向量验证即时预览。

### 2. 数据库与接口

- SQLite schema 升至 2，为 `metric_results` 幂等增加 `ra`、`rk`。
- 同步后端和桌面端目标 schema 版本。
- API 读模型保留字符串兼容，写模型对 D/A/K、Ra、Rk 执行枚举校验。
- 技术记录保存前重算并持久化；管理记录将 Ra/Rk 保持为空。
- 旧记录读取时补默认系数并重算，下一次保存时再落盘，不执行启动时批量改写。

### 3. 页面录入

- 技术表扩展为 11 列，在 D/A/K 后增加 Ra、Rk 下拉框。
- 对象评分改为只读输出；修改五个评分参数后即时刷新对象评分和单元得分。
- 单元得分始终基于该单元全部对象计算，筛选仅影响行显示，不改变分数。
- 管理表保持现有字段和交互。

### 4. 导入、导出与桌面兼容

- DOCX 生成器使用权威重算结果，但模板 profile 和技术表 8 列结构不变。
- DOCX 确认导入时为技术记录补 `Ra=1`、`Rk=1`，忽略 Word 中旧分数并按 D/A/K 重算。
- 章节复制保留 Ra/Rk，并在目标单元中重新计算完整单元分。
- 桌面验收采用非默认向量 `D=√、A=×、K=×、Ra=0.2、Rk=1.2`，期望对象评分和单元得分均为 `0.0600`。

## 验收标准

- 后端公式测试覆盖全部分支、默认值、非法值、全 `/`、未完成单元和舍入。
- schema 1 数据库可幂等升级至 schema 2，旧数据不在读取时被静默改写。
- 前端构建和独立评分测试通过，对象评分无法手工编辑。
- editable、final DOCX 技术表仍为 8 列，不包含 Ra/Rk 表头或内容控件。
- DOCX roundtrip、数据迁移、运行时恢复、桌面 TypeScript 测试和全量项目检查通过。
- 阶段提交只包含相关文件，不提交 `.codex/`、评分表源文件、缓存或生成物。
