# A-5 至 A-8 固定测评对象实施记录

## 规则来源

固定测评对象依据只读样本文档 `附录A编写.docx` 的 A-5 至 A-8 核心测评表确定。原始样本文档不参与运行时写入，也不在本次变更中修改。

## 固定规则

- A-5“管理制度”：每个测评单元固定为“管理体系（包括安全管理制度类文档、密码应用方案、密钥管理制度及策略类文档、操作规程类文档、记录表单类文档、系统相关人员）”。
- A-6“人员管理”：每个测评单元固定为“管理体系（包括安全管理制度类文档、记录表单类文档、系统相关人员）”。
- A-7“建设运行”：每个测评单元固定包含以下两个对象：
  1. “密码应用方案、密钥管理制度及策略类文档、密码实施方案、商用密码应用安全性评估报告、密码应用安全管理制度、攻防对抗演习报告、整改文档”；
  2. “管理体系（包括安全管理制度类文档、记录表单类文档、系统相关人员）”。
- A-8“应急处置”：每个测评单元固定为“管理体系（包括密码应用应急处置方案、应急处置记录类文档、安全事件发生情况及处置情况报告、系统相关人员）”。

## 产品行为

- 固定对象统一配置在 `templates/appendix_a/template_profile.json`，前端显示和后端保存使用同一规则源。
- 管理章节界面直接显示固定对象，不提供修改、新增或删除正常固定对象的入口。
- 打开旧数据时，界面通过独立的初始化路径补齐固定对象，不写入撤销栈；章节会明确提示保存后再落盘。
- 保存旧数据时，后端将旧对象名归一为固定值；A-7 缺少第二对象时自动补齐空白记录，不覆盖已有结果记录，并优先保留已经准确匹配固定对象的历史记录。
- 同一测评单元的对象行超过固定数量时拒绝保存，防止静默丢失历史内容。界面保留“删除多余对象”入口供用户主动清理旧数据。
- 管理章节采用固定对象，目标章节已有数据时禁止继续追加导入，避免旧对象名绕过数量约束；空目标章节和 DOCX 创建新项目仍会按固定规则归一。
- DOCX 导出继续使用结构化章节数据，不新增字段，也不改变管理表的 5 列结构。

## 验收标准

- 模板 profile 能精确返回四个章节的固定对象列表。
- A-5、A-6、A-8 的任意旧对象名保存后归一为章节固定对象。
- A-7 每个已录入测评单元保存后恰好包含两个固定对象，已有记录保留，缺少的第二行为空白记录。
- 超出固定数量的管理对象返回明确的 400 错误。
- 前端类型检查、后端测试、前端契约测试和项目全量检查通过。
