# 三类结果记录模板改造实施方案

## 1. 背景

当前结果记录模板知识库已经支持系统模板和用户模板并存，用户可以新增、编辑、删除、复制、导入和导出模板。但新的产品要求发生变化：

- 不再区分系统模板和用户模板。
- 每个测评单元只保留三类固定模板：
  - 符合/部分符合模板。
  - 不符合模板。
  - 不适用模板。
- 用户只能修改这三类模板的内容。
- 不允许删除模板。

该变化会把“模板库”从自由维护的知识库，改造为“按测评单元固定三槽位的可编辑标准话术”。核心目标是降低模板选择复杂度，让用户在每个测评单元下只需要判断测评结论类型，再按实际测评对象微调正文。

## 2. 改造目标

### 2.1 产品目标

- 在任意章节、任意固定测评单元下，模板数量固定为三类。
- 录入结果记录时，用户从三类模板中选择一种套用。
- 模板管理界面按章节和测评单元展示三类模板，不再展示“系统模板 / 我的模板”分组。
- 用户可修改三类模板的标题、正文、标签或说明，但不能新增第四类，也不能删除任何一类。
- 模板正文继续支持 `[插入图片引用]` 占位，套用后用户可通过图片引用下拉替换为真实 `[[FIG:imageId]]` token。
- 已有项目的测评行、图片、引用、评分和导出行为不应受影响。

### 2.2 技术目标

- 将运行时模板模型从“多条来源模板”改为“每个测评单元三条固定槽位”。
- 保留当前固定测评单元来源，不因用户修改模板而改变章节测评单元列表。
- 提供明确的数据迁移策略，避免当前模板数据直接丢失。
- 前端和后端 API 不再暴露删除模板能力。
- 自动化测试覆盖种子初始化、三槽位唯一性、编辑权限、不可删除、套用模板、导出回归。

## 3. 术语与分类

### 3.1 模板类型

建议在代码中使用稳定英文枚举，界面显示中文名称：

| 枚举值 | 界面名称 | 适用场景 |
| --- | --- | --- |
| `compliant` | 符合/部分符合模板 | 测评对象适用该测评单元，且结论为符合或部分符合。 |
| `non_compliant` | 不符合模板 | 测评对象适用该测评单元，但未满足要求。 |
| `not_applicable` | 不适用模板 | 测评对象不适用该测评单元，需要说明不适用原因。 |

“符合/部分符合模板”合并为一类，是为了适配当前结果记录主要由用户结合 D/A/K、对象评分和符合情况进行最终调整的工作方式。套用后仍允许用户手动改正文。

### 3.2 模板粒度

新模板粒度建议固定为：

```text
section_code + unit + template_type
```

即每个章节的每个测评单元固定三条模板，不再以测评对象区分模板。测评对象名称作为测评行字段保留，模板正文可使用通用表述，例如“经核查，{测评对象} ...”。第一版可以只把 `{测评对象}` 作为普通文本提示，不强制实现变量替换；后续如需要再增加变量渲染。

## 4. 数据模型方案

### 4.1 推荐新增表

建议新增独立表 `record_template_slots`，而不是直接复用现有 `record_templates` 表。原因是旧表承载了历史系统/用户模板和导入导出逻辑，直接改造风险较高；新增表可以降低迁移风险，并保留旧数据作为备份或回滚依据。

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键。 |
| `section_code` | text | A-1 至 A-8。 |
| `table_type` | text | technical 或 management。 |
| `unit` | text | 测评单元名称。 |
| `template_type` | text | `compliant`、`non_compliant`、`not_applicable`。 |
| `title` | text | 模板标题，默认等于中文类型名。 |
| `record_text` | text | 当前可编辑模板正文。 |
| `default_record_text` | text | 初始化默认正文，用于恢复默认。 |
| `tags` | text | JSON 字符串，可选。 |
| `is_customized` | integer | 用户是否修改过。 |
| `created_at` | text | 创建时间。 |
| `updated_at` | text | 更新时间。 |

唯一约束：

```text
unique(section_code, unit, template_type)
```

### 4.2 初始化规则

- 固定测评单元继续从现有模板种子或 profile 派生。
- 每个测评单元初始化三条模板。
- `compliant` 的默认正文可以优先从当前同章节同测评单元的系统模板中抽取一条代表性模板，清理具体机房/系统名称后作为初始话术。
- `non_compliant` 和 `not_applicable` 第一版可使用通用默认正文，后续由用户在界面中调整。
- 初始化必须幂等：重复启动后不能重复插入。

### 4.3 旧数据处理

旧的 `record_templates` 数据不建议立即删除。

推荐策略：

- 保留旧表和旧 JSON 种子，作为迁移备份和历史参考。
- 新接口只读取 `record_template_slots`。
- 旧的用户模板在迁移前可导出为 JSON 备份。
- 若后续确认不再需要旧模板，再在单独清理阶段移除旧 API 和前端旧逻辑。

## 5. API 方案

### 5.1 新接口

建议新增一组槽位模板接口：

```text
GET  /api/record-template-slots?section_code=A-1
GET  /api/record-template-slots?section_code=A-1&unit=身份鉴别
PUT  /api/record-template-slots/{slot_id}
POST /api/record-template-slots/{slot_id}/reset
GET  /api/record-template-slots/export
POST /api/record-template-slots/import-preview
POST /api/record-template-slots/import
```

其中：

- `GET` 返回每个测评单元下三类模板。
- `PUT` 只允许修改标题、正文、标签或说明字段。
- `reset` 可选，用于恢复默认正文，不属于删除。
- 导入导出从“用户模板备份”调整为“三类模板配置备份”。

### 5.2 禁止能力

以下能力在新模型中不再开放：

- 新增任意模板。
- 删除模板。
- 复制系统模板。
- 按系统模板/用户模板分组。
- 通过来源类型筛选模板。

旧接口可以先保留但前端不再使用；等新模型稳定后再进入兼容清理阶段。

## 6. 前端方案

### 6.1 测评表录入区

当前每个测评行的模板下拉改为固定三项：

```text
套用模板
符合/部分符合模板
不符合模板
不适用模板
```

交互规则：

- 下拉项来自当前测评单元的三类模板。
- 选择模板后，将该模板正文写入当前测评行结果记录。
- 若正文中有 `[插入图片引用]`，仍由现有图片引用下拉负责替换。
- 套用后用户仍可手动修改结果记录，不回写模板。

### 6.2 模板管理面板

模板管理面板从“模板列表 + 新增/编辑/删除/复制”改为“章节/测评单元 + 三类模板编辑器”。

建议布局：

- 左侧或顶部：章节选择、测评单元选择。
- 主体：三个固定编辑卡片或三个标签页：
  - 符合/部分符合。
  - 不符合。
  - 不适用。
- 每个卡片包含：标题、正文、标签、保存、恢复默认。
- 不显示删除按钮。
- 不显示新增模板按钮。
- 不显示系统模板/我的模板徽标。

### 6.3 导入导出

若继续保留备份能力，应调整文案：

- “导出模板配置”。
- “导入模板配置”。
- 导入只更新已有槽位，不创建第四类模板。
- 导入前校验每条数据是否能匹配到现有 `section_code + unit + template_type`。
- 无法匹配的项在预览中标记为错误或跳过。

## 7. DOCX 与项目数据影响

DOCX 导出不直接依赖模板来源，因此改造后应保持：

- 测评行数据结构不变。
- 结果记录仍是普通文本和 `[[FIG:imageId]]` token。
- 图片、题注、交叉引用、D/A/K、符合情况和评分导出逻辑不变。
- 固定测评单元仍由章节模板基准提供，导出表格合并逻辑不变。

## 8. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 旧用户模板被隐藏后用户找不到历史话术 | 用户迁移成本上升 | 改造前提供旧模板 JSON 导出，文档说明旧数据保留位置。 |
| 三类模板默认正文质量不足 | 用户需要大量手动调整 | `compliant` 优先从现有模板抽取，另外两类提供可编辑通用模板。 |
| 前端仍调用旧新增/删除接口 | 行为与新规则冲突 | 前端移除入口，后端新接口不提供删除；测试确认无删除按钮。 |
| 导入文件创建非法模板类型 | 数据污染 | 导入预览强校验三类枚举和唯一槽位。 |
| 固定测评单元来源混乱 | 影响表格录入和导出 | 固定单元仍从系统基准派生，不由用户修改模板决定。 |

## 9. 验收标准

- 任意测评单元下模板下拉只显示三类模板。
- 模板管理面板不再出现系统模板/用户模板分组。
- 模板管理面板不再出现新增、删除、复制入口。
- 用户可编辑三类模板并保存，刷新后仍能读取修改结果。
- 用户不能删除模板；后端也不提供删除槽位接口。
- 每个测评单元始终存在三类模板，重复初始化不产生重复数据。
- 现有项目保存、图片引用、校验、预览和 DOCX 导出回归通过。

## 10. 推荐结论

建议采用“新增 `record_template_slots` 表 + 新接口 + 前端切换三类模板”的渐进式改造。这样可以保护当前已完成的模板知识库成果，同时满足新规则：不再区分系统模板/用户模板，模板固定为三类，用户只能修改不能删除。
## 11. 当前进度

当前进度（2026-06-22）：T3-1 已完成。后端已新增 `record_template_slots` 运行时表，按 `section_code + unit + template_type` 为每个固定测评单元生成 `compliant`、`non_compliant`、`not_applicable` 三类槽位；旧 `record_templates` 表和 JSON 种子继续保留，作为后续 API 与前端切换前的迁移基线。下一阶段进入 T3-2，新增三类模板 API 并隔离旧接口。
