# 三类结果记录模板改造实施计划

## 1. 实施策略

本专项命名为 `T3`，含义是“三类结果记录模板”。实施原则：

- 先新增三类模板模型，不直接删除旧模板表和旧数据。
- 前端先切换到三类模板体验，再考虑清理旧接口。
- 每个阶段完成后更新相关文档、运行测试、提交并推送远程仓库。
- 涉及数据库、API、前端主流程的重要阶段使用独立分支。

推荐阶段：

1. T3-1：三类模板数据模型与种子初始化。
2. T3-2：三类模板 API 与旧接口兼容隔离。
3. T3-3：测评表录入区三类模板套用。
4. T3-4：模板管理面板改造为三类模板编辑器。
5. T3-5：导入导出与备份恢复调整。
6. T3-6：回归、文档和验收。

## 2. T3-1：数据模型与种子初始化

### 2.1 目标

建立 `record_template_slots` 运行时表，保证每个章节、每个固定测评单元都有三条固定模板。

### 2.2 任务

- 新增数据库表 `record_template_slots`。
- 新增唯一约束 `section_code + unit + template_type`。
- 新增模板类型枚举：
  - `compliant`。
  - `non_compliant`。
  - `not_applicable`。
- 新增种子初始化服务：
  - 读取固定测评单元。
  - 为每个测评单元生成三条槽位。
  - 幂等 upsert，避免重复插入。
- 为 `compliant` 生成初始正文：优先从现有同测评单元系统模板抽取代表文本。
- 为 `non_compliant` 和 `not_applicable` 生成通用默认正文。
- 保留旧 `record_templates` 表，不做破坏性删除。

### 2.3 验收标准

- 初始化后每个固定测评单元都有 3 条模板。
- 重复初始化不会重复插入。
- 每条模板都有中文展示名称和稳定枚举值。
- 旧模板表和旧 JSON 种子仍然保留。

### 2.4 测试

- 新增三类模板种子测试。
- 新增唯一约束和幂等初始化测试。
- 新增章节覆盖测试，确认 A-1 至 A-8 固定单元均有三类模板。

### 2.5 完成记录（2026-06-22）

- 已新增 `record_template_slots` 表，字段覆盖章节、表类型、测评单元、模板类型、标题、当前正文、默认正文、标签、自定义状态和时间戳。
- 已新增唯一约束 `section_code + unit + template_type`，保证每个测评单元每类模板只有一个槽位。
- 已新增 `compliant`、`non_compliant`、`not_applicable` 三类稳定枚举和中文展示名称。
- 已新增三类模板种子初始化服务，先保留并同步旧 `record_templates` 系统模板，再为每个固定测评单元生成三类槽位。
- `compliant` 默认正文优先使用现有同测评单元代表模板；`non_compliant` 和 `not_applicable` 使用通用默认正文。
- 已补充 3 项测试，覆盖三类槽位覆盖、幂等初始化、旧模板保留和按章节/测评单元筛选。

## 3. T3-2：API 与兼容隔离

### 3.1 目标

提供新的三类模板 API，并停止在新前端流程中使用旧的系统/用户模板维护接口。

### 3.2 任务

- 新增 schema：
  - `RecordTemplateSlotRead`。
  - `RecordTemplateSlotUpdate`。
  - `RecordTemplateSlotImportPayload`。
  - `RecordTemplateSlotImportPreview`。
- 新增接口：
  - `GET /api/record-template-slots`。
  - `PUT /api/record-template-slots/{slot_id}`。
  - `POST /api/record-template-slots/{slot_id}/reset`。
- 不新增 DELETE 接口。
- 旧 `record-templates` 接口暂时保留，避免测试和历史功能一次性断裂。
- 在 README 或方案中标注旧接口为兼容保留，不再作为主流程。

### 3.3 验收标准

- 可以按章节和测评单元读取三类模板。
- 可以更新模板标题、正文和标签。
- 可以恢复默认模板。
- 请求非法模板类型时返回明确错误。
- 不存在可删除三类模板的 API。

### 3.4 测试

- 三类模板读取测试。
- 三类模板编辑测试。
- 恢复默认测试。
- 不可删除能力测试，可通过路由不存在或 405 行为确认。

## 4. T3-3：测评表录入区三类模板套用

### 4.1 目标

把测评表中的“套用模板”下拉从系统/用户混合列表改为固定三类模板。

### 4.2 任务

- 前端 API client 新增三类模板读取函数。
- `ProjectPage` 加载当前章节的三类模板槽位。
- `AssessmentTable` 按当前测评单元筛选三类模板。
- 模板下拉文案固定为：
  - 套用模板。
  - 符合/部分符合模板。
  - 不符合模板。
  - 不适用模板。
- 选择模板后写入当前测评行结果记录。
- 保留图片引用下拉和 `[插入图片引用]` 替换逻辑。
- 移除录入区内“系统模板 / 我的模板”分组依赖。

### 4.3 验收标准

- 每个测评行模板下拉最多只显示三类模板。
- 套用三类模板后结果记录正确填入。
- 套用后用户仍可手动修改结果记录。
- 图片引用插入位置逻辑不受影响。

### 4.4 测试

- 固定单元下三类模板筛选测试。
- 套用模板文本测试。
- 图片占位替换回归测试。
- 前端 TypeScript 构建通过。

## 5. T3-4：模板管理面板改造

### 5.1 目标

将模板管理面板从“模板列表管理”改为“每个测评单元三类模板编辑器”。

### 5.2 任务

- 移除或隐藏：
  - 新建模板。
  - 删除模板。
  - 复制模板。
  - 系统模板/我的模板徽标。
  - 来源筛选。
- 保留：
  - 章节选择。
  - 测评单元选择。
  - 关键词搜索可选，若保留则只用于定位测评单元或正文。
- 新增三类模板编辑区：
  - 符合/部分符合模板。
  - 不符合模板。
  - 不适用模板。
- 每类模板支持编辑标题、正文和标签。
- 每类模板提供保存和恢复默认按钮。
- 面板顶部展示“当前测评单元固定 3 类模板”。

### 5.3 验收标准

- 用户找不到删除模板入口。
- 用户找不到新增第四类模板入口。
- 用户可以编辑三类模板并保存。
- 刷新页面后编辑结果仍存在。
- 恢复默认后正文回到默认模板。

### 5.4 测试

- 组件渲染结构测试或 TypeScript 构建检查。
- API 更新后前端调用类型检查。
- 手动浏览器验收模板管理面板。

## 6. T3-5：导入导出与备份恢复调整

### 6.1 目标

将当前“用户模板导入导出”调整为“三类模板配置导入导出”。

### 6.2 任务

- 新增导出接口：导出所有三类模板槽位。
- 新增导入预览接口：
  - 校验 `section_code`。
  - 校验 `unit`。
  - 校验 `template_type`。
  - 只允许更新已有槽位。
- 新增确认导入接口：按预览结果更新槽位。
- 前端文案改为：
  - 导出模板配置。
  - 选择模板配置 JSON。
  - 预览导入。
  - 确认导入。
- 导入不能创建不存在的测评单元或第四类模板。

### 6.3 验收标准

- 导出文件包含每个测评单元三类模板。
- 合法导入可以更新模板内容。
- 非法 `template_type` 会在预览中报错。
- 不存在的测评单元不会被自动创建。
- 导入后模板数量仍固定为三类。

### 6.4 测试

- 导出结构测试。
- 导入预览测试。
- 非法类型和不存在单元测试。
- 导入不新增槽位测试。

## 9. 需要提前确认的问题

实施前建议确认以下产品细节：

- “符合/部分符合模板”是否确认为一个合并模板，而不是拆成两个模板。
- 三类模板是否需要按技术表和管理表使用不同默认正文。
- 是否需要 `{测评对象}`、`{测评单元}` 这类变量替换能力。
- 旧用户模板是否只保留备份，还是需要提供一次性迁移到三类模板的辅助界面。
- 是否保留“恢复默认”按钮；它不删除模板，但会覆盖用户修改。

如果没有额外调整，建议按本计划继续进入 T3-2。
