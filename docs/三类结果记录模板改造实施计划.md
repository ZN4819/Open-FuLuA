# 三类结果记录模板改造实施计划

## 1. 实施策略

本专项命名为 `T3`，含义是“三类结果记录模板”。实施原则：

- 先新增三类模板模型，不直接删除旧模板表和旧数据。
- 前端先切换到三类模板体验，再考虑清理旧接口。
- 每个阶段完成后更新相关文档、运行测试、提交并推送远程仓库。
- 涉及数据库、API、前端主流程的重要阶段使用独立分支。

推荐阶段：

1. T3-1：三类模板数据模型与种子初始化。
2. T3-2：三类模板 API 与旧接口兼容隔离。
3. T3-3：测评表录入区三类模板套用。
4. T3-4：模板管理面板改造为三类模板编辑器。
5. T3-5：导入导出与备份恢复调整。
6. T3-6：回归、文档和验收。

## 2. T3-1：数据模型与种子初始化

### 2.1 目标

建立 `record_template_slots` 运行时表，保证每个章节、每个固定测评单元都有三条固定模板。

### 2.2 任务

- 新增数据库表 `record_template_slots`。
- 新增唯一约束 `section_code + unit + template_type`。
- 新增模板类型枚举：
  - `compliant`。
  -
on_compliant`。
  -
ot_applicable`。
- 新增种子初始化服务：
  - 读取固定测评单元。
  - 为每个测评单元生成三条槽位。
  - 幂等 upsert，避免重复插入。
- 为 `compliant` 生成初始正文：优先从现有同测评单元系统模板抽取代表文本。
- 为
on_compliant` 和
ot_applicable` 生成通用默认正文。
- 保留旧 `record_templates` 表，不做破坏性删除。

### 2.3 验收标准

- 初始化后每个固定测评单元都有 3 条模板。
- 重复初始化不会重复插入。
- 每条模板都有中文展示名称和稳定枚举值。
- 旧模板表和旧 JSON 种子仍然保留。

### 2.4 测试

- 新增三类模板种子测试。
- 新增唯一约束和幂等初始化测试。
- 新增章节覆盖测试，确认 A-1 至 A-8 固定单元均有三类模板。

### 2.5 完成记录（2026-06-22）

- 已新增唯一约束 `section_code + unit + template_type`，保证每个测评单元每类模板只有一个槽位。
- 已新增 `compliant`、
on_compliant`、
ot_applicable` 三类稳定枚举和中文展示名称。
- 已新增三类模板种子初始化服务，先保留并同步旧 `record_templates` 系统模板，再为每个固定测评单元生成三类槽位。
- `compliant` 默认正文优先使用现有同测评单元代表模板；
on_compliant` 和
ot_applicable` 使用通用默认正文。

## 3. T3-2：API 与兼容隔离

### 3.1 目标

提供新的三类模板 API，并停止在新前端流程中使用旧的系统/用户模板维护接口。

### 3.2 任务

- 新增 schema：
  - `RecordTemplateSlotRead`。
  - `RecordTemplateSlotUpdate`。
  - `RecordTemplateSlotImportPayload`。
  - `RecordTemplateSlotImportPreview`。
- 新增接口：
  - `GET /api/record-template-slots`。
  - `PUT /api/record-template-slots/{slot_id}`。
  - `POST /api/record-template-slots/{slot_id}/reset`。
- 不新增 DELETE 接口。
- 旧 `record-templates` 接口暂时保留，避免测试和历史功能一次性断裂。
- 在 README 或方案中标注旧接口为兼容保留，不再作为主流程。

### 3.3 验收标准

- 可以按章节和测评单元读取三类模板。
- 可以更新模板标题、正文和标签。
- 可以恢复默认模板。
- 请求非法模板类型时返回明确错误。
- 不存在可删除三类模板的 API。

### 3.4 测试

- 三类模板读取测试。
- 三类模板编辑测试。
- 恢复默认测试。
- 不可删除能力测试，可通过路由不存在或 405 行为确认。

### 3.5 完成记录（2026-06-22）

- 已新增 `RecordTemplateSlotRead`、`RecordTemplateSlotUpdate`、`RecordTemplateSlotImportPayload` 和 `RecordTemplateSlotImportPreview` 等 schema。
- 已新增独立路由 `GET /api/record-template-slots`，支持按章节、测评单元和模板类型读取三类模板。
- 已新增 `PUT /api/record-template-slots/{slot_id}`，支持修改模板标题、正文和标签，保存后标记为用户已自定义。
- 已新增 `POST /api/record-template-slots/{slot_id}/reset`，支持恢复默认标题、正文和标签，并清除自定义标记。
- 未新增 DELETE 接口，已通过路由表测试确认三类模板槽位不存在删除入口。
- 旧 `/api/record-templates` 接口继续保留，仅作为兼容入口，后续新前端流程应切换到 `/api/record-template-slots`。
- 已补充 3 项测试，覆盖读取筛选、编辑、恢复默认、非法模板类型、缺失槽位和不可删除能力。

## 9. 需要提前确认的问题

实施前建议确认以下产品细节：

- “符合/部分符合模板”是否确认为一个合并模板，而不是拆成两个模板。
- 三类模板是否需要按技术表和管理表使用不同默认正文。
- 是否需要 `{测评对象}`、`{测评单元}` 这类变量替换能力。
- 旧用户模板是否只保留备份，还是需要提供一次性迁移到三类模板的辅助界面。
- 是否保留“恢复默认”按钮；它不删除模板，但会覆盖用户修改。

如果没有额外调整，本专项已完成；后续可在独立阶段处理旧模板迁移辅助界面、变量替换或旧接口清理。

### 10.2 结果记录分段模板增强（2026-07-04）

用户反馈原“结果记录正文”模板同时包含“测评验证记录”和“测评对象评分计算依据”，在实际录入时需要分别维护和套用。为降低误覆盖风险，已完成分段模板增强：

- `record_template_slots` 增加 `template_group` 字段，并将唯一键调整为 `section_code + unit + template_group + template_type`。
- 旧槽位迁移为 `verification_record` 分组，保留用户已修改内容；未自定义默认模板会随种子更新为验证记录段。
- 新增 `score_basis` 分组，每个测评单元固定生成完全符合、分数修正、不符合三类评分依据模板。
- `verification_record` 分组固定为符合/部分符合、不符合、不适用三类验证记录模板。
- `/api/record-template-slots` 支持按 `template_group` 筛选；导入导出 JSON 增加 `template_group`，旧 JSON 未提供该字段时按验证记录模板兼容导入。
- 测评表录入区拆分为“套用验证记录模板”和“套用评分依据模板”两个下拉，套用时只替换对应段落，并重新计算该行图片交叉引用。
- 模板管理面板按“测评验证记录模板”和“测评对象评分计算依据模板”两组展示，用户只能编辑、恢复默认和导入导出，不提供新增或删除模板能力。
