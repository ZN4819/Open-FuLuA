# 附录A编写工具

这是一个面向“附录A测评结果记录”的本地 Web 应用项目。工具目标是把 A-1 至 A-8 的测评结果、评分、符合情况、证据图片、题注和交叉引用结构化维护，并导出符合样本文档格式的 DOCX。

## 当前阶段

当前已完成阶段 9：测试、回归与本地打包说明，并补充了结果记录模板库功能。当前已确认 UI 布局优化方向，并完成 UI-1 至 UI-8 响应式与视觉验收，补充项目级全部保存入口，并完成结果记录模板知识库专项。知识库专项已完成 KB-1 至 KB-6：系统模板已进入 SQLite 运行时知识库，用户模板维护 API 已开放，录入区模板下拉已按“系统模板 / 我的模板”分组，已提供可视化模板管理面板，支持用户模板 JSON 备份、导入预览和恢复，并完成专项整体回归验收。三类结果记录模板改造专项已完成 T3-1 至 T3-6，并在 2026-07-04 完成分段模板增强：每个测评单元的模板槽位拆分为“测评验证记录模板”和“测评对象评分计算依据模板”两组，验证记录保留符合/部分符合、不符合、不适用三类，评分依据提供完全符合、分数修正、不符合三类；录入区支持分别套用两段模板且只替换对应段落。DOCX 导入新项目专项已完成 DI-1 至 DI-8：导入任务基座、DOCX 包读取/结构扫描、核心测评表解析、图片题注引用解析、导入预览 API、确认导入创建项目能力、前端导入向导以及端到端回归验收已经落地。

## 图片编号规则

- 图片内部仍使用全局唯一 `evidence_images.id` 作为稳定引用，不在界面和导出文档中直接展示。
- API 会返回每个项目内从 1 开始的 `project_image_no`，证据图片卡片显示为“项目图片 N”。
- 图号仍按章节和章节内排序显示为 `图A-x-y`；删除图片或调整排序后，界面中的结果记录引用显示会按最新图片列表刷新。
- 保存和导出仍使用内部 `[[FIG:全局图片ID]]` token 生成稳定 Word 交叉引用；已删除图片不会被自动改指向其他图片。
- 导入 DOCX 创建新项目时，临时图片 token 会转换为新项目真实全局 ID token，展示时再生成项目内编号和章节图号。

## 模板 Profile

模板规则位于：

```text
templates/appendix_a/template_profile.json
```

当前 profile 固化了：

- 横向 A4 页面设置。
- A-1 至 A-8 章节和表题。
- 技术测评 8 列表格 schema。
- 管理测评 5 列表格 schema。
- 总标题、章节标题、表题、表头和正文的字体、字号、段落间距规则。
- 表格外框与内框线宽规则：外框加粗黑色边框，内部网格细边框。
- 测评单元列正文规则：灰底、加粗、居中、垂直居中，同单元多行合并后只保留一份单元名称。
- 测评单元得分表头公式规则：技术表使用均值公式，管理表使用 `S_i,j`。
- 两类下拉控件选项。
- 图片宽度、DPI 和内联放置规则。
- 样本文档结构基准指标。

结果记录模板种子位于：

```text
templates/appendix_a/record_templates.json
```

当前模板种子根据 `附录A编写.docx` 只读抽取生成，包含 A-1 至 A-8 的测评单元、测评对象和结果记录正文。应用运行时会将系统模板种子同步到 SQLite 的 `record_templates` 表，再通过接口提供给前端；用户新增、编辑、软删除和复制模板也基于该知识库。

前端会从模板接口按章节提取去重后的固定测评单元，用于测评表分组展示；测评单元本身不再作为用户手动填写项。重新生成系统模板种子可运行：

```powershell
.\backend\.venv\Scripts\python.exe scripts\extract_record_templates.py
```

导出文件会生成到 `storage/exports/`，接口会直接返回可下载的 DOCX。
